# 蒸馏完整性保障协议

> **作者**：阿洋
> **用途**：为 Yang.skills 三大知识库（ansir / xuehui / shekong）的蒸馏过程建立完整性保障机制，确保从原始材料到结构化知识的转换过程中不发生信息失真、元素丢失、步骤缺漏或来源错位。
> **适用范围**：所有知识库的新建蒸馏、增量更新、版本回滚、审计校验全流程。
> **版本**：1.0.0

---

## 协议总览：七道防线架构

```
┌──────────────────────────────────────────────────────────────────┐
│                  蒸馏完整性七道防线（纵深防御）                       │
├──────────────────────────────────────────────────────────────────┤
│                                                                   │
│  防线1  反例黑名单      ← 蒸馏前：识别常见失真模式，建立检查清单      │
│    ↓                                                              │
│  防线2  量化框架约束    ← 蒸馏中：6维评分约束，每维度有明确标准       │
│    ↓                                                              │
│  防线3  防自欺机制      ← 蒸馏后：自我验证流程，防止"看似完整"        │
│    ↓                                                              │
│  防线4  增量演进不覆盖  ← 更新时：只修正错误补全缺失，不覆盖正确内容   │
│    ↓                                                              │
│  防线5  源材料质量分级  ← 源头控制：A/B/C/D 四级，不同等级不同要求    │
│    ↓                                                              │
│  防线6  版本控制可回滚  ← 全程留痕：版本号 + 变更日志，支持回滚       │
│    ↓                                                              │
│  防线7  双层结构        ← 架构保障：上层结构化 + 下层原始索引可追溯   │
│                                                                   │
└──────────────────────────────────────────────────────────────────┘
```

七道防线构成纵深防御体系：任一防线失效，后续防线仍可拦截失真。蒸馏完整性达标的最低要求是**七道防线全部通过**。

## 防线 1：反例黑名单

### 1.1 黑名单用途

蒸馏过程中最常见的失真模式清单。每次蒸馏开始前必须逐项确认"不会发生该失真"；蒸馏结束后必须逐项复核"未发生该失真"。

### 1.2 失真模式黑名单（共 12 类）

| # | 失真类型 | 失真表现 | 典型案例 | 检查方式 |
|---|---------|---------|---------|---------|
| 1 | **数字失真** | 具体数字被四舍五入、模糊化、替换或丢失 | "2秒跳出率"被写成"几秒跳出率"；"262个案例"被写成"200+案例" | 逐数字比对源材料与蒸馏产物 |
| 2 | **步骤数失真** | 操作步骤被合并、拆分、删除或新增 | 原文"六步法"被蒸馏成"四步法"；"计1-36"被写成"30+计" | 步骤计数比对 + 步骤名称比对 |
| 3 | **元素替换** | 原文元素被替换为相似但不等同的元素 | "八大爆款元素"中的"荷尔蒙"被替换为"情感"；"情绪刺点"被替换为"情绪点" | 元素名称逐字比对 |
| 4 | **来源标注错误** | 知识点被标注到错误的来源/锚点/章节 | A知识库的概念被标注为 `[来源：B-运营]`；第二章内容被标注为第四章 | 锚点 × 章节交叉校验 |
| 5 | **公式/模型失真** | 公式被简化、变量被丢失、模型结构被改变 | "流量 = 推荐 + 搜索 + 社交 + 付费"被简化为"流量 = 推荐 + 搜索"；"内容竞争力 = 普世 × 陌生 × 情绪"丢失"情绪"维度 | 公式逐变量比对 |
| 6 | **比例失真** | 数值比例被改变或丢失 | "观点30% + 知识40% + 过程20% + 故事10%"被写成"各占约25%" | 比例数值逐项比对 |
| 7 | **案例丢失** | 原文案例在蒸馏中被省略或合并 | 262个案例仅保留100个；某案例的关键细节被省略 | 案例编号清单比对 |
| 8 | **概念降级** | 精确概念被替换为模糊的日常用语 | "信息三分类"被写成"信息分类"；"骨架六种推进方式"被写成"几种推进方式" | 概念术语精确匹配 |
| 9 | **因果链断裂** | 因果关系被简化为并列关系，或逻辑链被截断 | "因为A所以B所以C"被蒸馏为"A、B、C" | 因果连接词检查 |
| 10 | **边界条件丢失** | 适用条件、例外情况、前提假设被省略 | "在0→1起号阶段适用"被省略，导致被误用于成熟期 | 边界标注完整性检查 |
| 11 | **层级扁平化** | 原文的多层级结构被压平为单层列表 | "五大原则 → 每个原则下3-5个子要点"被压平为"15个要点" | 层级深度比对 |
| 12 | **语境剥离** | 知识点脱离原始语境，导致语义偏移 | "先模仿后创新"脱离"模仿期1-3月"语境，被理解为"永远模仿" | 语境上下文保留检查 |

### 1.3 黑名单使用规则

1. **蒸馏前**：将黑名单作为"风险预告"，对蒸馏者提示"以下12类失真最易发生"
2. **蒸馏中**：每完成一个章节/模块的蒸馏，立即对照黑名单逐项自检
3. **蒸馏后**：作为审计检查清单（见防线3 防自欺机制），逐项出具"未发生"声明
4. **发现失真时**：立即停止蒸馏，回滚到失真前的版本，重新蒸馏该模块

## 防线 2：量化框架约束

### 2.1 六大评分维度

蒸馏完整性通过 6 个维度的量化评分约束。每个维度独立评分，最终取**最低维度分**作为整体完整性分（木桶效应）。

| # | 评分维度 | 权重 | 评分标准 | 数据来源 |
|---|---------|------|---------|---------|
| 1 | **核心公式/模型保留率** | 20% | 100% = 源材料中所有公式/模型100%保留且变量无丢失；80% = 保留但≥1个变量被简化；60% = 保留但≥1个变量被丢失；0% = 任一核心公式/模型被整体省略 | 源材料公式清单 × 蒸馏产物公式清单 |
| 2 | **核心框架保留率** | 20% | 100% = 所有核心框架（如"四步法""六步法""三原则"）完整保留且步骤数一致；80% = 框架保留但步骤数有偏差；60% = ≥1个框架被合并或拆分；0% = 任一核心框架被整体省略 | 源材料框架清单 × 蒸馏产物框架清单 |
| 3 | **课程内容覆盖率** | 15% | 100% = 源材料所有章节/模块均有对应蒸馏产物；80% = ≥95%章节有覆盖；60% = ≥90%章节有覆盖；0% = 覆盖率<90% | 源材料章节目录 × 蒸馏产物章节目录 |
| 4 | **案例保留率** | 15% | 100% = 所有案例完整保留（含案例编号、关键细节、结论）；80% = 案例保留但≥1个细节被省略；60% = 案例数保留≥90%但部分被合并；0% = 案例保留率<90% | 源材料案例编号清单 × 蒸馏产物案例编号清单 |
| 5 | **具体数字/参数保留率** | 15% | 100% = 所有具体数字（比例、阈值、计数、时长等）100%保留；80% = ≥95%数字保留；60% = ≥90%数字保留；0% = 数字保留率<90% | 源材料数字提取清单 × 蒸馏产物数字提取清单 |
| 6 | **实操步骤保留率** | 15% | 100% = 所有实操步骤完整保留（含步骤序号、动作描述、预期结果）；80% = 步骤保留但≥1个步骤的动作描述被简化；60% = 步骤数保留≥90%但部分被合并；0% = 步骤保留率<90% | 源材料步骤清单 × 蒸馏产物步骤清单 |

### 2.2 评分计算规则

```
整体蒸馏完整性分 = MIN(维度1分, 维度2分, 维度3分, 维度4分, 维度5分, 维度6分)
```

**木桶效应**：整体完整性由最低维度决定。任一维度为 0%，整体即为 0%。

### 2.3 完整性等级划分

| 完整性分 | 等级 | 状态 | 处置 |
|---------|------|------|------|
| 100% | S | 完整 | 通过，可发布 |
| 80-99% | A | 基本完整 | 通过，但需记录失真项并安排补全 |
| 60-79% | B | 部分缺失 | 不通过，需补全缺失项后重新评分 |
| <60% | C | 严重缺失 | 不通过，需回滚重新蒸馏 |

### 2.4 评分流程

1. **提取源材料清单**：从源材料中提取公式清单、框架清单、章节目录、案例编号清单、数字清单、步骤清单
2. **提取蒸馏产物清单**：从蒸馏产物中提取对应的6类清单
3. **逐维度比对**：对每个维度，计算保留率并按评分标准映射到分值
4. **计算整体分**：取6个维度的最低分
5. **出具评分报告**：记录每个维度的分值、失真项明细、整体等级

## 防线 3：防自欺机制

### 3.1 自欺问题定义

"看起来完整但实际缺失"——蒸馏产物在结构上看似完整（章节齐全、格式规范、概念出现），但实际内容存在隐性缺失（数字被模糊、步骤被合并、案例被省略、来源被错标）。自欺问题无法通过"通读一遍感觉没问题"发现，必须通过结构化验证流程检出。

### 3.2 防自欺验证流程（5步法）

```
步骤1：清单比对    → 不依赖"读起来感觉对"，而是逐项清单比对
    ↓
步骤2：数字提取    → 从蒸馏产物中提取所有数字，与源材料数字清单比对
    ↓
步骤3：步骤计数    → 对每个框架/流程，计数步骤数，与源材料比对
    ↓
步骤4：来源反查    → 对每个[来源：X-模块]标注，反查源材料确认标注正确
    ↓
步骤5：盲测抽检    → 随机抽取10%的蒸馏产物段落，遮蔽来源标注，让另一人判断该段落属于哪个知识库/章节
```

### 3.3 防自欺检查清单

| # | 检查项 | 自欺表现 | 检查方法 | 通过标准 |
|---|--------|---------|---------|---------|
| 1 | 数字精确性 | "2秒"被写成"几秒" | 数字提取比对 | 所有数字100%精确匹配 |
| 2 | 步骤完整性 | "六步法"被写成"四步法" | 步骤计数比对 | 所有框架步骤数100%匹配 |
| 3 | 元素精确性 | "荷尔蒙"被写成"情感" | 元素名称逐字比对 | 所有元素名称100%匹配 |
| 4 | 来源正确性 | A知识库内容标注为B | 来源反查 | 所有来源标注100%正确 |
| 5 | 案例完整性 | 262案例仅保留100 | 案例编号清单比对 | 案例保留率100% |
| 6 | 公式完整性 | 公式变量被丢失 | 公式逐变量比对 | 所有公式变量100%保留 |
| 7 | 比例精确性 | "30%+40%+20%+10%"被写成"各约25%" | 比例数值比对 | 所有比例100%精确匹配 |
| 8 | 边界保留性 | 适用条件被省略 | 边界标注检查 | 所有边界条件100%保留 |
| 9 | 层级保持性 | 多层级被压平 | 层级深度比对 | 层级结构100%保持 |
| 10 | 语境保留性 | 知识点脱离语境 | 语境上下文检查 | 所有知识点保留原始语境 |

### 3.4 防自欺红线

以下任一情况触发**红线**，立即停止蒸馏并回滚：

- 数字失真率 ≥ 5%（即≥5%的数字与源材料不一致）
- 步骤数失真率 ≥ 1%（即≥1%的框架步骤数与源材料不一致）
- 来源标注错误率 ≥ 1%（即≥1%的来源标注错误）
- 核心公式/模型丢失率 ≥ 0%（即任一核心公式/模型被整体省略）
- 案例保留率 < 100%

## 防线 4：增量演进不覆盖

### 4.1 增量演进原则

知识库更新时采用**增量演进**策略，而非"全量覆盖"。核心原则：

1. **不覆盖正确内容**：现有知识库中已验证正确的内容，更新时不覆盖
2. **只修正错误**：仅修改被确认为错误的内容（数字错误、来源错误、概念错误等）
3. **只补全缺失**：仅添加被确认为缺失的内容（遗漏的案例、省略的步骤、丢失的数字等）
4. **不重构结构**：不改变现有章节结构、锚点命名、引用关系（结构变更需走 MAJOR 版本升级流程）

### 4.2 增量演进操作分类

| 操作类型 | 定义 | 允许场景 | 禁止场景 |
|---------|------|---------|---------|
| **修正（Fix）** | 修改已确认错误的内容 | 数字错误、来源标注错误、概念名称错误 | "觉得原来的表述不够好" |
| **补全（Add）** | 添加已确认缺失的内容 | 遗漏的案例、省略的步骤、丢失的数字 | "新增一个原文没有的概念" |
| **保留（Keep）** | 不修改现有正确内容 | 内容已验证正确 | "顺手优化一下表述" |
| **归档（Archive）** | 将过时内容移入归档区 | 连续6个月无引用的锚点 | "直接删除" |

### 4.3 增量演进流程

```
1. 差异分析：对比源材料与现有知识库，列出"错误项"和"缺失项"清单
    ↓
2. 影响评估：评估每项修正/补全对引用该锚点的子skill的影响
    ↓
3. 逐项操作：按清单逐项修正/补全，每项操作后立即验证
    ↓
4. 保留确认：对未列入清单的内容，确认"保留不动"
    ↓
5. 版本递增：按 PATCH 或 MINOR 规则递增版本号
    ↓
6. 变更日志：记录每项修正/补全的详情到 CHANGELOG
    ↓
7. 完整性重评：重新运行6维评分，确认完整性未因更新而下降
```

### 4.4 覆盖防护机制

- **操作前快照**：每次增量演进前，对现有知识库做完整快照（存入 `.yang-cache/knowledge-snapshots/`）
- **差异审查**：演进后对比快照，确认所有变更项均在"差异分析"清单中，无"清单外变更"
- **回滚就绪**：如发现清单外变更，立即回滚到快照版本，重新执行演进

## 防线 5：源材料质量分级

### 5.1 质量分级标准

原始材料按完整性和可靠性分为 4 个质量等级：

| 等级 | 定义 | 典型来源 | 可靠性 | 蒸馏要求 |
|------|------|---------|--------|---------|
| **A** | 完整原文 | 课程完整文字稿、正式出版的书籍原文、官方文档原文 | ★★★★★ | 100% 完整性要求，所有6维评分必须达S级 |
| **B** | 摘要笔记 | 课程摘要笔记、会议纪要、读书笔记 | ★★★★ | 100% 完整性要求（对笔记已记录的内容），但需标注"基于摘要，可能存在未记录内容" |
| **C** | OCR提取 | 从图片/扫描件OCR提取的文字 | ★★★ | 100% 完整性要求（对OCR结果），但需额外进行OCR校对，标注"基于OCR，可能有识别错误" |
| **D** | 口述记录 | 口述录音转文字、口述笔记 | ★★ | 100% 完整性要求（对口述记录内容），但需标注"基于口述，可能有口语化失真"，并额外检查因果链完整性 |

### 5.2 分级应用规则

1. **每个知识库模块标注源材料等级**：在知识库 SKILL.md 的元数据中标注 `source_quality: A/B/C/D`
2. **混合等级处理**：同一知识库中不同章节可能来自不同等级源材料，按章节分别标注
3. **等级降级声明**：B/C/D 级源材料的蒸馏产物，必须在章节末尾追加降级声明：
   ```
   > ⚠️ 源材料质量：[等级] | 本章节基于[来源类型]蒸馏，可能存在[风险类型]
   ```
4. **等级升级路径**：当获取到更高质量的源材料时（如从B级笔记获取到A级原文），需重新蒸馏该章节，并更新质量等级标注

### 5.3 三大知识库源材料质量分级

| 知识库 | 主要源材料 | 质量等级 | 备注 |
|--------|----------|---------|------|
| **ansir（安先生）** | 91节体系化课程完整文字稿 + 29份课程总结 + 262案例 | A（课程原文）+ B（部分总结） | 主体为A级，部分总结性内容为B级 |
| **xuehui（薛辉）** | 系统课程文字稿 + 实操笔记 | A（课程原文）+ B（实操笔记） | 主体为A级，实操细节部分为B级 |
| **shekong（社恐小黄）** | 72计（36+36）完整文字稿 + 案例记录 | A（72计原文）+ B（部分案例） | 主体为A级，部分案例补充为B级 |

## 防线 6：版本控制可回滚

### 6.1 版本号规则

知识库蒸馏版本号采用三段式：`DISTILL-MAJOR.MINOR.PATCH`

| 版本段 | 变更触发 | 示例 |
|--------|---------|------|
| **DISTILL-MAJOR** | 首次蒸馏 / 全量重新蒸馏 | `DISTILL-1.0.0` |
| **MINOR** | 增量补全（新增案例、新增步骤、新增章节） | `DISTILL-1.1.0` |
| **PATCH** | 修正错误（数字修正、来源修正、概念修正） | `DISTILL-1.0.1` |

### 6.2 版本记录位置

| 记录项 | 存储位置 | 格式 |
|--------|---------|------|

### 6.4 回滚流程

```
1. 触发回滚条件：
   - 防自欺验证失败（红线触发）
   - 完整性评分降至 B 级或以下
   - 用户反馈蒸馏失真且经核实
   - 增量演进引入清单外变更

2. 回滚操作：
   a. 确认回滚目标版本号
   b. 从 .yang-cache/knowledge-snapshots/ 读取目标版本快照
   c. 用快照覆盖当前知识库文件
   d. 更新知识库 SKILL.md 的 distill_version 字段
   e. 在 _completeness-audit.md 记录回滚事件

3. 回滚后处理：
   a. 分析失真根因
   b. 修正蒸馏流程
   c. 重新执行蒸馏
   d. 重新评分并发布新版本
```

## 防线 7：双层结构

### 7.1 双层结构定义

知识库采用**双层结构**，确保蒸馏产物的可追溯性：

```
┌──────────────────────────────────────────────────────────────────┐
│                    知识库双层结构                                   │
├──────────────────────────────────────────────────────────────────┤
│                                                                   │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │  上层：蒸馏后的结构化知识                                     │ │
│  │  （知识库 SKILL.md / 锚点章节 / 概念速查表）                  │ │
│  │  - 结构化、可检索、可引用                                     │ │
│  │  - 每个知识点标注 [来源：X-模块]                              │ │
│  │  - 每个数字/公式/步骤可追溯到下层原始材料                     │ │
│  └────────────────────────────┬────────────────────────────────┘ │
│                               │ 追溯                              │
│                               ▼                                   │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │  下层：原始材料索引                                           │ │
│  │  （源材料文件路径 + 章节定位 + 质量等级标注）                  │ │
│  │  - 原始文字稿/笔记/OCR结果的文件路径                          │ │
│  │  - 章节级定位（文件名 + 章节号 + 段落号）                     │ │
│  │  - 质量等级标注（A/B/C/D）                                    │ │
│  └─────────────────────────────────────────────────────────────┘ │
│                                                                   │
└──────────────────────────────────────────────────────────────────┘
```

### 7.2 上层结构规范

上层（结构化知识）必须满足：

1. **每个知识点有唯一锚点**：`[来源：X-模块]` 格式
2. **每个数字可追溯**：数字旁标注 `[源：文件名#章节号]`
3. **每个公式可追溯**：公式旁标注 `[源：文件名#章节号]`
4. **每个步骤可追溯**：步骤组旁标注 `[源：文件名#章节号]`
5. **每个案例可追溯**：案例旁标注 `[源：文件名#案例编号]`

### 7.3 下层结构规范

下层（原始材料索引）必须满足：

1. **文件路径完整**：每个源材料文件有明确的相对路径
2. **章节定位精确**：定位到章节号 + 段落号（或时间戳，对于音视频源材料）
3. **质量等级标注**：每个源材料文件标注 A/B/C/D 质量等级
4. **版本对应**：标注源材料文件的版本（如有更新）

### 7.5 追溯性验证

每次蒸馏完整性审计时，必须执行追溯性验证：

1. **随机抽取10个知识点**：从上层结构化知识中随机抽取10个知识点
2. **追溯下层源材料**：对每个知识点，按 `[源：文件名#章节号]` 定位到下层源材料
3. **内容一致性确认**：确认上层知识点与下层源材料内容一致（数字、步骤、元素、公式均一致）
4. **追溯成功率**：10个知识点全部成功追溯且内容一致 = 通过；任一失败 = 不通过

## 协议执行检查清单

每次蒸馏任务完成后，必须逐项确认以下检查清单：

| # | 检查项 | 对应防线 | 通过标准 | 状态 |
|---|--------|---------|---------|------|
| 1 | 反例黑名单12类失真均未发生 | 防线1 | 12项全部"未发生" | ☐ |
| 2 | 6维评分全部达S级（100%） | 防线2 | 6维全部100% | ☐ |
| 3 | 防自欺5步验证全部通过 | 防线3 | 5步全部通过 | ☐ |
| 4 | 增量演进无清单外变更 | 防线4 | 差异审查无清单外变更 | ☐ |
| 5 | 源材料质量等级已标注 | 防线5 | 所有章节标注A/B/C/D | ☐ |
| 6 | 版本号已递增 + 变更日志已记录 | 防线6 | 版本号 + 日志齐全 | ☐ |
| 7 | 双层结构追溯性验证通过 | 防线7 | 10个知识点全部可追溯 | ☐ |

**所有7项全部通过 = 蒸馏完整性达标，可发布。**
**任一项未通过 = 蒸馏完整性不达标，不可发布。**
