**身份**：视频号/抖音短视频创作教学领域标杆导师

|------|---------|---------|

| **02 方向篇** | 账号定位四步法、人设构建四要素、竞争优势分析框架 | `A-选题` |
| **03 储备篇** | 内容竞争力三维模型（普世 × 陌生 × 情绪）、五大基础技能体系 | `A-选题` |
| **04 进阶篇** | 流量结构模型、信息三分类（情绪/价值/身份）、爆款选题三大路径、262案例选题六步法 | `A-流量` |
| **05 结构精细化** | 钩子八种类型与不平衡理论、骨架六种推进方式、情绪刺点理论 | `A-结构` `A-钩子` `A-情绪` |
| **06 大师思维篇 + 导演级附录** | 情景化思维、故事性构建（5种实践/对抗内核）、形象种子；**导演级视听语言（视点/景别/构图/焦段/色彩/光线）、时间的语法、信息特性（视听/切片/持续）、销售成交付费链路、本地生活引流** | `A-结构` `A-影像` |

#### 核心概念速查

| 概念 | 简述 | 锚点 |
|------|------|------|
| **流量结构模型** | 流量 = 推荐 + 搜索 + 社交 + 付费；推荐驱动力 = 完播率 x 互动率 x 转化率 x 复播率 | `A-流量` |
| **三大数据维度** | 2秒跳出率（留住人）、停留时长（留住注意力）、互动反馈（点赞/评论/转发/收藏） | `A-数据` |
| **信息三分类** | 情绪信息（传播最快衰减最快）、价值信息（传播稳定长期有效）、身份信息（传播精准黏性最强） | `A-流量` |
| **钩子本质** | 建立不平衡状态，制造认知缺口/情绪悬念/好奇心缺口，迫使观众看完获得闭合感 | `A-钩子` |
| **骨架本质** | 兴趣点的排列和推进方式，让观众在每个"下一秒"都有继续观看的理由 | `A-结构` |
| **情绪刺点** | 点赞曲线图 + 五大互动词典 + 从单向宣讲到共创对话的核心思维转变 | `A-情绪` |
| **爆款选题法** | 普世需求 x 陌生化演绎 = 大众关心的议题 x 没人讲过的角度 | `A-选题` |
| **内容竞争力** | 普世 × 陌生 × 情绪（大众都关心 × 没人这么讲过 × 有情绪浓度） | `A-选题` |
| **8种钩子类型** | 悬念/冲突/共鸣/反常识/故事/情绪/利益/身份 八种核心类型 + 注意力钩子与价值钩子理论 | `A-钩子` |

## 八、知识库引用规范（统一引用格式标准）

### 8.1 统一引用格式

所有子 skill 在引用知识库内容时，必须使用以下统一格式：

```
[来源：X-模块]
```

其中：
- **X** = 知识库简称（A / B / C）
- **模块** = 锚点中的主题简称（如 选题、流量、钩子 等）

#### 引用场景与格式示例

| 引用场景 | 格式示例 | 说明 |
|---------|---------|------|
| 子skill SKILL.md 知识库依赖段 | `[来源：A-钩子]` | 标注该 skill 依赖的核心知识锚点 |
| 输出中的知识依据行 | `📚 知识依据：[来源：A-钩子] | [来源：C-开篇]` | 多个来源用 `\|` 分隔 |
| 内联引用（正文中提及） | `根据[来源：A-流量]的信息三分类理论……` | 行内引用，紧跟概念首次出现处 |
| 对标分析/竞品报告 | `方法论参考：[来源：B-爆款] + [来源：A-结构]` | 组合引用，用 `+` 连接 |

#### 引用纪律

1. **每条引用必须可溯源**：`[来源：X-模块]` 中的模块必须在本索引第四章锚点表中存在对应条目
2. **禁止模糊引用**：不允许 `[来源：知识库A]` 这种不含模块的引用——必须精确到锚点
3. **禁止自创锚点**：新增锚点须先在本索引第四章登记，再引用
4. **引用与内容对齐**：如果 skill 输出中使用了某知识库的概念，必须在知识依据行中标注对应来源

### 8.2 引用完整性校验

yang-doctor 诊断时，应校验以下规则：

| 校验项 | 规则 | 不通过时的动作 |
|-------|------|-------------|
| 锚点存在性 | `[来源：X-模块]` 中的 X-模块 在锚点表中存在 | 报告"未知锚点引用" |
| 引用覆盖度 | skill 声称依赖的锚点与实际输出中引用的锚点一致 | 报告"声明依赖但未引用"或"引用但未声明" |
| 格式合规性 | 引用格式严格匹配 `[来源：X-模块]` | 报告"引用格式不规范" |

### 10.2 版本记录位置

| 记录项 | 存储位置 | 格式 |
|-------|---------|------|

### 10.3 版本同步校验

| 校验时机 | 校验内容 | 不一致时的处理 |
|---------|---------|--------------|
| yang-init 初始化 | 写入当前知识库索引版本到 state | — |

### 10.4 向后兼容规则

- **PATCH 升级**：完全兼容，无任何动作需要
- **MINOR 升级**：新增锚点，旧 skill 不受影响；新 skill 可引用新锚点

## 十三、知识库扩展指南

### 13.1 新增知识库模块流程

当需要新增知识库（如知识库D）时，按以下步骤操作：

1. **创建知识库目录**：`knowledge/<name>/SKILL.md`（作为索引入口）+ 按主题拆分的子文件
2. **编写知识库 SKILL.md**：
   - frontmatter 格式与现有知识库一致（含 `version: 7.0.0`、`author: 阿洋`）
   - 作为精简索引，列出所有子文件
   - 定义锚点命名规则：`D-<主题简称>`
3. **编写主题子文件**：
   - 每个子文件自包含、可独立阅读
   - frontmatter 标注作者"阿洋"和版本号
4. **在本索引中注册**：
   - 第一章总览表新增行
   - 第二章文件索引新增该知识库的子文件列表
   - 第三章新增知识库核心内容摘要
   - 第四章新增锚点表（含"对应子文件"列）
   - 第九章新增降级替代方案
5. **更新总协议 SKILL.md**：
   - "三大知识库路由"段新增行（改为"四大知识库路由"）
   - 路由表中涉及新知识库的skill新增引用说明
6. **更新子skill**：
   - 在相关子skill的 `## 知识库依赖` 段新增引用
   - 输出中追加 `📚 知识依据：D-XX`
7. **版本号递增**：MAJOR +1（新增知识库属于 MAJOR 变更）
8. **验证**：运行 yang-doctor 确认所有新引用完整

### 13.2 新增锚点流程

在现有知识库中新增锚点时：

1. **确定锚点名称**：格式 `<知识库简称>-<主题简称>`，确保不与现有锚点冲突
2. **编写锚点内容**：在知识库对应的主题子文件中新增对应章节（v7.0.0 后锚点指向具体子文件，而非 SKILL.md）
3. **在本索引第四章锚点表中注册**：新增一行，填写锚点、对应子文件、章节、核心内容、引用子skill
4. **更新引用子skill**：在对应子skill的 `## 知识库依赖` 段新增引用
5. **更新降级方案**：为新增锚点设计降级替代方案，添加到第九章
6. **版本号递增**：MINOR +1（新增锚点属于 MINOR 变更）

### 13.3 知识库质量标准

新增知识库或锚点时，必须满足以下质量标准：

| 标准项 | 要求 | 验证方式 |
|--------|------|----------|
| **锚点唯一性** | 每个锚点名称全局唯一 | 在本索引第四章搜索确认无重复 |
| **内容完整性** | 每个锚点至少包含：概念定义、应用场景、关键指标 | 人工审核 |
| **引用可溯源** | 每个锚点可追溯到知识库源文件的特定章节 | 读取对应主题子文件确认（v7.0.0 后锚点指向具体子文件） |
| **降级可用性** | 每个锚点至少有一个降级替代方案 | 检查第九章降级表 |
| **命名规范** | 锚点名称符合 `<X>-<2-4汉字>` 格式 | 正则校验 |
| **子skill覆盖** | 新增锚点至少被1个子skill引用 | 检查子skill知识库依赖段 |

### 13.4 扩展注意事项

1. **避免锚点膨胀**：每个知识库锚点数建议 ≤10 个，超过时考虑合并相似锚点
2. **保持知识库独立性**：各知识库之间可以有交叉引用，但不应存在强依赖（降级方案需覆盖交叉引用场景）
3. **锚点粒度适中**：锚点太粗（如 `A-全部`）无法精确定位，太细（如 `A-钩子-悬念型-第2种`）增加维护负担
4. **版本兼容性**：新增锚点（MINOR 变更）不影响旧 skill 运行；删除锚点（MAJOR 变更）需走迁移流程
5. **测试覆盖**：新增锚点后，运行 yang-doctor 确认所有引用链路完整，运行降级方案测试确认替代路径可用

## 十五、知识库与 Skills 的正向联动机制

> **v7.0.0 新增章节**：本章节描述三大知识库拆分后，与 6 个核心子 skill 形成的正向联动拓扑。完整的联动拓扑详见 [`_linkage-map.md`](./_linkage-map.md)。

### 15.1 联动机制总览

知识库拆分为多个主题文件后，每个子 skill 通过"锚点 → 子文件"的精确引用路径，与知识库形成正向联动。联动机制包含两个方向：

- **知识库 → skill**：skill 在执行时按需加载知识库的具体主题文件，增强 skill 的专业判断能力
- **skill → 知识库**：skill 在输出中标注引用的锚点和子文件，便于追溯和校验

### 15.2 六条联动通道速查

| # | 联动通道 | skill | 引用的知识库子文件 | 联动时机 |
|---|---------|-------|------------------|---------|
| 1 | 钩子工厂联动 | yang-hook-factory | `ansir/hooks.md` `shekong/copywriting-hooks.md` `shekong/visual-hooks.md` | 生成钩子变体时 |

| 3 | 润色增强联动 | yang-polish | `ansir/content-methods.md` `shekong/copywriting-hooks.md` `xuehui/copywriting-scripts.md` | 活人感润色时 |

### 15.3 联动方式

每条联动通道的"联动方式"指 skill 如何重组知识库内容来增强自身功能：

1. **钩子工厂联动**：将 `ansir/hooks.md` 的8种钩子类型理论与 `shekong/copywriting-hooks.md` 的28种文案钩子模板、`shekong/visual-hooks.md` 的8种画面钩子组合，形成"理论 + 文案模板 + 画面模板"的三层钩子生成体系
