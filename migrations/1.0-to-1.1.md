# Migration: v1.0 → v1.1

## WHAT

删除 3 个硬模式切换字段，替换为从 `calibration_samples` 自动派生：

| 删除字段 | 替换逻辑 |
|---|---|
| `mode`（"cold-start" / "calibration"） | 用 `calibration_samples` 整数判断状态 |
| `prediction_complexity`（"cold-start-simple" / "complete"） | 所有预测统一用完整 7 组件结构，confidence 等级派生自 `calibration_samples` |
| `bucket_scheme`（"ratio" / "absolute" / "absolute_with_ratio" / "percentile"） | bucket 边界由单一算法自动派生 |

## WHY

硬模式切换是设计者的猜测，不是用户体验该有的样子。统一流程 + 渐进信心标注更符合"频道是不断进化的连续光谱"的现实。

## HOW

```python
state["schema_version"] = "v1.1"
# 删除废弃字段
for key in ("mode", "prediction_complexity", "bucket_scheme"):
    state.pop(key, None)
```

## Manual fallback

如果自动化迁移失败，手动编辑 `.yang-state.json`：
1. 改 `schema_version` 为 `"1.1"`
2. 删除 `mode`、`prediction_complexity`、`bucket_scheme` 三个字段
3. 确认 `calibration_samples` 字段存在且为整数
