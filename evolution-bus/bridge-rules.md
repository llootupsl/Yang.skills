## §0 翻译原则声明

### 0.1 翻译的边界定义

进化反馈总线的信号翻译层遵守以下核心原则：

```
┌─────────────────────────────────────────────────────────────────┐
│                    Bridge Rules · 翻译边界                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   闭环校准系统 输出                    Bridge 翻译层                      │
│   ┌──────────┐              ┌──────────────┐                    │
│   │ Bucket   │──→ 映射 ──→ │ Agent引擎 路径判定  │                    │
│   │ Rubric   │──→ 映射 ──→ │ Agent引擎 内容策略  │                    │
│   │ Bump     │──→ 映射 ──→ │ Agent引擎 路径升级  │                    │
│   │ Obs      │──→ 映射 ──→ │ Agent引擎 假设验证  │                    │
│   └──────────┘              └──────────────┘                    │
│                                                                 │
│   翻译层不做的事：                                                 │
│   · 不修改 闭环校准系统 原始信号（只翻译格式和语义）                         │
│   · 不替 Agent引擎 做决策（只提供翻译后的操作建议）                       │
│   · 不引入新判断逻辑（所有映射关系在此文档中预定义）                  │
│   · 不绕过总线直接通信（严格遵守 bus-protocol.md §3）               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 0.2 翻译的两种模式

| 模式 | 激活条件 | 翻译行为 | 输出目标 |
|------|---------|---------|---------|
| **完整产线模式** | 产线运行中（环节 1/3/6） | 全部翻译规则生效，闭环校准系统 信号注入对应 Agent引擎 | C-001~C-007 对应注入点 |
| **Solo 模式** | Agent引擎 未激活（见 bus-protocol.md §5） | 仅执行格式翻译为人类可读输出，不注入 Agent引擎 Agent | 当前对话界面 |

### 0.3 信号翻译的时序语义

闭环校准系统 信号注入 Agent引擎 是**异步非阻塞**的。翻译层在接收到 闭环校准系统 响应后执行以下时序：

```
T0: 产线环节 N 触发 → 创作意图信号经总线发送至 闭环校准系统
T0+Δt: 产线继续运行（不被阻塞）
T1: 闭环校准系统 完成预测/评估 → 输出信号返回总线
T1: 总线 Bridge Rules 执行翻译
T1+ε: 翻译后信号注入对应 Agent引擎 的输入缓冲区
T_next: Agent引擎 下一轮产线循环消费注入信号
```

## §1 闭环校准系统 Bucket → Agent引擎 决策路径映射

### 1.1 映射总表

闭环校准系统 5 级 Bucket（S / A / B / C / D）翻译为 Agent引擎 4 条决策路径（高度 / 中度 / 默认 / 保守），并附带对应的 C-Agent 响应动作。

| 闭环校准系统 Bucket | 播放量区间 | Agent引擎 决策路径 | 路径语义 | C-001 路径判定策略 | C-003 内容策略 | C-004 投流策略 | C-006 攻击方向 |
|-----------|-----------|------------|---------|-------------------|--------------|-------------|-------------|
| **S-Tier** | >150w | **高度路径（激进投入）** | 预测极强，建议全资源投入 | 批准全资源投入路径；要求 C-006 执行最高强度攻击；设定投入上限（如投流预算封顶为常规 3×） | 标记"重点运营"内容线；优先排期；策划后续承接内容（矩阵联动、系列化）；将该选题纳入"内容旗舰"池 | 生成激进投流策略（DOU+ + 千川 + 搜索竞价全开）；设定流失线（如 ROI ≤ 1.2 时自动停止追加）；标注"基于 S-Tier 盲预测，非实际数据" | 攻击"S-Tier 预测可能为过度乐观"；要求出示对标锚点中的 S-Tier 样本数及偏差历史；强制设定止损协议 |
| **A-Tier** | 100-150w | **中度偏上路径（重点运营）** | 预测良好，建议加大运营力度 | 批准重点运营路径；C-001 可根据内容线节奏决定是否升级为高度路径；若置信度为 speculative 则维持中度路径不升级 | 标记"重点内容线"；适度排期推进；对钩子进行一轮变体测试（钩子变体工厂输出 2-3 个备选） | 正常流量运营策略 + 适度 DOU+ 测试投放；设置止损线（ROI ≤ 1.0 减半，≤ 0.8 停止）；标注"基于 A-Tier 预测" | 攻击"A-Tier 与 B-Tier 的区分是否充分"；检查 rubric 中 ER/HP 是否被高估；审计对标锚点是否存在 A-Tier 高估历史 |
| **B-Tier** | 30-100w | **默认路径（标准流程）** | 预测中等，正常发布运营 | 批准标准流程路径；不追加额外资源；维持预定发布节奏 | 按内容线标准排期；不做特殊调整；正常执行脚本→拍摄→发布 | 标准发布策略；不投流或仅做最低限度测试投放（如 DOU+ 100 元测试）；标注"基于 B-Tier 预测，标准流程" | 攻击"B-Tier 是否掩盖了隐性风险"；检查 ER-Curve S3 冲突段评分；审计是否存在"高估受众共情"的假设 |
| **C-Tier** | 5-30w | **保守路径（优化后重新评估）** | 预测偏低，需识别弱点后优化 | 暂缓发布排期；要求 C-003 根据 C-006 攻击结果输出修改方案；可要求 闭环校准系统 在修改后重新预测 | C-006 强制攻击脚本弱点 → 输出修改建议 → C-003 执行修改（钩子重写 / 叙事结构优化 / 论证逻辑加固）→ 修改后重新提交 Stage2 Hook 盲预测 | 不建议投流；标注"C-Tier 预测，发布前需优化" | 主力攻击方向：逐维度低分项强制审计；攻击"哪些假设导致 C-Tier 预测"；要求每个低分维度出具一份修改方案 |
| **D-Tier** | <5w | **否决路径（推翻重做）** | 预测差，建议全面推翻或放弃 | 建议 C-001 宣布选题冻结；要求 C-003 + C-006 联合作出"推翻 or 重做"判定；若推翻→选题归档废弃；若重做→至少 3 个核心维度重写 | 脚本打回重做；全面修改钩子、叙事结构、论证逻辑；重做后重新提交 Stage1 Hook（选题重评估）+ Stage2 Hook（盲预测）；标记为"D-Tier 重做流程" | 严禁投流；标注"D-Tier 预测，不可发布" | 全面攻防：逐维度揭示失败风险；要求出示所有对标锚点中 D-Tier 样本的共性特征；输出完整的"失败模式清单" |

### 1.2 路径映射的上下文修正

Bucket → 路径翻译不是机械的一对一映射。总线在执行翻译时 MUST 应用以下修正规则：

#### 1.2.1 置信度修正

| 置信度等级 | 修正行为 |
|-----------|---------|
| **speculative** | 所有路径**降一档**执行。S→A 路径、A→B 路径、B→C 路径、C→D 路径（即 C-Tier speculative → 直接建议否决/重做）。仅在置信度升级到 medium 后恢复原路径。 |
| **medium** | 正常映射，不修正。 |
| **medium-high+** | 正常映射。S-Tier 可直接进入高度路径，无需 C-001 额外裁决。 |

#### 1.2.2 对标数据占比修正

当对标数据占比 > 50%（即 `benchmark_ratio` > 0.5），路径**再降一档**（与置信度降档叠加生效）：

- S-Tier + benchmark_ratio > 50% + medium 置信度 → 中度路径（降两档：对标降一档 + 不再叠加置信度降档，因为已在 §1.2.1 中处理）
- 叠加示例：A-Tier + speculative 置信度 + benchmark_ratio > 50% → 否决路径（先行降一档至 B→默认，对标再降一档至 C→保守；实际上 speculative 对标占比高应触发叠加保守策略）

> 注：当 confidence_level = speculative 且 benchmark_ratio > 50% 时，不对 Bucket 做双重路径降档（已是最保守策略），而是在路径判定中追加标注"⚠️ 推测性高且数据以对标为主，路径参考价值有限"。

#### 1.2.3 Bucket 分布一致性修正

当 闭环校准系统 yang-predict 给出完整 bucket 概率分布时（见 bus-protocol.md §4.2.5），应检查分布集中度：

| 分布特征 | 修正行为 |
|---------|---------|
| headline bucket 概率 ≥ 60% | 正常映射，不修正 |
| headline bucket 概率 40-60% | 路径决策追加"分布分散"标注，C-001 执行路径时需考虑次级 Bucket 的可能性 |
| headline bucket 概率 < 40%（高度分散） | 路径降一档；C-001 追加标注"闭环校准系统 预测高度不确定，建议保守执行" |

### 1.3 Bucket 不是最终判决：离散警告规则

> **BR-WARN-01**：闭环校准系统 Bucket 是**盲预测信号**，不是**传播结果的担保**。

总线在每次翻译 Bucket → 路径时，MUST 在输出中附加以下离散警告：

```
┌─────────────────────────────────────────────────────────────┐
│  ⚠️ Bucket 离散警告（不可省略）                                │
│                                                             │
│  1. 当前预测基于 calibration_samples = {N}，置信度 = {level} │
│  2. 历史 Bucket 命中率（如同 Bucket 预测的准确率）：          │
│     - 无历史数据时标注"N/A——无可对照历史"                     │
│     - 有历史数据时标注实际命中率百分比                         │
│  3. Bucket 是"预测"而非"判决"：                               │
│     - C-006 MUST 对所有 Bucket 执行独立攻击                   │
│     - C-004 投流策略 MUST 设定止损线                          │
│     - C-001 路径判定 MUST 考虑次级 Bucket 的降级风险           │
│  4. 如果以下条件中任一条成立，路径建议的置信度进一步降低：       │
│     ☐ 对标数据占比 > 50%                                     │
│     ☐ calibration_samples < 5                               │
│     ☐ Bucket 概率分布高度分散（headline < 40%）               │
│     ☐ 最近 3 次预测中有 ≥2 次偏差超过 1 个 Bucket 等级         │
│  5. 离散警告生效范围：当前产线循环。下次产线循环可基于新数据更新  │
└─────────────────────────────────────────────────────────────┘
```

## §2 闭环校准系统 Rubrics 维度 → Agent引擎 含义翻译

### 2.1 维度翻译总表

闭环校准系统 7 个 Tier 1 维度（HP / ER / QL / NA / AB / SR / SAT）翻译为 Agent引擎 可消费的操作语义。

| 闭环校准系统 维度 | 缩写 | 评分区间 | Agent引擎 等价概念 | 翻译逻辑（高分 ≥8） | 翻译逻辑（低分 ≤4） | C-006 攻击角度（低分） | C-003 策略调整（高分） |
|---------|------|---------|------------|-------------------|-------------------|---------------------|---------------------|
| **Hook Power** | HP | 1-10 | 前 3 秒关键词密度 + 钩子锐度（对应钩子变体工厂评估） | HP ≥ 8 → C-003 标记"钩子强，保持当前钩子策略"；C-004 标记"高钩子锐度 → 前 3 秒留存预期高，可适度提高投流出价" | HP ≤ 4 → C-003 标记"钩子失败风险"；强制触发钩子变体工厂重新生成钩子；C-006 执行钩子脆弱性攻击 | 攻击"钩子是信息型还是情绪型？信息型钩子在推荐流中天然弱势"；攻击"钩子是否依赖特定受众预知？如果是，泛流量下的钩子失效概率估算"；要求钩子变体工厂输出 ≥3 个替代钩子 | 将当前钩子策略固化为"钩子模板"纳入内容策略库；对同内容线的后续选题复用钩子结构 |
| **Emotional Resonance** | ER | 1-10 | 情感共鸣度（含 ER-Curve 六段分析：S1 引入 / S2 铺垫 / S3 冲突 / S4 高潮 / S5 余韵 / S6 节奏） | ER ≥ 8 → C-003 标记"情感设计优秀，保持情绪节奏"；C-005 标记"高情感共鸣 → 粉丝转化预期高" | ER ≤ 4 → C-003 标记"情感连接薄弱"；C-006 执行情感断层攻击；特别关注 ER-Curve S3 冲突段——若 S3 ≤ 4，攻击"核心冲突不够尖锐" | 攻击"情感共鸣是靠内容还是靠选题本身？选题自带的情感共鸣在同类竞争中是否被稀释？"；攻击 ER-Curve 各段的具体缺陷——S1≤4 攻击"开场无法建立情感锚"；S3≤4 攻击"核心冲突不够尖锐，无法推动情绪爬升"；S5≤4 攻击"结尾无力，观众看完无情绪残留" | 将 ER 设计模式固化为"情绪设计模板"；在同内容线后续选题中对标已成功的情绪结构；偏高 S1/S4 时可考虑缩短铺垫段直接进高潮 |
| **Quality Logic** | QL | 1-10 | 论点质量与逻辑严密性（对应内容论证体系的完整性） | QL ≥ 8 → C-003 标记"论证体系严密，可作为同类内容的论证模板" | QL ≤ 5 → C-003 标记"论点存在逻辑漏洞"；C-006 执行逻辑审计——识别逻辑跳跃、因果倒置、以偏概全等缺陷 | 攻击"论证链条的薄弱环节在哪？"；攻击"是否存在'因为爆款所以正确'的循环论证？"；攻击"是否用情绪替代了逻辑？情绪可以让人点赞，但逻辑才能让人信服"；要求每条核心论点出示"反方最强反驳" | 将论证框架固化为"逻辑模板"；对同内容线的后续选题复用论证结构；可适度提高信息密度（QL 高意味着受众信息耐受度较强） |
| **Narrative Arc** | NA | 1-10 | 叙事结构与节奏（故事弧线的完整性和张力设计） | NA ≥ 8 → C-003 标记"叙事结构优秀，节奏控制精准" | NA ≤ 5 → C-003 要求重新编排叙事结构；检查是否符合理想结构比（1:3:4:5:2:1） | 攻击"叙事是否有'为了结构而结构'的僵硬感？"；攻击"叙事节奏在推荐流中是加速器还是减速器？减速叙事在短视频场景中天然弱势"；攻击"叙事依赖的是信息增量还是情绪增量？纯信息叙事缺乏情绪锚点" | 将叙事结构固化为"叙事模板"；可在同类选题中复用叙事节奏；根据 NA 高分段的节奏分布优化后续内容的段落配比 |
| **Audience Bonding** | AB | 1-10 | 受众连接度/身份认同（受众是否能"看到自己"） | AB ≥ 8 → C-002 标记"受众共情指数高，身份认同信号强"；C-004 标记"高受众连接 → 互动率预期高 → 推荐流加权预期高" | AB ≤ 4 → C-003 标记"受众连接薄弱，可能存在'自说自话'风险"；C-006 执行受众脱节攻击 | 攻击"目标受众画像是谁？内容中是否出现了明确的目标受众信号？"；攻击"受众能否在 3 秒内判断'这是给我看的内容'？"；攻击"假设的受众共情是否基于真实受众反馈，还是创作者自我投射？" | 将受众连接策略固化为"受众锚定模板"；在选题阶段优先选择 AB 高分的内容方向；C-002 可在心理画像中更新"受众共情锚点" |
| **Shareability Rating** | SR | 1-10 | 转发驱动力（内容是否具备"我必须分享给某人"的内驱力） | SR ≥ 8 → C-004 标记"高传播潜力，设定传播 KPI（如分享率 ≥ 3%）"；C-003 标记"可在发布时设计分享诱因（如评论区引导 @好友）" | SR ≤ 4 → C-003 标记"分享驱动力不足"；C-006 执行传播瓶颈攻击 | 攻击"观众转发动机是什么？'认同'转发和'震惊'转发的传播路径完全不同"；攻击"分享行为是否被内容结构引导？没有 Call-to-Share 暗示的内容天然少分享"；攻击"是否存在'值得收藏但不值得转发'的陷阱？" | 将高 SR 的内容要素固化为"传播因子模板"；在后续内容中主动设计分享触发点（如信息落差、情感反差、身份标签） |
| **Satisfaction** | SAT | 1-10 | 观看满足感/完播预期（观众看完后的"值了"感） | SAT ≥ 8 → C-003 标记"完播闭环优秀，预期完播率较高"；C-004 标记"高满足感 → 推荐流加权预期高" | SAT ≤ 4 → C-003 标记"可能引发中途跳出"；C-006 执行完播中断攻击 | 攻击"观众在哪个时间点最可能跳出？是否对应 ER-Curve 的某一段？"；攻击"结尾是否构成了完整闭环？开放式结尾在短视频场景中可能导致'未完成感'"；攻击"满足感是靠内容质量还是靠信息量？信息型满足感不可持续" | 将 SAT 高分内容的结构特征固化为"闭环模板"；检查同类高 SAT 内容的结尾设计模式并复用 |

### 2.2 ER-Curve 六段专项翻译

ER-Curve 是 ER 的子维度分析，对 Agent引擎内容策略有独立翻译价值。

| 段位 | 闭环校准系统 评分 | 翻译到 Agent引擎操作语义 | C-003 响应 | C-006 攻击 |
|------|---------|---------------------|-----------|-----------|
| **S1 引入 Hook** | ≤4 | 前 3 秒无法建立情绪锚 | 钩子变体工厂强制重新生成 | "开场情绪锚是什么？观众在 3 秒内感受到了什么情绪？" |
| **S2 铺垫 Build** | ≤4 | 铺垫段冗长或信息密度低 | 压缩铺垫段；或将铺垫信息融入冲突段 | "铺垫信息能否后置？能否用一句话替代一个段落？" |
| **S3 冲突/转折** | ≤4 | 核心冲突不够尖锐 | 重写冲突段；加入对比案例或反常识事实 | ★ 高危攻击："没有冲突就没有传播——S3≤4 的内容本质上是'信息告知'而非'故事讲述'" |
| **S4 高潮 Peak** | ≤4 | 情绪爆发点设计不佳 | 重写高潮段；检查铺垫→高潮的情绪爬升梯度是否足够 | "高潮前是否有足够张力积累？没有张力积累的高潮 = 干喊" |
| **S5 余韵/署名** | ≤4 | 结尾无情绪残留 | 重写结尾；检查是否构成叙事闭环 | "观众看完后记住了什么？如果没有 10 秒后仍能回忆的情绪锚，结尾失败" |
| **S6 整体节奏** | ≤4 | 张弛比例失衡 | 按理想结构比（1:3:4:5:2:1）重新编排节奏 | "哪一个段占据了不该占的篇幅？节奏失衡通常是一个段'吃掉了'另一个段" |

### 2.3 维度翻译的复合规则

当多个维度同时出现极端值时，翻译应触发复合信号：

| 复合条件 | 翻译为 Agent引擎 复合信号 | 目标 Agent |
|---------|-------------------|-----------|
| HP ≥ 8 **且** SR ≥ 8 | "钩子强 + 传播潜力高" → 标记为"爆款候选"，C-004 可考虑超出标准预算的投流方案 | C-004 |
| HP ≤ 4 **且** ER ≤ 4 | "钩子弱 + 情感共鸣弱" → 标记为"高危脚本"，无论其他维度多高都必须大幅修改 | C-003 + C-006 |
| AB ≥ 8 **且** SR ≥ 8 | "受众连接强 + 传播驱动力强" → 标记为"社交裂变候选"，C-004 应在发布时设计分享裂变机制 | C-004 |
| QL ≤ 5 **且** NA ≤ 5 | "逻辑弱 + 叙事弱" → 底层创作能力警告，C-001 应评估是否需回退到基础创作能力训练 | C-001 |
| SAT ≤ 4 **且** AB ≥ 8 | "高受众连接但低满足感" → 警告"受众来了但留不住"，C-003 需重点优化内容闭环 | C-003 |

## §3 闭环校准系统 Bump 信号 → Agent引擎 路径升级/降级触发条件

### 3.1 Bump 信号类型定义

闭环校准系统 yang-bump 通过 Stage3 Hook 输出 4 种 Bump 信号。总线将其翻译为 Agent引擎 路径变更触发条件。

#### 3.1.1 UPGRADE_BUMP（路径升级触发）

```
信号定义：
  名称：UPGRADE_BUMP
  含义：闭环校准系统 检测到实际播放量持续超越预测基准，建议提升 Agent引擎 决策路径等级
  来源：闭环校准系统 yang-bump + yang-retro 偏差分析
  注入目标：C-001（路径裁决）

生成条件（需全部满足）：
  ☑ 连续 ≥3 个样本的实际播放量 > 预测 Bucket 中枢值 × 1.25（即超过预测中枢 25% 以上）
  ☑ calibration_samples ≥ 5
  ☑ 偏差方向一致（全部为低估，即 actual > predicted）
  ☑ C-006 乖离率审计结果为 PASS 或 PASS_WITH_WARNINGS

置信度要求：
  ┌────────────────────┬──────────────────────────────────────┐
  │ confidence_level   │ UPGRADE_BUMP 行为                      │
  ├────────────────────┼──────────────────────────────────────┤
  │ speculative        │ 不触发升级。Bump 信号仅记录在 C-007    │
  │                    │ 假设跟踪表中，标注"未满足置信度要求"。   │
  │                    │ 路径维持原级别，不执行任何变更。         │
  ├────────────────────┼──────────────────────────────────────┤
  │ medium             │ 正常触发升级评估。C-001 收到后执行标准  │
  │                    │ 升级裁决流程。                          │
  ├────────────────────┼──────────────────────────────────────┤
  │ medium-high+       │ 正常触发升级评估。C-001 可适度加速裁决  │
  │                    │ 流程（如跳过部分非关键审计项）。         │
  └────────────────────┴──────────────────────────────────────┘

升级幅度限制：
  · 默认 → 中度：允许（跨越 1 级）
  · 中度 → 高度：允许（跨越 1 级）
  · 默认 → 高度：禁止一跳升级。必须经过至少 3 个样本的中度路径验证后，
    再次触发 UPGRADE_BUMP 方可升至高度路径。
  · 高度 → 进化：仅在 calibration_samples ≥ 20 且 Bucket 命中率 ≥ 70% 时允许。
```

#### 3.1.2 DOWNGRADE_BUMP（路径降级触发）

```
信号定义：
  名称：DOWNGRADE_BUMP
  含义：闭环校准系统 检测到实际播放量持续低于预测基准，建议降低 Agent引擎 决策路径等级
  来源：闭环校准系统 yang-bump + yang-retro 偏差分析
  注入目标：C-001（路径裁决）

生成条件（满足任一即触发，≥3 个连续样本时强制触发）：
  ☑ 连续 ≥3 个样本的实际播放量 < 预测 Bucket 中枢值 × 0.75（即低于预测中枢 25% 以上）
  或
  ☑ 最近 5 个样本中 Bucket 预测命中率 < 40%（即 5 个中 ≥3 个预测错误）

降级幅度：
  · 高度 → 中度：1 个信号触发
  · 中度 → 默认：1 个信号触发
  · 默认 → 保守：1 个信号触发
  · 保守 → 冻结：连续 ≥2 次 DOWNGRADE_BUMP 触发
  · 低置信度（speculative）下：降级无条件，不设冻结保护期

降级后的恢复路径：
  · 降级后需经过 ≥5 个样本的稳定期（无新 DOWNGRADE_BUMP）方可重新评估升级
  · 恢复升级时需额外满足：最近 5 个样本的 Bucket 命中率 ≥ 60%
```

#### 3.1.3 PATTERN_DISCOVERY（模式发现触发）

```
信号定义：
  名称：PATTERN_DISCOVERY
  含义：闭环校准系统 在复盘校准中发现了新的创作模式（Pattern），该模式可能影响路径决策
  来源：闭环校准系统 yang-retro → Observation → Pattern 候选
  注入目标：C-001（评估是否纳入路径决策因子）+ C-003（更新内容策略）

生成条件：
  ☑ 闭环校准系统 发现新 Pattern，状态为 proposed 或 active
  ☑ Pattern 的支持样本 ≥3（或 1 个强信号样本——如 ≥6× 流量比）
  ☑ Pattern 与当前 rubric 维度有明显关联

C-001 裁决流程：
  ┌─────────────────────────────────────────────────────────┐
  │ C-001 PATTERN_DISCOVERY 裁决流程                         │
  ├─────────────────────────────────────────────────────────┤
  │                                                         │
  │  步骤 1：接收 PATTERN_DISCOVERY 信号                      │
  │     ↓                                                   │
  │  步骤 2：审查 Pattern 内容和支持证据                       │
  │     ↓                                                   │
  │  步骤 3：判定 Pattern 是否影响路径决策                     │
  │     ├── 不影响（如细化的叙事技巧）→ 仅通知 C-003 更新策略库 │
  │     ├── 可能影响（如发现某类钩子在特定时段效果显著）         │
  │     │   → 标记为"观察模式"，在后续 3 个样本中验证           │
  │     └── 明确影响（如持续高估/低估某类内容）                 │
  │         → 纳入路径决策因子，更新路径判定权重                │
  │     ↓                                                   │
  │  步骤 4：通知 C-003 更新内容策略库                         │
  │     ↓                                                   │
  │  步骤 5：C-007 记录 PATTERN_DISCOVERY 裁决日志             │
  │                                                         │
  └─────────────────────────────────────────────────────────┘
```

#### 3.1.4 CALIBRATION_MATURE（校准成熟触发）

```
信号定义：
  名称：CALIBRATION_MATURE
  含义：闭环校准系统 检测到 calibration_samples 达到成熟阈值，系统应从"置信度标注模式"
        切换为"数据驱动模式"
  来源：闭环校准系统 yang-status（状态监控）
  注入目标：C-001（系统模式切换裁决）+ C-007（更新假设跟踪策略）

触发条件：
  ☑ calibration_samples ≥ 10
  ☑ 对标数据占比 < 50%（确保自有数据主导）
  ☑ 最近 5 个样本的 Bucket 预测命中率 ≥ 50%

模式切换行为：
  ┌──────────────────────┬──────────────────────────────────┐
  │ 切换前（置信度标注模式） │ 切换后（数据驱动模式）              │
  ├──────────────────────┼──────────────────────────────────┤
  │ 所有信号标注 speculative │ 所有信号标注 medium-high+       │
  │ 对标数据贡献策略建议     │ 对标数据仅作 sanity check       │
  │ 路径判定偏保守           │ 路径判定基于实际校准数据          │
  │ Bump 触发偏谨慎          │ Bump 触发基于数据驱动            │
  │ C-006 攻击偏"怀疑论"     │ C-006 攻击偏"数据偏差审计"       │
  └──────────────────────┴──────────────────────────────────┘

C-001 裁决项：
  · 确认进入数据驱动模式
  · 审核对标数据的"淡出"节奏（避免对标数据一次性断崖式退出）
  · 设定数据驱动模式下的 Bucket 命中率 KPI（建议 ≥ 60%）
  · 通知全 Agent 系统模式变更
```

### 3.2 Bump 信号与 C-006 乖离率审计的联动

无论何种 Bump 信号，C-006 MUST 在消费前执行乖离率审计：

```
┌─────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────┤
│                                                             │
│  乖离率计算公式：                                            │
│    divergence_rate = |actual_plays - predicted_median|       │
│                      / predicted_median                      │
│                                                             │
│  审计判定：                                                  │
│  ┌──────────────┬────────────────────────────────────────┐  │
│  │ 乖离率        │ 审计结果                                │  │
│  ├──────────────┼────────────────────────────────────────┤  │
│  │ divergence   │ PASS —— 偏差在预测区间内，Bump 信号可信   │  │
│  │ < 0.25       │                                        │  │
│  ├──────────────┼────────────────────────────────────────┤  │
│  │ 0.25 ≤       │ PASS_WITH_WARNINGS —— Bump 信号可信但    │  │
│  │ divergence   │ 偏差较大，C-001 裁决时需将此警告纳入考量   │  │
│  │ < 0.50       │                                        │  │
│  ├──────────────┼────────────────────────────────────────┤  │

│  ├──────────────┼────────────────────────────────────────┤  │
│  │ divergence   │ FAIL —— Bump 信号不可信。C-001 MUST 宣布  │  │
│  │ ≥ 1.00       │ Bump 冻结 3 个样本周期。触发 rubric 审计  │  │
│  │ (偏差 ≥100%)  │ 流程（检查是否存在系统性评分偏差）       │  │
│  └──────────────┴────────────────────────────────────────┘  │
│                                                             │
│  审计解锁条件：                                              │
│    · 冻结期满 + 新增 ≥2 个校准样本 + 乖离率降至 < 0.50       │
│    · 或 C-001 行使最终裁决权强制解锁（需附书面理由）          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## §4 闭环校准系统 Observation → Agent引擎 假设验证状态 双向同步规则

### 4.1 假设生命周期同步概述

闭环校准系统 和 Agent引擎 在假设管理上遵循"闭环校准系统 创建和验证、Agent引擎 消费和追踪"的单向同步模型。

```
┌─────────────────────────────────────────────────────────────────┐
│              假设生命周期 · 跨体系同步模型                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
```

### 4.2 假设状态定义与同步规则

| 闭环校准系统 状态 | Agent引擎 等价状态 | 状态含义 | 触发条件 | 闭环校准系统→Agent引擎 同步动作 | Agent引擎→闭环校准系统 数据注入 |
|---------|------------|---------|---------|-----------------|-----------------|
| **ACTIVE** | 假设活跃 | 预测已生成，等待发布后验证 | Stage2 Hook 输出盲预测信号后，C-007 创建 H2xx 记录 | C-007 在假设跟踪表中创建 H2{NN} 条目，记录预测 Bucket、中枢值、置信度、Hook 保护段锁定时间 | 无（此时 Agent引擎 侧仅有预测，无实际数据） |
| **MATCHED** | 假设已验证（预测成立） | 实际播放数据与预测一致 | T+3 复盘后，闭环校准系统 yang-retro 判定偏差在 ±25% 以内 | C-007 更新 H2xx 状态为 MATCHED；记录实际播放数据；将偏差幅度写入假设验证日志；更新 Bucket 命中率统计 | Agent引擎 通过 Stage3 Hook 将 T+3 实际播放数据、留存曲线、互动数据注入 闭环校准系统 |
| **MISMATCHED** | 假设被推翻（预测偏差） | 实际播放数据与预测不一致 | T+3 复盘后，闭环校准系统 yang-retro 判定偏差超出 ±25% | C-007 更新 H2xx 状态为 MISMATCHED；记录偏差方向和幅度；C-006 据此攻击 Agent引擎 假设缺陷；标记为"需归因分析" | Agent引擎 将 T+3 数据 + C-003 自评 + C-004 投流操作记录一并注入 闭环校准系统，供归因分析 |
| **CLOSED** | 假设已关闭 | 假设生命周期结束（无论验证成立或推翻） | 假设已被吸收为 Pattern / 产生新观察 / 或超过关注窗口 | C-007 归档 H2xx 条目；总结该假设对系统进化的贡献；更新 Pattern 库和观察库 | 无（CLOSED 后不再注入新数据到该假设） |

### 4.6 同步方向的严格约束

> **BR-SYNC-01**：闭环校准系统 → Agent引擎 单向同步。Agent引擎 不修改 闭环校准系统假设状态。

| 操作 | 闭环校准系统 侧 | Agent引擎 侧 | 允许？ |
|------|--------|--------|-------|
| 创建假设 | yang-predict 生成预测 | C-007 创建 H2xx 记录 | ✓ 允许（闭环校准系统 → Agent引擎） |
| 更新假设状态 | yang-retro 更新状态 | C-007 同步更新 H2xx 状态 | ✓ 允许（闭环校准系统 → Agent引擎） |
| 关闭假设 | yang-retro 或手动关闭 | C-007 归档 H2xx | ✓ 允许（闭环校准系统 → Agent引擎） |
| Agent引擎 修改 闭环校准系统 假设状态 | — | C-007 直接修改 闭环校准系统 假设 | ✗ 禁止（Agent引擎 → 闭环校准系统 写操作） |
| Agent引擎 创建 闭环校准系统 假设 | — | C-007 在 闭环校准系统 侧创建假设 | ✗ 禁止（违背信息边界） |

### 5.2 对标数据占比降档规则

## §6 信号翻译的异常处理

### 6.1 闭环校准系统 预测与 Agent引擎 直觉严重冲突

> **BR-ERR-01**：当 闭环校准系统 预测 Bucket 与 Agent C-003（内容总监）或用户的直觉判断严重冲突时。

```
冲突判定标准：
  · 闭环校准系统 预测 Bucket S-Tier 但 C-003/用户直觉认为 ≤ B-Tier
  · 闭环校准系统 预测 Bucket D-Tier 但 C-003/用户直觉认为 ≥ B-Tier
  · 即偏差 ≥ 3 个 Bucket 等级时触发冲突处理协议

处理流程：
  ┌─────────────────────────────────────────────────────────────┐
  │  Step 1：总线上报冲突事件（BUS_CONFLICT_DETECTED）            │
  │     ↓                                                       │
  │  Step 2：C-001 收到冲突通知后主持"冲突调解"会议                │
  │     ├── 要求 闭环校准系统（经总线）解释其 Bucket 判定依据               │
  │     ├── 要求 C-003 明确陈述直觉分歧的理由                      │
  │     └── 要求 C-006 独立评估双方的论证强度                      │
  │     ↓                                                       │
  │  Step 3：C-001 裁决                                          │
  │     ├── 置信度 = speculative → 优先采纳 Agent引擎 直觉               │
  │     │   理由：低置信度下 闭环校准系统 预测的可靠性不足以覆盖直觉判断    │
  │     ├── 置信度 = medium      → C-001 自行裁决                 │
  │     │   参考：闭环校准系统 历史命中率 vs C-003 历史直觉准确率           │
  │     ├── 置信度 ≥ medium-high+ → 优先采纳 闭环校准系统 预测              │
  │     │   理由：高置信度下数据驱动预测的可靠性通常高于直觉       │
  │     └── 但 C-001 MUST 在任何情况下保留最终裁决权              │
  │     ↓                                                       │
  │  Step 4：裁决结果记录                                          │
  │     ├── 写入冲突日志（冲突内容 + 各方论证 + 裁决结果 + 理由）   │
  │     ├── 标记为"待 T+3 验证"——实际播放数据将事后判定谁对谁错   │
  │     └── C-007 纳入元认知审计（检查是否存在系统性直觉偏差）     │
  │     ↓                                                       │
  │  Step 5：T+3 复盘裁决验证                                     │
  │     ├── 闭环校准系统 正确 → Agent引擎 直觉需要校准 → C-003 调整直觉基线      │
  │     ├── Agent引擎 直觉正确 → 闭环校准系统 预测需要校准 → 触发偏差分析         │
  │     └── 写入冲突验证日志                                      │
  └─────────────────────────────────────────────────────────────┘
```

### 6.2 闭环校准系统 未校准（calibration_samples = 0）的处理

> **BR-ERR-02**：当 calibration_samples = 0 时，闭环校准系统 没有任何校准数据，所有预测完全基于对标数据推断。

```
处理规则：
  1. 闭环校准系统 仍然输出预测信号（不拒绝工作——见 bus-protocol.md §5 冷启动策略）
  2. 总线翻译时 MUST 执行以下降级：

     ┌──────────────────────────────────────────────────────┐
     │  ⚠️ 零校准警告（calibration_samples = 0）             │
     │                                                      │
     │  所有 闭环校准系统 信号翻译后追加：                             │
     │  ┌────────────────────────────────────────────────┐  │
     │  │ "⚠️ 零样本警告：闭环校准系统 校准样本数为 0。            │  │
     │  │  当前预测完全基于对标数据推断和对标模型迁移，    │  │
     │  │  尚未对您的账号进行任何个性化校准。              │  │
     │  │                                                │  │
     │  │  建议操作：                                      │  │
     │  │  · 将当前预测视为"方向性参考"而非"量化预测"      │  │
     │  │  · 尽快发布 ≥3 条视频以建立自有校准池            │  │
     │  │  · 在自有校准池建立前，对标数据是您的主要参考    │  │
     │  │  · 所有投流决策应以最低保守预算执行"            │  │
     │  └────────────────────────────────────────────────┘  │
     └──────────────────────────────────────────────────────┘

  3. Bucket → 路径映射强制降两档：
     · S → 默认路径（不是高度路径！）
     · A/B → 保守路径
     · C/D → 否决路径
     理由：零校准下 Bucket 预测的可靠性极低，不宜引导任何激进投入

  4. Bump 信号完全锁定（不评估、不裁决、不输出）
     理由：无校准数据的情况下 Bump 完全无意义

  5. C-001 在启动时 SHOULD 主动提示用户：
     "系统检测到校准样本为 0。建议您先发布 3-5 条视频，让系统了解
      您的账号特征。在此期间，所有预测仅供参考。"
```

### 6.3 对标数据折价率随时间衰减规则

> **BR-ERR-03**：对标数据的参考价值随时间衰减。对标分析完成的时间越久远，对当前预测的贡献越小。

```
对标数据时间折价系数表：

┌────────────────────────────┬──────────┬──────────────────────────┐
│ 对标分析完成时间             │ 折价系数  │ 对 calibration_samples  │
│                             │           │ 计算的影响               │
├────────────────────────────┼──────────┼──────────────────────────┤
│ ≤ 30 天（新鲜）              │ ×1.0     │ 全额贡献（0.5 或 0.3）    │
│ 31 - 60 天（衰减中）         │ ×0.7     │ 贡献降为 0.35 或 0.21     │
│ 61 - 90 天（严重衰减）       │ ×0.4     │ 贡献降为 0.20 或 0.12     │
│ > 90 天（失效）              │ ×0.0     │ 不贡献                   │
└────────────────────────────┴──────────┴──────────────────────────┘

折价后的 calibration_samples 计算公式：

calibration_samples = 
    SUM(自己发布的视频) × 1.0
  + SUM(对标爆款深度分析) × 0.5 × 时间折价系数    // 上限 3 条计入
  + SUM(对标低播放深度分析) × 0.3 × 时间折价系数   // 上限 2 条计入
  + SUM(用户确认为"代表作"的历史视频) × 1.0

计算示例：
  · 自发布视频：3 条 × 1.0 = 3.0
  · 对标爆款分析 A（25 天前）：1 条 × 0.5 × 1.0 = 0.50
  · 对标爆款分析 B（45 天前）：1 条 × 0.5 × 0.7 = 0.35
  · 对标爆款分析 C（70 天前）：1 条 × 0.5 × 0.4 = 0.20
  · 对标低播放分析（50 天前）：1 条 × 0.3 × 0.7 = 0.21
  · calibration_samples = floor(3.0 + 0.50 + 0.35 + 0.20 + 0.21) = 4
  · 原始（不折价）计算：floor(3.0 + 0.5×3 + 0.3×1) = floor(4.8) = 4
  · 折价后 vs 不折价：4 vs 4（本例差异不显著，因自发布占主导）

总线翻译时的附加标注：
  当对标数据中有 >60 天的条目且仍在使用时：
  "⚠️ 注意：对标数据中有 {N} 条超过 60 天，已按折价系数 {0.4} 计算。
   建议更新对标分析以获取更准确的市场信号。"

  当对标数据全部 >90 天时：
  "⚠️ 警告：所有对标数据均已超过 90 天，对标贡献已降为 0。
   当前 calibration 仅基于自有发布数据。建议尽快执行新的对标分析
   （触发 /yang-learn-from 或 Stage1 Hook 自动对标发现）。"
```

### 6.4 信号翻译异常的错误码体系

| 错误码 | 含义 | 触发条件 | 总线行为 |
|--------|------|---------|---------|
| `BR_ERR_BUCKET_PARSE` | 闭环校准系统 Bucket 信号解析失败 | Bucket 字段不在 [S, A, B, C, D] 枚举内 | 拒绝翻译，返回原始 闭环校准系统 输出。C-001 基于 Agent引擎 自身判断做路径判定 |
| `BR_ERR_DIMENSION_OUT_OF_RANGE` | Rubric 维度评分超出 1-10 范围 | 任一维度分数 <1 或 >10 | 钳位到合法范围 [1, 10] 后继续翻译。追加修正标注 |
| `BR_ERR_BUMP_SIGNAL_INCOMPLETE` | Bump 信号缺少必需字段 | bump_evaluation.triggered = true 但缺少 validation_steps | 标记为"不完整 Bump 信号"，C-001 不予裁决，退回 闭环校准系统 要求补全 |
| `BR_ERR_HYPOTHESIS_ID_CONFLICT` | 假设 ID 冲突 | 新 H2xx ID 与已有假设 ID 重复 | 自动分配下一个可用 ID。记录 ID 冲突日志 |
| `BR_ERR_BENCHMARK_TIMEOUT` | 对标数据时间折价导致贡献归零 | 所有对标数据 >90 天 | 发出警告信号通知 C-002（赛道策略师）触发新的对标分析 |
| `BR_WARN_CONFIDENCE_BOUNDARY_CROSS` | 置信度临近边界 | calibration_samples 距离下一等级边界 ≤1 | 标注"置信度即将升级/降级"，提醒 C-001 关注未来 1-2 个样本后的置信度变化 |
| `BR_WARN_BUCKET_DISTRIBUTION_FLAT` | Bucket 概率分布过于平坦 | headline bucket 概率 < 40% 或 最大两个 bucket 概率之和 < 65% | 在路径翻译中追加"⚠️ 预测高度不确定，概率分布过于分散" |

### 6.5 翻译降级模式

当总线翻译层自身出现异常时（如规则文件损坏、翻译表不完整），进入翻译降级模式：

```
翻译降级模式行为：
  1. 总线标记 BUS_DEGRADED（见 bus-protocol.md §8.2）
  2. 闭环校准系统 输出原封不动地传递给 Agent引擎（未经翻译）
     → Agent引擎 各自按原生理解消费 闭环校准系统 信号
     → 标注"原始信号（翻译层降级，未经语义翻译）"
  3. C-001 收到降级通知后转入保守策略
  4. 翻译层恢复后，总线自动退出降级模式
```

## §7 信号翻译精度标准

### 7.1 精度等级定义

信号翻译的精度分为三个等级，用于衡量翻译后信号与原始信号之间的语义保真度：

| 精度等级 | 标识 | 定义 | 判定标准 | 示例 |
|---------|------|------|---------|------|
| **精确翻译** | `EXACT` | 翻译后信号的语义与原始信号完全一致，无信息损失 | ① 所有必填字段完整映射<br>② 枚举值一对一映射（如 Bucket S → 高度路径）<br>③ 数值型字段无精度损失（评分、中枢值等）<br>④ 置信度标注完整传播 | Bucket = S → 高度路径（激进投入），HP=8 → "钩子强，保持策略" |
| **近似翻译** | `APPROXIMATE` | 翻译后信号保留了原始信号的核心语义，但存在可接受的精度损失 | ① 非关键字段被省略或合并<br>② 数值型字段经过四舍五入或区间映射<br>③ 复合信号被简化为单一信号<br>④ 置信度标注降级传播 | ER-Curve 六段评分被合并为"情绪曲线总分=7.2"；Bucket 概率分布被简化为 headline bucket |
| **丢失翻译** | `LOST` | 原始信号的关键语义在翻译过程中丢失，翻译结果不可靠 | ① 必填字段缺失<br>② 枚举值无法映射（如未知 Bucket 等级）<br>③ 数值型字段超出合法范围<br>④ 置信度标注丢失 | 闭环校准系统 输出包含新维度（如 FUTURE维度），但 Agent引擎 侧无对应概念，该维度信息被丢弃 |

### 7.2 精度等级的判定规则

总线在每次翻译完成后 MUST 自检翻译精度：

```
翻译精度自检流程：

  Step 1：字段完整性检查
    ├── 所有必填字段均已映射 → 继续
    └── 存在必填字段缺失 → 精度 = LOST，记录 BUS_WARN_TRANSLATION_LOST

  Step 2：枚举值映射检查
    ├── 所有枚举值均有预定义映射 → 继续
    └── 存在未定义的枚举值 → 精度降级：
        ├── 非关键字段 → 精度 = APPROXIMATE，记录 BUS_WARN_TRANSLATION_APPROXIMATE
        └── 关键字段（Bucket / confidence_level / Bump 信号类型）→ 精度 = LOST

  Step 3：数值精度检查
    ├── 数值型字段在合法范围内且无精度损失 → 继续
    ├── 数值经过四舍五入/区间映射 → 精度 = APPROXIMATE
    └── 数值超出合法范围 → 精度 = LOST

  Step 4：置信度传播检查
    ├── 置信度标注完整传播 → 精度 = EXACT
    ├── 置信度标注降级传播（如 medium-high+ → medium）→ 精度 = APPROXIMATE
    └── 置信度标注丢失 → 精度 = LOST

  最终精度 = min(Step1, Step2, Step3, Step4)
    EXACT < APPROXIMATE < LOST（LOST 最低）
```

### 7.3 精度等级的传播与标注

| 精度等级 | 翻译输出中的标注 | Agent引擎 消费行为 |
|---------|-----------------|-------------------|
| EXACT | 无附加标注（默认即精确） | 正常消费，无特殊处理 |
| APPROXIMATE | `⚠️ 翻译精度：近似（{丢失/简化字段列表}）` | 正常消费，但对标注的简化字段持谨慎态度；C-006 在攻击时需考虑精度损失的影响 |
| LOST | `🚫 翻译精度：丢失（{丢失字段列表}）` | C-001 MUST 评估丢失字段的影响；如丢失字段为关键字段（Bucket / confidence / Bump 类型），C-001 可选择拒绝消费该信号 |

## §8 翻译冲突解决规则

### 8.1 冲突场景定义

当多个信号映射到同一个 Agent引擎 动作时，产生翻译冲突。冲突场景包括但不限于：

| 冲突类型 | 描述 | 典型示例 |
|---------|------|---------|
| **Bucket 冲突** | 不同维度的评分指向不同的 Bucket 等级 | 7 组件综合评分指向 A-Tier，但 rubric 加权总分指向 B-Tier |
| **路径冲突** | 多个 Bump 信号同时触发，指向相反的路径变更 | UPGRADE_BUMP 和 DOWNGRADE_BUMP 在同一轮复盘中共存 |
| **策略冲突** | 多个维度翻译结果对同一 Agent 给出矛盾建议 | HP ≥ 8 建议"保持钩子策略"，但 ER-Curve S1 ≤ 4 建议"重写钩子" |
| **优先级冲突** | 同一注入点同时存在不同优先级的信号 | URGENT 的 DOWNGRADE_BUMP 和 NORMAL 的 PATTERN_DISCOVERY 同时到达 |

### 8.2 冲突解决优先级规则

当翻译冲突发生时，总线按以下优先级顺序解决：

```
冲突解决优先级（从高到低）：

  1. 信号来源优先级：
     URGENT 信号 > NORMAL 信号 > LOW 信号
     （高优先级信号覆盖低优先级信号的同目标映射）

  2. 信号类型优先级（同优先级内）：
     Bump 信号 > 偏差分析信号 > 预测信号 > 选题推荐信号
     （后产生的信号比先产生的信号更有决策权重）

  3. 置信度优先级（同类型内）：
     high > medium-high+ > medium > speculative
     （高置信度信号的映射优先采纳）

  4. 数据来源优先级（同置信度内）：
     自有数据驱动 > 对标数据驱动
     （自有数据的映射优先于对标数据的映射）

  5. 保守优先原则（以上全部相同时）：
     当所有优先级条件相同时，采纳更保守的翻译结果
     （如：A-Tier vs B-Tier 冲突 → 采纳 B-Tier 映射的默认路径而非中度偏上路径）
```

### 8.3 具体冲突场景的解决流程

#### 8.3.1 Bucket 冲突解决

```
当 7 组件综合 Bucket ≠ rubric 加权 Bucket 时：

  Step 1：检查差异幅度
    ├── 差异 ≤ 1 个 Bucket 等级（如 A vs B）→ 采纳更保守的 Bucket
    │   理由：保守策略降低过度投入风险
    └── 差异 ≥ 2 个 Bucket 等级（如 S vs C）→ 触发 BR_ERR_BUCKET_CONFLICT

  Step 2（差异 ≥ 2 时）：置信度仲裁
    ├── 7 组件的置信度 > rubric 的置信度 → 采纳 7 组件 Bucket
    ├── rubric 的置信度 > 7 组件的置信度 → 采纳 rubric Bucket
    └── 置信度相同 → 采纳更保守的 Bucket + 标注"⚠️ Bucket 内部冲突"

  Step 3：翻译输出中附加冲突标注
    "⚠️ Bucket 冲突：7组件={A-Tier}，rubric={B-Tier}，采纳={B-Tier}，理由={保守优先}"
```

#### 8.3.2 路径冲突解决

```
当 UPGRADE_BUMP 和 DOWNGRADE_BUMP 同时存在时：

  Step 1：检查信号的时间顺序
    ├── 两者时间差 > 1 个样本周期 → 采纳更新的信号
    └── 两者时间差 ≤ 1 个样本周期 → 进入 Step 2

  Step 2：乖离率仲裁
    ├── UPGRADE_BUMP 的乖离率 < DOWNGRADE_BUMP 的乖离率 → 采纳 DOWNGRADE_BUMP
    │   理由：更大的乖离率意味着更严重的预测偏差，降级更安全
    └── 反之 → 采纳 UPGRADE_BUMP，但标注"⚠️ 路径冲突：同时存在升级和降级信号"

  Step 3：C-001 最终裁决
    → 无论总线如何仲裁，C-001 保留最终裁决权
    → C-001 可选择：执行仲裁结果 / 冻结路径变更 / 要求更多数据
```

#### 8.3.3 策略冲突解决

```
当多个维度翻译结果对同一 Agent 给出矛盾建议时：

  解决规则：维度优先级
    HP（钩子力量）> ER（情感共鸣）> NA（叙事结构）> QL（逻辑质量）> AB（受众连接）> SR（传播力）> SAT（满足感）

  理由：HP 是短视频最关键的前 3 秒决定因素，优先级最高。
  当 HP 和其他维度冲突时，以 HP 的翻译结果为主，其他维度的建议降级为"参考意见"。

  示例：
    HP ≥ 8 → "保持钩子策略"
    ER-Curve S1 ≤ 4 → "重写钩子"
    冲突解决：采纳 HP 的"保持钩子策略"为主策略，
    但附加标注"⚠️ ER-Curve S1≤4 与 HP≥8 冲突，建议在保持主钩子的同时准备 1 个备选钩子变体"
```

## §9 信号翻译性能要求

### 9.1 延迟上限

总线翻译层的处理延迟 MUST 满足以下上限：

| 操作类型 | 延迟上限（P50） | 延迟上限（P99） | 说明 |
|---------|----------------|----------------|------|
| 单维度翻译（如 Bucket → 路径） | ≤ 50ms | ≤ 200ms | 查表映射，无复杂计算 |
| 多维度复合翻译（如 7 组件 + ER-Curve → 策略建议） | ≤ 200ms | ≤ 500ms | 需要复合规则匹配 |
| 完整 Stage 信号翻译（输入 + 输出） | ≤ 500ms | ≤ 1500ms | 包含格式校验 + 翻译 + 精度自检 |
| Bump 信号翻译 + 乖离率审计 | ≤ 1000ms | ≤ 3000ms | 包含五步验证翻译 + 审计计算 |
| 置信度计算 + 降档判定 | ≤ 100ms | ≤ 300ms | 纯数值计算 |

> 注：以上延迟指总线翻译层自身的处理时间，不含 Agent引擎 或 闭环校准系统 的响应时间。

### 9.2 吞吐量下限

总线翻译层 MUST 满足以下吞吐量下限：

| 场景 | 最小吞吐量 | 说明 |
|------|-----------|------|
| 单注入点连续翻译 | ≥ 10 条/秒 | 单个 Stage Hook 的连续信号翻译 |
| 多注入点并行翻译 | ≥ 5 条/秒/注入点 | 三个 Stage 同时激活时的每注入点吞吐 |
| Solo 模式翻译 | ≥ 20 条/秒 | Solo 模式下翻译为人类可读格式，无 Agent引擎 注入开销 |
| Bump 评估翻译 | ≥ 2 条/秒 | Bump 信号翻译较复杂，但频率低 |

### 9.3 性能降级策略

当翻译层延迟超过 P99 上限或吞吐量低于下限时：

```
性能降级分级：

  Level 0（正常）：
    · 延迟 ≤ P99 上限，吞吐量 ≥ 下限
    · 所有翻译规则完整执行

  Level 1（轻度降级）：
    · 触发条件：延迟 > P99 上限 但 ≤ 2×P99 上限
    · 降级行为：
      - 跳过翻译精度自检（§7.2 Step 2-4），仅执行 Step 1 字段完整性检查
      - 复合信号简化为单一信号（APPROXIMATE 翻译）
      - 标注"⚠️ 翻译层轻度降级，部分精度检查已跳过"

  Level 2（中度降级）：
    · 触发条件：延迟 > 2×P99 上限 或 吞吐量 < 0.5×下限
    · 降级行为：
      - 仅执行核心翻译（Bucket → 路径、Bump 信号类型判定）
      - 维度翻译降级为批量映射（不逐维度翻译）
      - LOW 优先级消息直接丢弃
      - 标注"🚫 翻译层中度降级，仅核心翻译执行"

  Level 3（重度降级）：
    · 触发条件：延迟 > 5×P99 上限 或 吞吐量 < 0.2×下限
    · 降级行为：
      - 进入翻译降级模式（见 §6.5）
      - 闭环校准系统 输出原封不动传递，标注"原始信号（翻译层重度降级）"
      - C-001 自动转入保守策略
      - 总线标记 BUS_DEGRADED
```

### 9.4 性能监控指标

总线翻译层 SHOULD 暴露以下监控指标：

| 指标名 | 类型 | 说明 |
|--------|------|------|
| `bridge_translation_duration_seconds` | histogram | 翻译耗时分布 |
| `bridge_translation_total` | counter | 翻译总数（按 stage / priority / precision 分标签） |
| `bridge_translation_errors_total` | counter | 翻译错误数（按 error_code 分标签） |
| `bridge_conflict_resolutions_total` | counter | 冲突解决次数（按 conflict_type 分标签） |
| `bridge_precision_level_total` | counter | 翻译精度分布（EXACT / APPROXIMATE / LOST） |
| `bridge_degradation_level` | gauge | 当前降级等级（0-3） |
