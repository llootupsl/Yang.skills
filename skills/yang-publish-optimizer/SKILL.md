# yang-publish-optimizer · 发布时间优化器

> **前置条件**：calibration_samples ≥ 8（足够构建初始分布）
>
> **产生**：发布时间推荐 + 置信度
>
> **依赖**：`.yang-state.json`（复盘数据中的发布时间 + 播放量）

## 失败模式编码

| 编码 | 名称 | 描述 |
|------|------|------|
| PUB-E01 | INSUFFICIENT_SAMPLES | 校准样本 < 8，无法构建初始分布 |
| PUB-E02 | NO_RETRO_DATA | predictions/ 中无复盘数据，无法提取发布时间+播放量 |
| PUB-E03 | SPARSE_TIMESLOTS | 所有时段样本都很少（< 3 条），推荐结果不可靠 |
| PUB-E04 | LOOKBACK_TOO_SHORT | 回溯天数不足，数据量不够支撑分析 |
| PUB-E05 | CROSS_ANALYSIS_UNAVAILABLE | 样本 < 20，时段×星期交叉分析不可用 |

## 反例黑名单

1. **禁止在样本不足时输出高置信度推荐**：样本 < 30 时置信度必须标注"低"，不得虚报
2. **禁止忽略时段样本不均**：某时段仅 1-2 条数据时，不得将其作为独立推荐窗口
3. **禁止伪造播放量数据**：所有播放量必须从复盘文件实际提取，不得用估算值填充
4. **禁止默认黄金时段为唯一推荐**：F 时段（19:00-22:00）可作为备选，但不得作为唯一推荐
5. **禁止跳过置信度标注**：每个推荐窗口必须附带置信度百分比
6. **禁止忽略星期维度**：推荐必须包含星期信息，不得只推荐时段
7. **禁止在交叉分析不可用时强行输出**：样本 < 20 时不得输出交叉分析结果

## 工作流

### Step 1: 收集历史数据

> 🔍 **检查点 CP-1**：确认复盘数据 ≥ 8 条且含发布时间字段，否则输出 PUB-E01/PUB-E02

从 `predictions/` 目录中扫描所有已复盘的预测文件（含 `## 发布信息` 和 `## 复盘` 段），提取：
- 发布时间（精确到分钟）
- 发布星期几
- 发布小时段
- 实际播放量

### Step 2: 时间窗口编码

| 编码 | 时段 | 描述 |
|------|------|------|
| A | 07:00-09:00 | 早安通勤 |
| B | 09:00-12:00 | 上午摸鱼 |
| C | 12:00-14:00 | 午休 |
| D | 14:00-17:00 | 下午工作 |
| E | 17:00-19:00 | 下班通勤 |
| F | 19:00-22:00 | 黄金时段 |
| G | 22:00-24:00 | 深夜 |

### Step 3: 星期维度分析

计算每日平均播放量，输出柱状图。

### Step 4: 时段 × 星期交叉分析

> 🔍 **检查点 CP-2**：确认样本 ≥ 20，否则输出 PUB-E05 并跳过交叉分析

若样本 ≥ 20 则启用交叉分析。

### Step 5: 生成推荐窗口

> 🔍 **检查点 CP-3**：确认推荐窗口含星期+时段+置信度，无遗漏字段

```
⏰ 发布时间推荐

样本数: N=15（≥8 ?）

推荐窗口: 周五 19:00-21:00
  置信度: 65%（中等）

备选窗口 1: 周四 19:00-21:00
  置信度: 55%

备选窗口 2: 周日 09:00-11:00
  置信度: 50%

⚠ N<30，置信度低，建议继续收集数据。
```

### Step 6: 进阶分析（规划中）

📊 目前仅支持频率统计方法。未来版本将引入贝叶斯优化。

短期增强：从 `.yang-state.json` 的 `calibration_records` 中提取发布时间 + 表现数据做频率统计，按时段 × 星期交叉排序推荐窗口。

### Step 7: 输出后续实验计划

> 🔍 **检查点 CP-4**：确认 A/B 测试方案已输出，含对照窗口和评估指标
> 🔍 **检查点 CP-5**：确认置信度标注与样本量一致（N<30 标注低置信度）

建议 A/B 测试方案。

## 量化标准：推荐置信度分级细则

发布时间推荐的置信度必须按以下分级标准量化，不得主观标注：

| 置信度等级 | 标签 | 样本量要求 | 附加条件 |
|-----------|------|-----------|---------|
| ≥ 80% | 高置信度 | N ≥ 30 | 交叉分析可用 + 推荐窗口内样本 ≥ 5 |
| 60%-79% | 中置信度 | N ≥ 15 | 至少 2 个时段有 ≥ 3 条样本 |
| 40%-59% | 低置信度 | N ≥ 8 | 仅频率统计可用，交叉分析不可用 |
| < 40% | 极低置信度 | N < 8 | 不输出推荐，仅输出默认黄金时段 + "数据不足"警告 |

**置信度计算公式**：
```
置信度 = min(N/30, 1) × 60% + 时段覆盖度 × 20% + 交叉分析可用性 × 20%
其中：
  时段覆盖度 = 有样本的时段数 / 7
  交叉分析可用性 = N≥20 ? 1 : 0
```

## 发布时间 A/B 测试

通过设计对比实验验证发布时间推荐的有效性，而非仅依赖历史数据推断：

### 实验设计框架

| 要素 | 说明 |
|------|------|
| 实验目标 | 验证推荐窗口是否优于当前发布时间 |
| 自变量 | 发布时间（推荐窗口 vs 对照窗口） |
| 因变量 | 播放量 / 互动率 / 完播率 |
| 控制变量 | 内容类型、脚本质量、发布平台（保持一致） |

### 实验方案

**方案一：交替测试（推荐，低风险）**

```
第 1 周: 推荐窗口发布（如周五 19:00-21:00）
第 2 周: 对照窗口发布（如当前习惯的周三 12:00-14:00）
第 3 周: 推荐窗口发布
第 4 周: 对照窗口发布
→ 4 周后对比两组数据的平均表现
```

- 优点：节奏稳定，不影响发布频率
- 缺点：周期较长，受内容质量波动影响

**方案二：同周对比（快速验证，需双内容）**

```
同一周内发布 2 条同类型内容:
  内容 A: 推荐窗口（周五 19:00）
  内容 B: 对照窗口（周三 12:00）
→ 控制脚本质量差异（建议评分差异 < 1 分）
```

- 优点：1 周内出结果
- 缺点：需要双倍内容产出，脚本质量差异可能干扰

**方案三：渐进迁移（最安全）**

```
阶段 1（2 周）: 80% 推荐窗口 + 20% 对照窗口
阶段 2（2 周）: 60% 推荐窗口 + 40% 对照窗口
阶段 3（2 周）: 100% 推荐窗口
→ 每阶段评估表现，异常时回退
```

- 优点：风险最低，可随时回退
- 缺点：验证周期最长（6 周）

### 实验结果评估

| 指标 | 计算方式 | 显著性判定 |
|------|---------|-----------|
| 播放量提升率 | (推荐窗口均值 - 对照窗口均值) / 对照窗口均值 | ≥ 15% 为显著 |
| 互动率提升率 | (推荐窗口互动率 - 对照窗口互动率) / 对照窗口互动率 | ≥ 10% 为显著 |
| 完播率提升率 | (推荐窗口完播率 - 对照窗口完播率) / 对照窗口完播率 | ≥ 5% 为显著 |

### 实验记录

每次 A/B 测试结果记录到 `.yang-state.json` 的 `ab_tests` 数组：

```json
{
  "ab_tests": [
    {
      "test_id": "ab-2026-06-14-001",
      "started_at": "2026-06-01",
      "ended_at": "2026-06-28",
      "method": "alternating",
      "recommended_window": "周五 19:00-21:00",
      "control_window": "周三 12:00-14:00",
      "sample_count_recommended": 4,
      "sample_count_control": 4,
      "result": {
        "plays_lift": "+22%",

```

### 实验注意事项

- 每组至少 4 条内容才能得出初步结论（< 4 条仅作参考）
- 脚本评分差异 > 1 分的对比数据需标注"内容质量差异可能干扰"
- 实验期间不得同时调整其他变量（如内容类型、发布平台）
- 实验失败（推荐窗口无显著优势）时，保留当前发布时间，记录失败原因

## 季节性调整规则

不同季节和节假日的用户行为模式差异显著，发布时间需相应调整：

### 季节性调整矩阵

| 季节/时段 | 用户行为特征 | 推荐时段调整 | 调整幅度 |
|----------|------------|------------|---------|
| 春节（除夕-初七） | 家庭聚会、走亲访友，碎片化使用 | 推迟到 21:00-23:00 深夜档 | +2 小时 |
| 寒假（1-2 月） | 学生群体活跃，日间使用增加 | 增加 B/C 时段（09:00-14:00）权重 | +20% 日间权重 |
| 暑假（7-8 月） | 同上，且夜间活跃延长 | G 时段（22:00-24:00）权重提升 | +15% 深夜权重 |
| 长假（国庆等 7 天） | 类似春节，但旅行内容消费增加 | 旅行/生活类内容提前到 E 时段 | +1 小时 |
| 小长假（清明/端午/中秋） | 短途出行，午间和晚间活跃 | C + F 时段优先 | 无调整 |
| 双十一/618 | 购物内容竞争激烈，非购物内容被挤压 | 避开 20:00-22:00 购物高峰 | -1 小时 |
| 开学季（8 月底-9 月初） | 学生群体使用时间收缩 | 减少日间权重，增加 F 时段 | -15% 日间权重 |
| 年底（12 月） | 总结/回顾类内容需求增加 | 此类内容优先 F 时段 | 无调整 |

### 节假日前置发布策略

| 节假日类型 | 前置时间 | 理由 |
|-----------|---------|------|
| 春节 | 提前 2 天 | 节日期间创作和消费均下降 |
| 长假 | 提前 1 天 | 假期首日流量尚可，后续递减 |
| 小长假 | 当天上午 | 短假期影响较小 |
| 购物节 | 提前 3 天 | 避开大促当天流量被瓜分 |

### 季节性调整输出格式

在发布时间推荐中追加季节性标注：

```
⏰ 发布时间推荐

📅 季节性调整: 暑假模式（7-8 月）
  调整: 深夜档权重 +15%，日间档权重 +20%

推荐窗口: 周五 20:00-22:00（原 19:00-21:00，暑假延后 1 小时）
  置信度: 65%（中等）
  季节性调整: +1 小时（深夜活跃延长）

备选窗口 1: 周日 10:00-12:00（暑假日间权重提升）
  置信度: 55%
  季节性调整: 新增日间推荐（学生群体活跃）
```

### 季节性数据积累

- 每个节假日/季节结束后，记录该时段的实际表现数据
- 积累 ≥ 2 个相同节假日的数据后，季节性调整从"规则推断"升级为"数据驱动"
- 季节性调整规则每年复盘一次，根据最新数据更新

## 发布时间推荐解释

每个推荐时间必须附带理由说明，让用户理解推荐依据而非盲目执行：

### 解释格式

每个推荐窗口必须包含以下四要素：

```
⏰ 推荐窗口: 周五 19:00-21:00

📊 数据依据:
  · 该时段历史平均播放量: 8.5 万（高于整体均值 6.2 万，+37%）
  · 该时段样本数: 5 条（占总量 33%）
  · 该时段 × 周五交叉表现: 平均 9.1 万（交叉分析可用）

🧠 推理逻辑:
  · 周五晚间用户进入周末心态，内容消费意愿强
  · 该时段与你的内容类型（观点视频）匹配度高
  · 历史数据显示周五 F 时段的互动率比其他时段高 22%

⚠️ 不确定性:
  · 样本量偏少（N=15），统计显著性有限
  · 周五 F 时段竞争激烈，头部账号集中发布
  · 未考虑季节性因素（当前为暑假，深夜档可能更优）

💡 替代方案:
  · 若周五发布冲突，周四 F 时段是次优选择（平均 7.8 万）
  · 若追求低竞争，周日 C 时段（12:00-14:00）竞争较小
```

### 解释要素说明

| 要素 | 内容 | 作用 |
|------|------|------|
| 数据依据 | 具体数字 + 对比基准 | 让用户判断数据是否可信 |
| 推理逻辑 | 从数据到推荐的因果链 | 让用户理解推荐思路 |
| 不确定性 | 样本量限制、竞争环境、未考虑因素 | 防止用户过度信赖推荐 |
| 替代方案 | 次优选择 + 低竞争选项 | 给用户灵活决策空间 |

### 不同置信度的解释策略

| 置信度 | 解释策略 | 语气 |
|--------|---------|------|
| ≥ 80% | 重点展示数据依据，推理逻辑可简略 | "数据明确支持" |
| 60%-79% | 平衡数据依据和推理逻辑，充分说明不确定性 | "数据倾向支持，但需注意" |
| 40%-59% | 弱化数据依据，强调推理逻辑和不确定性 | "初步推测，建议 A/B 测试验证" |
| < 40% | 不输出推荐，仅输出默认黄金时段 + 不确定性说明 | "数据不足，使用默认建议" |
