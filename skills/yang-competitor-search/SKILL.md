# yang-competitor-search · 多平台竞品发现与数据采集

## ⚡ 紧凑核心规则

**搜索意图竞品**：除了按账号名搜索竞品，还支持按搜索意图关键词发现竞品——搜索"AI工具推荐"看谁在排名前列，这些就是你的搜索意图竞品。调用search_intent.py的detect_content_gap()可同时发现竞品和内容空白。

> **前置条件**：`adapters/competitor-search/search.py` 和 `adapters/competitor-data/collector.py` 必须存在于项目根目录
>
> **产生**：竞品数据库记录 + 竞品快照 + `.yang-state.json` 更新
>
> **依赖**：adapters/competitor-search/search.py, adapters/competitor-data/collector.py, adapters/data_pipeline/db.py

> [前置条件] 运行本 skill 前，必须满足: 竞品搜索工具和采集工具已安装

验证以下文件存在于项目根目录：
- `adapters/competitor-search/search.py` — 多平台竞品搜索脚本

## 执行流程

### Step 1: 确认搜索关键词和平台范围

询问用户：
- 搜索关键词（赛道名/领域名，如"知识付费""AI绘画"）
- 目标平台（默认全平台：抖音/小红书/B站/快手）
- 返回数量（默认每平台 20 个）
- 是否启用 Sherlock 跨平台查询（可选）

### Step 2: 执行多平台搜索

> 🔍 **检查点 CP-1**：确认关键词非空且平台列表 ≥1，否则回退 Step 1

调用命令：

```bash
python adapters/competitor-search/search.py "{keyword}" --platforms "{platforms}" --limit {limit} --output .temp_search_result.json
```

读取 `.temp_search_result.json`，检查返回结果。

- 若 `search_meta.errors` 非空 → 向用户报告失败的平台
- 若 `total_found = 0` → 提示用户更换关键词或扩大平台范围

### Step 3: 采集竞品基础数据

> 🔍 **检查点 CP-2**：验证 `.temp_search_result.json` 存在且 `total_found > 0`，否则终止并提示

对每个发现的竞品，尝试采集更多数据：

```bash
python adapters/competitor-data/collector.py {account_url_or_id} --source {source} --output .temp_collect_{uuid}.json
```

采集策略：
| 平台 | 优先源 | 降级方案 |
|------|--------|----------|
| B站 | `bilibili_api` | `playwright_fallback` |
| 抖音 | `oceanengine` | `playwright_fallback` |
| 小红书 | `playwright_fallback` | — |
| 快手 | `playwright_fallback` | — |

每个竞品独立 try/except，采集失败不阻塞其他竞品。

### Step 4: 写入竞品数据库

> 🔍 **检查点 CP-3**：确认采集数据列表非空，至少 1 条竞品采集成功

调用 `adapters/data_pipeline/db.py` 中的 `insert_competitor()` 和 `insert_competitor_snapshot()`：

```python
from adapters.data_pipeline import db

for competitor in collected_data:
    competitor_id = db.insert_competitor({
        "account_name": competitor["account_name"],
        "platform": competitor["platform"],
        "account_id": competitor["account_id"],
        "account_url": competitor["account_url"],
        "description": competitor.get("description"),
        "follower_count": competitor.get("follower_count"),
        "content_count": competitor.get("content_count")
    })
    db.insert_competitor_snapshot(competitor_id, {
        "follower_count": competitor.get("follower_count"),
        "content_count": competitor.get("content_count"),
        "avg_engagement": competitor.get("avg_engagement"),
        "account_metrics": competitor.get("account_metrics")
    })
```

更新 `.yang-state.json` 中的 `competitor_count` 字段。

### Step 5: 输出竞品清单

> 🔍 **检查点 CP-4**：验证 `competitor_count` 已写入 `.yang-state.json` 且 ≥1

以表格形式输出发现的竞品（账号名、平台、粉丝数、简介），并给出下一步建议：

```
### 竞品发现结果

| # | 账号名 | 平台 | 粉丝数 | 简介 |
|---|--------|------|--------|------|
| 1 | xxx   | 抖音 | 12.3万 | ... |

📊 共发现 N 个竞品，已写入 project_data.db

下一步建议：
  → 对 Top 3 竞品运行 yang-benchmark 深度分析
  → 注册监控：python monitor.py --add <competitor_id>
```

> 🔍 **检查点 CP-5**：确认临时文件 `.temp_*` 已全部清理

## 失败模式编码

| 编码 | 含义 | 触发条件 | 处置 |
|------|------|----------|------|
| `CS-E01` | 搜索脚本缺失 | `search.py` 不存在 | 提示 `yang-init`，终止 |
| `CS-E02` | 全平台搜索无结果 | `total_found = 0` | 建议换关键词/扩平台，终止 |
| `CS-E03` | 采集器异常 | `collector.py` 抛出未捕获异常 | 标注"数据不完整"，继续 |
| `CS-E04` | 数据库写入失败 | `insert_competitor()` 抛异常 | 检查 `project_data.db`，提示 `yang-init` |
| `CS-E05` | Sherlock 跨平台超时 | Sherlock 查询 >60s 无响应 | 降级为无 Sherlock 策略，继续 |
| `CS-E06` | 临时文件残留 | 流程结束后 `.temp_*` 仍存在 | 自动清理，记录警告 |

## 反例黑名单

1. **禁止仅输出 JSON 不入库**：搜索结果必须写入 `project_data.db`，不得仅存临时文件后交付
2. **禁止单平台失败终止全局**：任一平台搜索失败不得阻断其他平台，必须独立 try/except
3. **禁止跳过采集直接入库**：仅用搜索结果的基础字段入库而跳过 `collector.py` 采集，会导致数据严重不完整
4. **禁止静默丢弃采集失败**：采集失败的竞品必须在输出表格中标注"数据不完整"，不得隐瞒
5. **禁止残留临时文件**：所有 `.temp_*` 文件在流程结束后必须清理，不得留到下次
6. **禁止忽略 Sherlock 降级**：Sherlock 失败时必须告知用户已降级，不得静默跳过
7. **禁止关键词为空搜索**：用户未提供关键词时不得用空字符串或通配符发起搜索
8. **禁止覆盖已有竞品记录**：`insert_competitor()` 遇到同平台同 `account_id` 应更新而非重复插入

## 量化标准：多平台覆盖率

竞品搜索的有效性由**多平台覆盖率**衡量：

- **覆盖率** = 实际返回结果的平台数 / 用户指定的平台数
- **合格线**：覆盖率 ≥ 60%（如指定 4 个平台，至少 3 个有结果）
- **优秀线**：覆盖率 ≥ 80%
- 覆盖率 < 60% 时，输出中必须标注"平台覆盖不足"并建议补充搜索
- 每平台最低有效竞品数：≥ 5 个（不足时标注该平台结果稀疏）

| 场景 | 行为 |
|------|------|
| 搜索关键词不明确 | 让用户确认后再继续 |
| 搜索无结果 (`total_found = 0`) | 建议更换关键词、扩大平台范围、检查网络连接 |
| 部分平台搜索失败 | 报告失败的平台及原因，用剩余平台结果继续 |
| 采集失败 | 不阻塞流程，标注"数据不完整"，继续后续步骤 |
| 数据库写入失败 | 检查 `project_data.db` 是否存在，提示运行 `yang-init` |
| `search.py` 或 `collector.py` 缺失 | 提示运行 `yang-init` 初始化项目 |
| Sherlock 查询无结果 | 降级为不使用 Sherlock 的跨平台策略，不影响流程 |

## 搜索结果质量评估

搜索结果的质量由三个维度综合衡量，每个维度独立评分后加权汇总：

### 覆盖率评估

| 指标 | 计算方式 | 合格线 | 优秀线 |
|------|---------|--------|--------|
| 平台覆盖率 | 返回结果的平台数 / 用户指定平台数 | ≥ 60% | ≥ 80% |
| 关键词覆盖率 | 返回结果中包含核心关键词的账号数 / 总返回数 | ≥ 50% | ≥ 70% |
| 垂直领域覆盖率 | 返回结果中属于目标垂直领域的账号数 / 总返回数 | ≥ 40% | ≥ 60% |

- 覆盖率 < 合格线时，必须标注"⚠ 覆盖不足"并建议补充搜索
- 每平台最低有效竞品数：≥ 5 个（不足时标注该平台结果稀疏）

### 准确性评估

| 指标 | 计算方式 | 合格线 | 优秀线 |
|------|---------|--------|--------|
| 领域相关性 | 人工抽检前 10 条结果中属于目标领域的比例 | ≥ 70% | ≥ 90% |
| 账号活跃度 | 最近 30 天内有发布的账号数 / 总返回数 | ≥ 50% | ≥ 70% |
| 数据完整性 | 采集到完整基础数据（粉丝数+简介+内容数）的账号数 / 总返回数 | ≥ 60% | ≥ 80% |

- 准确性 < 合格线时，标注"⚠ 结果准确性偏低"并建议调整关键词
- 数据完整性不足时，标注"数据不完整"的竞品数量和占比

### 时效性评估

| 指标 | 计算方式 | 合格线 | 优秀线 |
|------|---------|--------|--------|
| 数据新鲜度 | 最近 7 天内采集的记录数 / 总记录数 | ≥ 30% | ≥ 60% |
| 账号活跃新鲜度 | 最近 30 天内有更新的账号数 / 总返回数 | ≥ 50% | ≥ 70% |
| 搜索时间戳 | 本次搜索距今天数 | ≤ 7 天 | ≤ 1 天 |

- 时效性 < 合格线时，标注"⚠ 数据偏旧"并建议重新搜索
- 超过 90 天未更新的竞品记录应标记为 `stale`，建议重新采集

### 综合质量评分

```
综合质量评分 = 覆盖率 × 0.4 + 准确性 × 0.35 + 时效性 × 0.3
满分 100 分，≥ 70 为合格，≥ 85 为优秀
```

输出格式：
```
📊 搜索结果质量评估
  覆盖率: 75/100 | 准确性: 68/100 | 时效性: 82/100
  综合质量: 75/100 ✅ 合格
  ⚠ 准确性偏低，建议调整搜索关键词
```

## 竞品账号筛选规则

从搜索结果中筛选真正有价值的对标账号，需通过以下五层漏斗：

### 第一层：基础门槛过滤

| 条件 | 标准 | 不满足时 |
|------|------|---------|
| 账号活跃度 | 最近 60 天内有发布 | 标注"不活跃"，降级处理 |
| 粉丝数下限 | ≥ 1000（或所在平台中位数以上） | 排除，标注"体量过小" |
| 内容数下限 | ≥ 10 条公开内容 | 排除，标注"样本不足" |
| 领域相关性 | 主营内容与目标领域匹配度 ≥ 60% | 排除，标注"领域偏移" |

### 第二层：质量信号筛选

| 信号 | 评估方式 | 权重 |
|------|---------|------|
| 平均互动率 | (点赞+评论+分享) / 播放量 | 高 |
| 内容稳定性 | 近 10 条内容播放量标准差 / 均值 | 中 |
| 粉丝增长趋势 | 近 30 天粉丝增量（若可获取） | 中 |
| 商业化程度 | 是否有品牌合作/带货/广告内容 | 低 |

### 第三层：对标价值评估

| 维度 | 评估标准 | 优先级 |
|------|---------|--------|
| 策略可复用性 | 该账号的内容策略是否可被借鉴 | P0 |
| 阶段匹配度 | 该账号当前阶段是否与用户阶段相近 | P0 |
| 差异化空间 | 该账号未覆盖的选题/角度/风格 | P1 |
| 数据可获取性 | 该账号的公开数据是否足够分析 | P1 |

### 第四层：去重与合并

- 同一账号在多平台出现 → 以粉丝数最多的平台为主记录，其他平台标记为"跨平台存在"
- 同一公司/团队运营的多个账号 → 标注关联关系，避免重复计数
- 已存在于 `project_data.db` 的竞品 → 不重复插入，更新快照数据

### 第五层：排序与推荐

最终筛选结果按以下公式排序：

```
对标价值分 = 策略可复用性(0-10) × 0.3 + 阶段匹配度(0-10) × 0.25 + 数据表现(0-10) × 0.25 + 差异化空间(0-10) × 0.2
```

输出格式：
```
🎯 竞品账号筛选结果（从 N 个搜索结果中筛选）

| # | 账号名 | 平台 | 对标价值分 | 筛选结果 | 原因 |
|---|--------|------|-----------|---------|------|
| 1 | xxx | 抖音 | 8.5 | ✅ 推荐 | 策略可复用、阶段匹配 |
| 2 | yyy | B站 | 6.2 | ⚠️ 备选 | 领域偏移但风格可借鉴 |
| 3 | zzz | 小红书 | 3.1 | ❌ 排除 | 不活跃、体量过小 |
```

## 搜索策略优化

根据搜索结果反馈动态调整搜索关键词和策略，形成闭环优化：

### 关键词优化规则

| 搜索结果反馈 | 诊断 | 优化动作 |
|-------------|------|---------|
| 结果为空（0 条） | 关键词过于狭窄或冷门 | 扩大关键词范围：上位词替换（"AI绘画" → "AI创作"）；添加同义词 |
| 结果过多（>100 条）且相关性低 | 关键词过于宽泛 | 缩小关键词范围：添加限定词（"知识付费" → "知识付费 职场"）；使用引号精确匹配 |
| 结果相关性 < 50% | 关键词歧义或多义 | 添加领域限定词；使用平台特有标签替代通用词 |
| 某平台无结果 | 平台生态差异 | 使用该平台的热门标签/话题词替代通用关键词 |
| 结果均为头部大号 | 缺少中腰部对标 | 添加"新号""起号"等限定词；降低粉丝数筛选下限 |

### 搜索策略迭代流程

```
第 1 轮：用户原始关键词 → 执行搜索 → 质量评估
  ↓ 评估不达标
第 2 轮：根据诊断调整关键词 → 执行搜索 → 质量评估
  ↓ 仍不达标
第 3 轮：切换搜索策略（平台标签/话题/关联推荐）→ 执行搜索 → 质量评估
  ↓ 仍不达标
报告：输出当前最佳结果 + 未覆盖领域说明 + 建议用户手动补充
```

- 最多自动迭代 3 轮，每轮必须告知用户调整内容
- 第 2 轮起，每轮搜索前需用户确认调整方向（避免方向偏移）
- 迭代过程中保留每轮搜索结果，最终合并去重

### 平台特化搜索策略

| 平台 | 推荐搜索策略 | 备选策略 |
|------|------------|---------|
| 抖音 | 话题标签搜索 + 达人搜索 | 搜索结果按粉丝数排序 |
| 小红书 | 笔记关键词搜索 → 提取作者 | 话题页 + 品牌合作列表 |
| B站 | UP主搜索 + 分区排行 | 视频搜索 → 提取UP主 |
| 快手 | 达人搜索 + 话题搜索 | 热门榜单 + 同城推荐 |

### 搜索结果反馈记录

每次搜索完成后，在 `.yang-state.json` 中记录搜索反馈：

```json
{
  "last_search_feedback": {
    "keyword": "知识付费",
    "platforms": ["抖音", "B站"],
    "total_found": 35,
    "quality_score": 72,
    "iterations": 2,
    "keyword_adjustments": ["知识付费 → 知识付费 职场"],
    "searched_at": "2026-06-14T10:00:00+08:00"
  }
}
```

下次搜索时读取 `last_search_feedback`，自动应用历史优化经验。

## 不可妥协原则

1. **搜索结果必须写入 competitors 数据库**（`project_data.db`），不得仅存在临时 JSON 文件中
2. **采集失败不阻塞流程**，但必须在输出中明确标注"数据不完整"的竞品
3. **每个平台搜索独立 try/except**，单平台失败不影响其他平台结果
4. **所有临时文件（`.temp_*`）在流程结束后清理**
