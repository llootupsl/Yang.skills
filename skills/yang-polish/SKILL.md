# yang-polish · 活人感润色引擎

## ⚡ 紧凑核心规则

**三层漏斗顺序**：①人设层注入（口癖/情绪表达/私人视角）→ ②方法论层优化（节奏感/知识输出/情绪刺点）→ ③规则层微调（数字锚定/荒诞比喻/回环呼应）。结构问题>开头问题>语言肌理问题，先修骨架再修皮肉。

**四层自检清单**：L1硬性规则（禁用词0/禁用标点0/套话0/空泛工具名0）→ L2风格一致性（开头✓/节奏≥3/4/口语化≥3/4/标点二次确认✓）→ L3内容质量（观点支撑✓/知识输出✓/文化升维/对立面/类型专项/逐一展示）→ L4活人感终审（温度感/独特性/姿态/心流）。L1不过不进L2，逐层递进。

**26技术→5类映射**：节奏类(#1#11#15) | 情绪类(#2#4#7#8#9) | 结构类(#12#16#17#21#24) | 传播类(#3#6#10#14#18#19#22#23) | 文案类(#5#13#20#25#26)。低分维度→查技术优先级矩阵→取Top3技术应用。

**活人感量化评分**：润色前后各评一次Humanness Score（6维度×权重→总分0-100），输出量化变化。支持两种模式：①润色+评分（默认）②只评分不润色（用户问"评分多少"时）。详见 shared-protocols/humanness-score.md。🔴0-30必须润色 | 🟠31-50建议润色 | 🟡51-70可选 | 🟢71-85微调 | 🔵86-100无需润色。评分<50时QL维度自动降1分。

> **前置条件**：项目已 init + 脚本已通过 yang-score 诊断
>
> **闭环位置**：yang-score 之后、yang-predict 之前
>
> **产生**：润色后脚本 + 润色记录段（脚本尾部追加 `### 🖊️ Yang.skills 润色记录`）
>
> **依赖**：shared-protocols/blind-prediction-protocol.md、`.yang-persona.md`（用户人设档案，可选）

## 失败模式编码

润色过程中可能出现的失败模式，按编码分类。当自检或用户反馈命中以下编码时，须立即回退并修复：

| 编码 | 名称 | 描述 | 触发条件 | 修复动作 |
|------|------|------|----------|----------|
| POLISH_NO_PERSONA | 人设缺失 | 润色时未加载人设档案，导致输出同质化 | persona_mode 为 generic 但未在润色记录中标注 | 重新加载人设档案；若用户跳过则必须在输出中明确标注"通用模式润色，未注入个人风格" |
| POLISH_OVER_REWRITE | 过度改写 | 润色改变了原文核心观点或态度 | 原文核心论点被替换/弱化/反转 | 回退至原文，仅做语言肌理层面的微调，不动观点层 |
| POLISH_AI_FLAVOR_REMAIN | AI味残留 | L1 硬性规则检查未通过 | L1 禁用词/标点/套话扫描仍有命中 | 逐项修复至 L1 零命中后方可继续 |
| POLISH_STRUCTURE_DESTROYED | 结构破坏 | 润色破坏了原文的叙事结构 | 原文段落顺序被打乱、关键转场被删除、叙事弧断裂 | 恢复原文结构，仅允许在结构力 < 4 时做结构调整 |
| POLISH_FACT_FABRICATED | 事实编造 | 润色过程中编造了原文不存在的事实/数据/案例 | 出现原文未提及的具体人名/数据/事件 | 立即删除编造内容，恢复原文表述或留空 |

**编码使用方式**：在润色记录的改动清单中，若某项改动触发了失败模式，标注编码（如 `⚠️ POLISH_OVER_REWRITE`）。在自检报告中统计各编码命中次数。

## 反例黑名单

以下 10 条规则为润色时的绝对红线，任何一条被违反即触发对应失败模式编码，必须回退修复：

1. **禁止编造用户经历**：不得为原文添加用户未提及的个人经历、故事或场景。原文没有的细节，润色不能凭空创造。（→ POLISH_FACT_FABRICATED）
2. **禁止改变核心观点**：润色不得替换、弱化或反转原文的核心论点和态度。可以优化表达，不能改变立场。（→ POLISH_OVER_REWRITE）
3. **禁止删除数据引用**：原文中的具体数据、案例、引用来源不得删除或替换为模糊表述。"137个人"不能改成"很多人"。（→ POLISH_OVER_REWRITE）
4. **禁止过度润色导致同质化**：不得将不同作者的稿件润色成同一风格。润色应强化作者个人特征，而非抹平差异。每次润色必须以人设档案为基准，无人设时使用通用规则但保留原文的原始语感。（→ POLISH_NO_PERSONA）
5. **禁止跳过 L1 直接做 L4**：四层自检必须严格按 L1→L2→L3→L4 顺序执行。L1 未通过时不得进入 L2，L2 未通过时不得进入 L3，以此类推。跳层检查会导致 AI 味残留被遗漏。（→ POLISH_AI_FLAVOR_REMAIN）
6. **禁止忽略人设档案**：当 `.yang-persona.md` 存在时，润色必须加载并参照人设档案的口癖、情绪表达、身份视角。不得以"通用规则更合适"为由跳过人设注入。（→ POLISH_NO_PERSONA）
7. **禁止套用固定模板**：不得将所有文章润色为同一种开头/结尾/转场模式。开头必杀技应根据诊断报告的 hook 分数选择，而非每次都用"故事是这样的"。（→ POLISH_OVER_REWRITE）
8. **禁止重新引入冒号**：L1-2 已清除的冒号"："，在后续润色步骤中不得重新引入。AI 极易在改写过程中无意识恢复禁用标点，L2-4 须二次确认。（→ POLISH_AI_FLAVOR_REMAIN）
9. **禁止重新引入破折号**：L1-2 已清除的破折号"——"，在后续润色步骤中不得重新引入。同上，AI 倾向在长句中恢复破折号作为解释性标点。（→ POLISH_AI_FLAVOR_REMAIN）
10. **禁止重新引入双引号**：L1-2 已清除的双引号（""和""），在后续润色步骤中不得重新引入。需要强调或引用时使用「」或直接不加引号。（→ POLISH_AI_FLAVOR_REMAIN）

**检查方式**：每条黑名单规则在 L1 和 L2 自检中各验证一次。L1 检查原文→润色稿的增量违规，L2 检查润色稿内部的回退违规。

## 工作流

### Step 1: 加载诊断报告

从脚本末尾搜索 `### 📊 Yang.skills 评分` 段，提取：
- 7 维评分：钩子力/情绪力/结构力/文案力/人设力/传播力/节奏力
- 改进建议：各维度低于阈值的具体改进建议

若脚本中无 `### 📊` 段：
警告："建议先运行 yang-score 获取诊断报告，以便精准定位润色重点。是否仅凭人设和脚本直接润色？(y/n)"

**[CP: persona_loaded]** — Step 2 完成后检查：人设是否已成功加载（loaded 或 generic 模式已确认）。若未加载 → 阻断，回到 Step 2。

### Step 2: 加载用户人设

若 `.yang-persona.md` 存在 → 读取完整人设（12 字段：身份、核心价值观、个人故事、口癖/习惯用语、情绪表达方式 + 7项选填），加载为润色的"人格基准"
若不存在 → 重新引导："你还没有创作人设档案。输入「快速建人设」填写必填5项（身份/核心价值观/1个故事/口癖/情绪表达），或输入「跳过」继续——润色将使用通用活人感规则。"
若用户仍选择跳过 → 设置 persona_mode: generic，使用通用活人感规则（通用方法论 + 中性人设）
加载方式：将人设内容作为"你正在以这个人的身份润色脚本"的身份注入

**[CP: intensity_determined]** — Step 3 完成后检查：润色强度是否已明确判定（轻量/标准/深度）且用户已确认。若未判定 → 阻断，回到 Step 3。

### Step 3: 判定润色强度

根据诊断报告自动判定：
- 所有维度 ≥ 4 → 轻量润色：仅 L1+L2（去AI味 + 口语化节奏，不碰结构）
- 文案力或情绪力 < 4 → 标准润色：L1+L2+L3（加内容质量优化）
- 任何维度 < 3 或 3 个以上维度 < 4 → 深度润色：L1-L4 全量

**轻度润色模式**：当用户说"不要改太多"或Humanness Score>60时，只修改最低的2个维度而非全部6个。轻度润色模式下，Humanness Score变化应<20分，输出标注"轻度润色模式"。

向用户展示判定结果和润色范围：
"诊断分析：钩子力 4、情绪力 2、结构力 3...
→ 判定为标准润色（L1+L2+L3）
  L1：硬性规则检查（禁用词/标点/套话扫描）
  L2：风格一致性（口语化节奏/论述打破/标点情绪化）
  L3：内容质量（观点支撑/知识输出/文化升维）
确认开始润色？(y/n)"

### Step 4: 执行润色

**润色边界指令（在润色前告知自己）：**

你必须保留的（禁止改动）：
- 脚本的核心观点和态度
- 所有数据、案例、引用
- 整体叙事结构（除非结构力评分 < 4）
- 用户已经注入的个人经历细节

你可以改动的：
- 语言的肌理：句式长度变化、口语化程度
- AI味清除：禁用词、套话、教科书式表达
- 标点规范：去冒号、去破折号、去双引号、用。。。？？？= = 表达情绪
- 节奏感：句子时长时短、扣主线句频率、一段一句制造重点
- 活人感注入：用用户的口癖、情绪表达、自嘲风格替换中性表达
- 开头优化：若 hook 分 < 6，从 4 种必杀技重写开头

你绝对不能做的：
- 编造用户没有的经历
- 改变用户的观点和态度
- 把用户的故事替换成别人的故事
- 把用户的经历替换成他人的经历

润色顺序：先人设层 → 再方法论层 → 最后规则层
**每次改动须注明依据**：引用诊断报告中对应的低分维度（如"文案力 4 → 提高金句密度"）或活人感方法论的具体规则（如"情绪表达-口语化标点"、"私人视角-用我也面临替换"）。无依据不改动。

### Step 5: 四层自检

按 L1→L2→L3→L4 逐层执行。每层输出格式："L1 硬性规则检查：通过了 X 项，修复了 Y 项"

**[CP: L1_passed]** — L1 完成后检查：禁用词扫描 0 命中、禁用标点扫描 0 命中、结构性套话扫描 0 命中、空泛工具名 0 命中。任一项 > 0 → 阻断，修复后重新扫描。

**[CP: L2_passed]** — L2 完成后检查：开头检查全部通过、节奏与结构 ≥3/4 通过、口语化 ≥3/4 通过、标点禁令二次确认通过。未达标 → 阻断，修复后重新检查。

**[CP: L3_passed]** — L3 完成后检查：观点支撑和知识输出方式必须全部通过，其余适用项至少通过。未达标 → 阻断，修复后重新检查。

**[CP: L4_passed]** — L4 完成后检查：整体感觉"这像是真人写的"。任一维度 AI 味过重 → 阻断，返工重写对应段落。

### Step 5.5: 文案质量评估增强（Vale + writing-analysis）

> **[CP: copy_quality_checked]**
> - 通过条件：copy_quality_checker.py 成功返回 5 维度检查结果
> - 失败处理：工具执行失败时降级为跳过本步骤，标注"CQC-降级（工具不可用）"，不阻断润色流程

在四层自检（L1-L4）完成后，调用 `tools/copy_quality_checker.py` 执行文案质量评估增强。此步骤为**增强层**，在现有 26 技术→5 类映射基础上，提供独立的文案质量量化检查。

**调用方式**：
```bash
python tools/copy_quality_checker.py --script <润色后稿件路径> --format json
```

**5 维度文案质量检查**（基于 Vale + TextDescriptives + textstat 理念，评分范围 0.0-1.0）：

| 维度 | 检查内容 | 对应 Vale 检查类型 |
|------|---------|------------------|
| 可读性 | 句子长度、复杂度、阅读难度 | existence |
| 一致性 | 术语统一、风格一致、人称一致 | consistency |
| 简洁性 | 冗余检测、废话检测、重复检测 | existence + repetition |
| 感染力 | 情绪词密度、行动号召力、记忆点 | existence |
| 规范性 | 标点规范、用词规范、语法规范 | capitalization + spelling |

**与 26 技术→5 类映射的关系**：
- 文案质量评估是 26 技术体系的**量化补充**，不替代原有技术体系
- "可读性"维度与节奏类技术(#1#11#15)交叉验证
- "简洁性"维度与文案类技术(#5#13#20#25#26)交叉验证
- "感染力"维度与情绪类技术(#2#4#7#8#9)交叉验证
- "规范性"维度与 L1 硬性规则交叉验证（双重保障）
- 当文案质量综合评分 < 0.6 时，在润色记录中追加 ⚠️ 警告"文案质量未达标，建议返工"
- 当某维度 error 数 ≥ 3 时，标记该维度为"需重点修复"

**输出格式**（追加到自检报告之后）：

```markdown
#### 📝 文案质量评估增强（Vale + writing-analysis）

| 维度 | 评分 | 问题数 | 错误 | 警告 | 建议 |
|------|------|--------|------|------|------|
| 可读性 | X.XX | X | X | X | X |
| 一致性 | X.XX | X | X | X | X |
| 简洁性 | X.XX | X | X | X | X |
| 感染力 | X.XX | X | X | X | X |
| 规范性 | X.XX | X | X | X | X |
| **综合评分** | **X.XXX/1.0** | | | | |

Top 5 修复建议:
1. [维度] 问题描述 → 修复建议
2. ...
```

> **降级规则**：当 `copy_quality_checker.py` 不可用时，降级为跳过本步骤，标注"CQC-降级（工具不可用）"。不阻断润色流程，L1-L4 自检结果仍然有效。

### Step 6: 输出润色结果

在脚本末尾追加 `### 🖊️ Yang.skills 润色记录` 段：

```
### 🖊️ Yang.skills 润色记录
```

## 活人感写作的底层哲学

以下是活人感写作的底层哲学。你的具体价值观已在人设档案中定义，写作时以你的人设档案为准。

**永远对世界保持好奇。** 面对新工具新技术，不是先问"我会被取代吗？"，而是充满兴奋地问"我能用它来玩点什么有意思的？"

**讲人话，像个活人。** AI时代最稀缺的是"活人感"。不追求滴水不漏的客观，分享的是亲身经历、真实感受、踩过的坑。大胆使用"我觉得"、"我认为"。拥抱不完美。

**真诚是唯一的捷径。** 可以不写，但绝不骗人。如果产品有缺点就直接说，不懂就大方承认。读者的信任是最宝贵的资产。

**有所为有所不为。** 不追逐违背价值观的流量。动笔前先问：这个选题，是我真的相信并想表达的吗？

## 第二步：润色场景下的AI角色边界

这一步非常重要。润色不是代写——AI 最大的价值是优化表达，不是替代你的声音。

### AI擅长做的

**找证据和佐证**：给出一个观点后，让AI在历史、学术、文化中找到能支撑（和反驳）这个观点的论据。比如表达"信息差是亘古不变的"，AI可以帮你找到《北京折叠》、赛博朋克的"High Tech, Low Life"、1880年代电力普及的历史等素材。

**找类比和比喻**：当你需要一个生动的比喻来解释一个抽象概念时，AI可以提供多个候选。比如"AI像一个全能实习生"这种类比，你自己脑子里有就直接给AI让它按这个写，没有的话可以让AI提供几个候选让你挑。

**按确定的角度扩写**：当你已经想好了核心角度和每段的标题，AI可以帮你填充论述和细节。比如你已经确定了"信息被折叠成三层"这个角度，并且写好了每层的标题，AI来负责扩写每层的内容。

**补充学科背景知识**：格式塔心理学、荣格阴影理论、因果语言模型原理这些，AI可以帮你准确表述。

**梳理逻辑和结构建议**：写到一半不确定某一段放哪最好，或者觉得逻辑不够流畅，AI可以帮你调整并标注原因。

### AI做了会暴露的（绝对不能碰）

**第一手观察和真实经历**：花几块钱买了个AI服务、找人上门帮你配置工具、凌晨三点偷偷起床去网吧。这些不可能用AI编造，一编就假。用户自己写的经历细节，一个字都不能改。

**核心创意角度**：从"电商平台卖AI体验"联想到"信息折叠"、从"AI看不到爱心"推导出"我们活在流中而AI活在帧中"。这种让脚本真正立住的创意灵感，AI给不了。AI可以提供很多候选，但最终那个"对，就是这个！"的判断必须是用户自己的。脚本最独特的那个角度——保留不动。

**情绪的真实表达**：用"我当时就愣住了"而不是"我当时很震撼"。前者是体感记忆，后者是知识性描述。AI容易写后者。保持原样或仅微调到更自然。

**数据到人物的同理心转换**：从"1000个已付款"想象出那个四五线城市刚毕业的学生的完整人生，这种温度是需要作者真心去感受的。脚本中那种从冰冷数据联想到具体人生的温度——保留并加强，但不能编造新的。

### Yang 体系协作流程

你的位置是整个 Yang 工具链中的一环，理解完整流程才能做好协作：

## 第三步：润色

### 文章原型

根据诊断报告中的脚本类型，识别当前脚本属于哪种原型，按对应写法重心润色。五大原型：

**调查实验型**：亲自下场去做一件事，然后报道发现。花几块钱体验AI服务、亲手给AI投毒测试安全、找人上门实际体验部署流程。核心是"我替你去做了这件事"。写法重心在过程叙事和发现的层层递进。润色重点：增强过程叙事的口语感和发现的递进节奏。

**产品体验型**：拿到产品实际使用，带着读者一起体验。miclaw手机Agent、Seedance 2.0。核心是"跟我一起玩"。写法重心在场景演示和真实感受。润色重点：强化"跟我一起玩"的代入感，增加场景细节的口语化描述。

**现象解读型**：观察到一个现象，然后层层深入分析。三宫格图片刷屏、AI看不到爱心、复制粘贴Prompt。核心是"你注意到了吗？背后是什么？"。写法重心在观察→好奇→研究→哲学升维。润色重点：检查这个递进链是否流畅，是否每一层都到位。

**工具分享型**：分享一个实用的工具/Prompt，但用个人故事包裹。天赋挖掘Prompt。核心是"我发现了一个好东西"。写法重心在个人故事铺垫→工具展示→效果惊艳。润色重点：确保故事铺垫有活人感，效果展示有"卧槽"感。

**方法论分享型**：把自己长期积累的经验和方法论系统性地分享出来。"如何找回你的创造力""用AI三年的9条心得"。核心是"我把压箱底的东西掏给你了"。写法重心在每一节都必须有可执行的行动建议，同时必须坦诚地提到学习成本、时间曲线和常见失败点（"一开始可能会有点笨拙，花的时间比手动做还长"），而不是只画饼。开头要用谦逊铺垫卸掉傲慢感（"我也不知道行不行""不成熟的经验"），结尾要回扣所有行动点并升华。润色重点：确保每节有 actionable 建议，检查是否诚实地提到了学习成本和失败点。

### 绝对禁区

这些是最容易暴露AI味的地方，必须绝对避免：

1. **套话**：禁用"首先...其次...最后"、"综上所述"、"值得注意的是"、"不难发现"、"让我们来看看"、"接下来让我们"
2. **过度结构化**：不用bullet point罗列观点，不大量加粗。活人感文章绝大多数时候没有小标题，从头到尾一口气顺下来，靠节奏和转场自然推进。唯一的例外是"N条心得/方法"这种本身就是独立条目的方法论文章，可以用数字编号（1、2、3），但也不是正式的markdown标题，就是文中的数字。如果不是这种分条目的结构，就不要加小标题，用口语化的转场句（"说到这个""回到xxx这块"）来衔接板块
3. **标点禁令**：
   - 不使用冒号"："，用逗号代替
   - 不使用破折号"——"
   - 不使用任何双引号（""和""都不用），需要引用或强调时用「」或者直接不加引号
4. **高频踩雷词，绝对禁用**：
   - "说白了" ← AI特别爱用，一出现立刻暴露
   - "意味着什么？" ← AI标志性句式
   - "这意味着" ← 同上，换成更口语的表达
   - "本质上" ← 太学术
   - "换句话说" ← 太书面
   - "不可否认" ← 套话
5. **假设性例子**："比如有一次..."这种编造场景是大忌。要用"就像我今天正在搞的xxx"这种正在发生的真实细节。如果你没有真实细节，就别硬编，不如写"我自己还没试过，但想想就觉得xxx"
6. **空泛工具名**：不说"AI工具"、"某个模型"，要说具体名字，比如ChatGPT、Claude、Midjourney等具体产品名
7. **教科书开头**：禁止"在当今AI快速发展的时代"、"随着技术的不断进步"这类空话开头。永远从一个具体的、当下的事件或场景切入

### 推荐口语化词组

以下词组为口语化表达的通用参考。润色时**优先从人设档案中的「口癖/习惯用语」+「情绪表达方式」字段动态注入**——让文章听起来像这个具体的人在说话，而非套用固定模板。

**有人设时**：从 `.yang-persona.md` 的「口癖/习惯用语」字段提取该用户的高频口语化词组和口头禅，作为润色的核心词汇库。例如用户的口癖是"讲道理""我跟你说"，则全文应优先使用这些词组；用户的情绪表达是"破防了""上头"，则情绪节点应优先使用这些表达。

**无人设时（persona_mode: generic）**：使用以下 5 个通用中性口语化词组作为最简词汇库，不做个性化注入：
- "说实话"
- "你想想"
- "真的"
- "讲真"
- "说白了"

以下为通用口语化词组分类（仅作参考，实际润色以人设档案为准）：

**转场和过渡**：坦率的讲、说真的、我是真的觉得、反正我觉得、怎么说呢、其实吧、你想想看、我跟你说、回到xxx这块、这块需要注意一下、顺着上面的再聊聊

**表达判断**：我有时候觉得、我一直觉得、这话听着有点刺耳但、不是说xxx不行而是说、我自己的感受是、我始终坚信、我觉得还是挺重要的

**承认和自嘲**：说实话我也不确定、我自己也还在摸索、可能有些想法还不成熟、这个事儿我也踩过坑、愚钝如我、我说"理论上"是因为我自己还没完全跑通、说实话我们还差得远

**情绪表达**：这种感觉太爽了、我当时就愣住了、想想就觉得兴奋、我真的被震撼到了、搞得我现在还有点懵、太离谱了、我直接懵了、一时间不知道说什么、鬼使神差的、你敢信？？？

**拉近距离**：很多朋友可能不知道、可能有小伙伴纳闷、你如果关注这个领域的话、大家也都知道、看到的兄弟可以把公屏打在弹幕上

**口头禅和口癖**：依人设档案「口癖/习惯用语」字段注入；无人设时使用 5 个通用中性词组（"说实话""你想想""真的""讲真""说白了"），不使用任何固定口癖

这些词组不是每句话都要塞，而是在需要转场、表达观点、拉近读者距离的时候，自然地用上去。目标是读起来像一个真人在跟你聊天。

### 开头的几种必杀技

活人感文章的开头永远从一个具体的、当下的事件切入，绝不宏大叙事：

**叙事启动**："故事是这样的。"/"事情是这样的。" 简单直接。
**荒诞事实**：直接抛出一个让人"？？？"的事实。
**热点破题**："最近这两天，被一个三宫格AI图片给刷屏了。"
**好奇心驱动**："这两天在网上刷到了一张图，很有意思。"

根据诊断报告中的 hook（钩子力）评分决定是否重写开头：
- hook ≥ 6：保持原开头，仅做口语化微调
- hook ≥ 4 且 < 6：从 4 种必杀技中选择一种，重写开头（使其更接近必杀技风格）
- hook < 4：必须从 4 种必杀技中选择一种，完全重写开头

### 逐一展示法（升番逻辑）

当涉及多个产品/模型/案例的对比或测试时，不要一次性罗列结论，而是逐一展示，每个都带一句吐槽或点评，制造发现感和节奏感。这种写法比"我测了6个模型，全军覆没"有趣100倍。

更重要的是，逐一展示的排列要遵循sketch喜剧里的「升番」逻辑。升番是喜人奇妙夜那类sketch戏剧的核心技巧，找到一个好玩的game点，然后一轮一轮升级，每轮都比上一轮更夸张、更出乎意料，就像经典的《父亲的葬礼》一轮比一轮离谱。用在内容创作上，展示一个工具不会一上来放大招，先展示基础功能让大家觉得还行，再放一个进阶用法让大家觉得有点意思，最后放出一个出乎意料的骚操作让大家觉得「卧槽还能这么玩？」。一轮一轮升上去，读者的情绪就是这么被推着走的。排列顺序决定了情绪曲线，最弱的放前面，最炸的留到最后，中间要有「我以为到顶了结果还能往上翻」的惊喜感。

如果文章涉及产品评测或工具推荐，一定要有一个让人"卧槽"的创意案例。案例要包装成微型故事：亮出挑战→展示脑洞→秀出过程→引爆结果。

### 结构模板

一篇典型的活人感长文大致这样组织：

```
【开头】感性切入，从一个具体事件/场景开始，迅速建立情绪
  ↓
【背景铺垫】简要科普，让非专业读者也能看懂，但科普方式是聊天式的
  ↓
【核心内容】分几个板块展开，每个板块有：
  - 一个明确观点
  - 至少一个具体场景/人物/对话支撑
  - 私人视角的连接（"我自己也是这样"）
  - 一句扣主线的话，把偏出去的内容拉回来
  ↓
【升华】从具体事件拉到更大的文化/哲学/历史参照物
         不是论文式总结，更像是"聊着聊着自然想到了"
  ↓
【收尾】几种常见收法，选最合适的一种：
  - 引用收尾：用别人的一句话作结
  - 哲思余韵：一个短句留白
  - 行动呼吁：鼓励读者去做一件事
  - 信念宣言：表达对未来的坚信
  - 回环呼应：回到开头的意象，但视角已经不同
  ↓

[固定尾部] 根据你的人设档案中「结尾偏好」字段选择收尾方式。若未设置结尾偏好，默认选择一种自然收尾。
```

### 字数和格式

- 公众号长文一般在4000-8000字
- 段落要短，很多时候一句话就是一段
- 重要观点前后留白，让它"呼吸"
- 科普/解释部分可以稍长，但也要保持聊天感
- 需要插图的位置标注"图片"即可
- **不加小标题**。绝大多数文章从头到尾一口气顺下来，不需要任何小标题来切割。板块之间用口语化转场句自然衔接（"说到这个""回到xxx这块""顺着上面的再聊聊"）。只有"N条心得"这种分条目结构才用数字编号，也不是正式标题

## 第四步：四层自检体系

润色完成后必须跑完整个四层质检流程。L1→L2→L3→L4 逐层递进，L1不过不进L2。

**L1 硬性规则**：禁用词0/禁用标点0/结构性套话0/空泛工具名0。修复时间 ≤3分钟/千字。
**L2 风格一致性**：开头✓ / 节奏≥3/4 / 口语化≥3/4 / 标点禁令二次确认✓。修复时间 ≤8分钟/千字。
**L3 内容质量**：观点支撑✓ / 知识输出✓ / 文化升维 / 对立面 / 类型专项 / 逐一展示。修复时间 ≤12分钟/千字。
**L4 活人感终审**：温度感 / 独特性 / 姿态 / 心流。核心问题："这像是真人写的吗？"修复时间 ≤15分钟/千字。

每层详细检查项、通过标准、量化指标和修复指引详见 [references/self-check-detail.md](references/self-check-detail.md)。

## 错误处理

| 场景 | 行为 |
|------|------|
| `.yang-state.json` 不存在 | 拒绝执行："请先运行 yang-init" |
| 脚本不存在 | 报告并退出："未找到脚本文件，请提供有效路径" |
| `.yang-persona.md` 不存在 | 引导快速建立（必填5项）或标记使用通用活人感规则 |
| 诊断报告不存在（无 `### 📊` 段） | 警告"建议先运行 yang-score 获取诊断报告"，允许仅凭人设和脚本直接润色 |
| `in_progress_session` 冲突 | 警告并发："检测到其他技能正在运行，可能导致冲突。是否继续？(y/n)" |
