## 翻译规则

### 规则 1: 线性映射

> 🔍 **检查点 CP-1**：5 个维度的映射公式均已加载，clamp 范围 [1,5] 正确

| Agent群维度 | 闭环校准系统维度 | 映射公式 |
|---------|---------|---------|
| 选题吸引力分 | 钩子冲击力 | `hook = (yang_attr - 0.5) * 1.0` → clamp [1,5] |
| 信息含量分 | 信息增量 | `info = (yang_info - 0.3) * 1.1` → clamp [1,5] |
| 情绪感染分 | 情绪价值 | `emotion = yang_emo * 1.0` → clamp [1,5] |
| 人设匹配分 | 人设契合 | `persona = yang_persona * 1.0` → clamp [1,5] |
| 传播预估分 | 传播力 | `viral = (yang_viral - 0.2) * 1.15` → clamp [1,5] |

### 规则 2: 争议信号处理

> 🔍 **检查点 CP-2**：跨系统争议已检测，差异 >30% 的维度已标记

Agent群评分与闭环校准系统评分差异 > 30% 时标记「跨系统争议」，累计 ≥3 条建议调整映射公式。

### 规则 3: 置信度信号

- 置信度 < 0.3 → 信号不过桥
- 置信度 0.3-0.5 → 通过但标注 [低频]
- 置信度 > 0.5 → 正常通过

### 规则 4: 双向同步节律

> 🔍 **检查点 CP-3**：同步节律已确认，Agent群→闭环校准系统每周期触发、闭环校准系统→Agent群仅在显著变化时触发

```
Agent群 → 闭环校准系统（每周期触发）:
  选题阶段: topic_score → rubric check
  发布前: final_script → blind predict
  发布后: actual_data → retro

闭环校准系统 → Agent群（仅在信号显著变化时触发）:
  bump 后: 新版 rubric → Agent群权重更新
  连续 3 次预测偏差 > 30% → Agent群某维度降权
  新观察积累 ≥3 → Agent群 Agent 调整策略
```

**搜索意图桥接**：Channel E的搜索意图信号通过evolution-bus传递给yang-hook-factory（生成搜索意图钩子）和yang-publish（附加搜索意图标签）。

**Humanness Score桥接**：Humanness Score通过evolution-bus传递给yang-score（QL维度关联）和yang-bump（校准权重调整）。

## 反例黑名单

1. **禁止绕过映射公式**：信号翻译必须经过线性映射公式，不得直接传递原始分值
2. **禁止忽略 clamp**：映射结果超出 [1,5] 必须截断，不得传递越界值
3. **禁止低置信度信号过桥**：置信度 <0.3 的信号必须拦截，不得影响决策
4. **禁止忽略争议累积**：跨系统争议累计 ≥3 条必须触发映射公式调整建议
5. **禁止 Solo 模式下发 Agent 群信号**：Solo 模式下 Agent 群方向必须静默
6. **禁止信号格式不校验**：缺少必须字段的信号必须拒绝翻译，不得补零/补默认值
7. **禁止双向同步节律错乱**：Agent群→闭环校准系统每周期触发，闭环校准系统→Agent群仅在显著变化时触发，不得颠倒
8. **禁止跳过置信度标注**：置信度 0.3-0.5 的信号过桥时必须标注 [低频]，不得省略

## 量化标准：映射保真度

信号翻译的有效性由**映射保真度**衡量：

- **映射保真度** = 翻译后信号与源信号语义一致性的维度占比
- **合格线**：保真度 ≥ 80%（5 维中至少 4 维语义一致）
- **优秀线**：保真度 = 100%
- 跨系统争议率：≤ 1 次/周期（超过则触发映射公式调整）
- clamp 截断率：≤ 10%（超过则说明映射公式需要重新校准）
- 保真度 < 80% 时，必须暂停桥接并建议人工审核映射公式

## 信号翻译质量评估

信号翻译的有效性需要持续评估，确保映射保真度不随时间退化。

### 评估维度

| 评估维度 | 定义 | 测量方法 | 合格线 | 优秀线 |
|----------|------|----------|--------|--------|
| **语义保真度** | 翻译后信号与源信号语义一致的维度占比 | 人工抽样比对翻译前后5个维度的语义一致性 | ≥ 80%（4/5维） | 100% |
| **数值保真度** | 映射后数值与源数值的线性相关程度 | 计算映射前后5个维度的皮尔逊相关系数 | ≥ 0.85 | ≥ 0.95 |
| **截断率** | 被 clamp 截断的信号占比 | 统计 clamp 触发次数 / 总映射次数 | ≤ 10% | ≤ 3% |
| **争议率** | 跨系统评分差异 >20% 的维度占比 | 统计争议标记数 / 总维度评估数 | ≤ 1次/周期 | 0次/周期 |
| **信息完整度** | 翻译过程中未丢失关键信息的信号占比 | 检查翻译后信号是否包含源信号的所有关键语义要素 | ≥ 95% | 100% |
| **方向一致性** | 翻译后评分排序与源评分排序的一致性 | 计算Kendall tau排序相关系数 | ≥ 0.7 | ≥ 0.9 |

### 评估流程

1. **自动评估**（每次信号翻译时）：
   - 截断率实时统计，超过阈值自动告警
   - 争议率实时统计，累计 ≥3 条触发映射公式调整建议
   - 数值越界自动 clamp 并标注

2. **周期评估**（每10个翻译周期）：
   - 抽取最近10次翻译结果，计算数值保真度和方向一致性
   - 对比映射前后排序，检测排序反转（翻译后排序与源排序相反的情况）
   - 输出评估报告到 `.yang-cache/bridge-quality-report.json`

3. **人工评估**（每 bump 后）：
   - 人工比对5个维度的翻译前后语义是否一致
   - 特别关注争议维度和截断维度的语义是否失真
   - 评估结果记录到 `rubric-memo.md`

### 评估结果处置

| 评估结果 | 处置动作 |
|----------|----------|
| 所有维度合格 | 继续运行，无需调整 |
| 截断率 >10% | 调整映射公式偏移量和缩放系数 |
| 争议率 >1次/周期 | 检查映射公式，必要时人工校准 |
| 语义保真度 <80% | 暂停桥接，人工审核映射公式 |
| 方向一致性 <0.7 | 映射公式存在系统性偏差，必须重新校准 |

## 翻译规则维护

翻译规则（映射公式）需要随系统演进持续更新，确保映射保真度不退化。

### 规则更新触发条件

| 触发条件 | 触发方式 | 更新类型 |
|----------|----------|----------|
| 截断率 >10% | 自动检测 | 系数微调 |
| 争议率 ≥3次/周期 | 自动检测 | 系数微调 + 偏移量调整 |
| rubric bump 后维度权重变化 | yang-bump 触发 | 映射公式全面更新 |
| Agent群评分标准漂移 | 人工发现 | 锚点重新校准 |
| 新增/删除维度 | 架构变更 | 映射表重建 |

### 规则更新流程

1. **诊断**：确认触发条件和受影响的维度
2. **分析**：收集最近20次翻译数据，分析偏差模式
3. **调整**：修改 `bridge-rules.md` 中的映射公式
   - 系数微调：调整缩放系数（±0.05步进），调整偏移量（±0.1步进）
   - 全面更新：基于校准池数据重新拟合映射公式
4. **回测**：用历史数据验证新公式，确认截断率 ≤10%、争议率 ≤1次/周期
5. **发布**：更新 `bridge-rules.md`，记录变更到 `rubric-memo.md`
6. **验证**：执行一个完整三阶段周期，确认映射保真度 ≥80%

### 规则版本管理

- 每次规则更新递增版本号（如 `bridge-rules-v1.0` → `bridge-rules-v1.1`）
- 版本号记录在 `bridge-rules.md` 文件头部
- 旧版本规则保留在 git history 中，不删除
- `.yang-state.json` 中记录当前使用的 `bridge_rules_version`

### 规则扩展指南

新增翻译维度时，按以下步骤操作：

1. 在 `bridge-rules.md` 映射表中新增一行：`Agent群新维度 → 闭环校准系统新维度 | 映射公式`
2. 确定映射公式：初始使用线性映射 `y = (x - offset) * scale`，clamp [1,5]
3. 用历史数据回测，确认截断率 ≤10%
4. 更新本 SKILL.md 的"信号流向"和"翻译规则"段
5. 更新 `yang-evolution-bus/SKILL.md` 的"总线与子skill的接口规范"段
6. 更新 `Knowledge-Index.md` 的锚点表（如涉及新知识库引用）

## 跨系统兼容性

yang-bridge 的信号翻译规则设计为可适配不同AI模型和系统，确保跨系统协作的语义一致性。

### 兼容性架构

```
Agent群（任意AI模型）                    闭环校准系统
     │                                      │
     ├─ 信号适配层 ──→ 标准信号格式 ──→ 映射层 ─┤
     │   (模型特定)     (统一JSON)     (通用)   │
     │                                      │
     └─ 置信度归一化 ──→ 标准置信度 ──→ 门控层 ─┘
         (模型特定)     (0.0-1.0)     (通用)
```

### 模型兼容性矩阵

| AI模型/系统 | 信号格式适配 | 评分范围适配 | 置信度适配 | 兼容性等级 |
|------------|-------------|-------------|-----------|-----------|
| **Claude (Anthropic)** | 原生JSON | 1-5分制 → 直接映射 | 原生0.0-1.0 | ✅ 完全兼容 |
| **GPT系列 (OpenAI)** | JSON（需结构化提示） | 1-10分制 → 线性缩放到1-5 | 需从logprobs提取 | ⚠️ 需适配层 |
| **Gemini (Google)** | JSON（需结构化提示） | 1-5分制 → 直接映射 | 需从输出概率提取 | ⚠️ 需适配层 |
| **开源模型 (Llama/Qwen等)** | JSON（需结构化提示+后处理） | 不固定 → 需归一化到1-5 | 需从logits提取或估算 | ⚠️ 需适配层+校准 |
| **自定义Agent系统** | 需实现标准信号格式接口 | 需归一化到1-5 | 需实现置信度输出 | ⚠️ 需完整适配 |

### 适配层规范

每个新模型接入时，需实现以下适配层：

| 适配层 | 功能 | 必须实现 |
|--------|------|----------|
| **信号格式适配器** | 将模型输出转换为标准JSON信号格式（source/stage/payload/confidence/timestamp） | ✅ 必须 |
| **评分范围归一化** | 将模型评分范围映射到1-5标准范围 | ✅ 必须 |
| **置信度提取器** | 从模型输出中提取或估算0.0-1.0置信度 | ✅ 必须 |
| **语义校准器** | 确保模型评分语义与标准rubric维度对齐 | ⚠️ 推荐 |
| **漂移检测器** | 检测模型评分标准随时间的漂移 | ⚠️ 推荐 |

### 跨模型校准协议

1. **初始校准**：新模型接入时，用5条标准样本进行评分对比，确认映射公式适用
2. **周期校准**：每10个翻译周期，检查跨模型评分差异
3. **漂移检测**：连续3次同一模型评分偏差 >20%，标记"模型漂移"，建议重新校准
4. **争议升级**：跨模型争议累计 ≥3 条，升级为跨系统争议，按流程C处理

### 兼容性测试清单

新模型接入前，必须通过以下测试：

- [ ] 信号格式适配：能输出标准JSON信号
- [ ] 评分范围归一化：5个维度评分均在[1,5]范围内
- [ ] 置信度提取：能输出0.0-1.0置信度
- [ ] 语义对齐：5个维度评分语义与rubric定义一致
- [ ] 截断率测试：映射后截断率 ≤10%
- [ ] 争议率测试：与基准模型评分差异 >20%的维度 ≤1个
- [ ] 端到端测试：完成一个完整三阶段周期无错误
