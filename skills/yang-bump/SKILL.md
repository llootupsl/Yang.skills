# yang-bump · Rubric 升级

## ⚡ 紧凑核心规则

**bump触发条件**：calibration_samples ≥ 10 + 存在≥1条待验证观察。前置不满足→拒绝执行。

**验证规则**：5≤N≤10一致率≥80% | 10<N≤30一致率≥70% | N>30一致率≥60%。极差>2标记争议维度，≥3条争议触发权重审查。单次bump最多2种修改类型，公式+删除不可同时。

**版本号升级一句话**：bump通过→rubric_notes.md顶部版本号v<X>.<Y>.<Z>递增（修改权重Y+1/新增维度或改公式Z+1）+删除已吸收观察+stats.rubric_bumps+=1。bump未通过→保留所有观察，不修改rubric。

**Humanness Score校准**：bump时检查Humanness Score的校准数据——如果润色后实际表现与Humanness Score预测不一致（如Score=80但观众反馈"太AI"），调整评分权重。

> **前置条件**：`calibration_samples >= MIN_SAMPLES_FOR_BUMP`（默认 ≥10）
>
> **产生**：rubric_notes.md 版本号 ↑ + 公式更新
>
> **原则**：三条不可妥协原则 #2（Bump = full re-score）

## 工作流

### 验证条件细化标准

> 不同样本数区间的具体验证步骤，确保验证过程可操作、可审计。

**小样本区间（5 ≤ N ≤ 10）**：
1. 逐样本对比新排名与实际表现排名，列出每个样本的"一致/不一致"判定
2. 一致率计算：一致样本数 / 总样本数，要求 ≥ 80%（即 ≥4/5）
3. 争议维度检测：对每个维度计算新评分与旧评分的极差，极差 > 2 → 标记争议
4. 争议维度处理：标记争议维度后，必须在 Step 7 决定前给出解释（为何该维度虽争议但可接受，或需调整公式）
5. 若一致样本 < 4 个 → 直接判定不通过，不进入 Step 7

**中等样本区间（10 < N ≤ 30）**：
1. 逐样本对比 + 按流量档次分组统计一致率（≤1w / 1w-10w / >10w），要求每组至少有 1 个一致样本
2. 整体一致率要求 ≥ 70%
3. 争议维度检测：极差 > 2 标记争议，统计争议维度数量
4. 若争议维度 ≥ 3 条 → 触发权重审查：逐维度检查权重调整是否合理，输出权重审查报告
5. 权重审查报告需包含：调整前权重、调整后权重、争议维度在新旧 rubric 下的评分分布对比
6. 分组一致率若某档为 0% → 标注"该流量档次验证不足"，但不硬性拦截

**大样本区间（N > 30）**：
1. 整体一致率要求 ≥ 60%
2. 争议维度阈值放宽至极差 > 2.5
3. 增加统计显著性检验：对一致率做二项检验，p-value < 0.05 视为统计显著
4. 按平台分组统计一致率，若某平台一致率 < 50% → 标注"该平台验证不足"
5. 输出完整验证报告：整体一致率、分组一致率、争议维度列表、统计检验结果

**通用验证规则**（所有区间适用）：
- 验证过程必须输出完整的样本级对比表，不得只输出汇总数字
- 不一致样本必须逐条说明原因（新评分高估/低估了什么）
- 验证通过/不通过的判定必须是二元结果，不允许"部分通过"

### 维度修改策略

> 不同类型的维度修改有不同的风险等级和执行策略，bump 前必须明确修改类型并按对应策略执行。

**修改类型与策略**：

| 修改类型 | 风险等级 | 触发条件 | 执行策略 | 验证要求 |
|---------|---------|---------|---------|---------|
| **新增维度** | 🟡 中 | 观察积累足够，发现 rubric 未覆盖的特征 | 1. 定义维度名称、评分范围、公式<br>2. 从现有权重中按比例划拨（总权重保持 1.0）<br>3. 对校准池全部样本补打新维度分 | 新维度与现有维度的相关性 < 0.7（避免冗余）；新维度对不一致样本的解释力 > 30% |
| **修改权重** | 🟢 低 | 多次复盘显示某维度系统性高估/低估 | 1. 单次权重调整幅度 ≤ 0.05（5个百分点）<br>2. 调整后重新归一化所有权重<br>3. 记录调整前后权重对比 | 权重调整后，受影响维度的评分分布不应出现断崖式变化（相邻分数段样本数差异 < 3x） |
| **修改公式** | 🟠 中高 | 观察显示某维度评分与实际表现存在非线性关系 | 1. 保留旧公式作为回退方案<br>2. 新公式必须对校准池全部样本重打<br>3. 公式变更需附变更说明（旧→新，变更理由） | 新公式下不一致样本数 ≤ 旧公式下不一致样本数；新公式不得引入新的极端偏差（>50%） |
| **删除维度** | 🔴 高 | 维度连续 3 次 bump 验证中无显著区分力（极差 < 0.5） | 1. 删除前必须确认该维度对至少 1 个样本无区分贡献<br>2. 删除后权重重新分配给最相关的维度<br>3. 保留删除记录（维度名、删除理由、历史权重） | 删除后其余维度的评分稳定性不受影响（composite score 变异系数变化 < 10%） |

**组合修改规则**：
- 单次 bump 最多同时执行 2 种修改类型（避免变更过多导致归因困难）
- 若需 3 种以上修改 → 拆分为多次 bump，每次验证通过后再执行下一次
- 新增维度 + 修改权重 可同时进行（风险叠加可控）
- 修改公式 + 删除维度 不可同时进行（风险叠加过高，归因困难）

**修改影响评估**：
每次修改前，必须输出影响评估报告：
```
📋 维度修改影响评估
  修改类型: <类型>
  影响范围: <受影响样本数/总样本数>
  预期改善: <预计不一致样本减少数>
  风险点: <可能引入的新问题>
  回滚条件: <什么情况下需要回滚>
```

### 回滚预案

> bump 后如果新 rubric 表现不如旧版，按以下预案执行回滚，确保可安全退回。

**回滚触发条件**（满足任一即触发）：
1. bump 后连续 3 条新内容的预测偏差均值 > bump 前近 5 条的偏差均值
2. bump 后首次复盘出现 2 项及以上极端偏差（>50%）
3. bump 后校准池样本的 composite score 分布出现异常偏移（均值变化 > 1.5 分）
4. 用户主动要求回滚

**回滚执行步骤**：

```
🔄 回滚预案执行

Step 1: 确认回滚
  → 输出 bump 前后对比数据，确认回滚必要性
  → 询问用户确认："确认回滚到 v<old>？（y/n）"

Step 2: 恢复 rubric
  → 从 rubric_notes.md 的版本历史中恢复旧版维度、权重、公式
  → 版本号回退：v<new> → v<old>（不使用新版本号，直接回退）
  → 在 rubric_notes.md 顶部追加回滚记录：
    ```
    ⏪ 回滚记录：YYYY-MM-DD
      从 v<new> 回滚至 v<old>
      原因: <触发条件描述>
      回滚前偏差均值: <X%>
    ```

Step 3: 恢复观察
  → 将 bump 时删除的已吸收观察重新写回 `## 观察（待验证）` 区域
  → 标注 `[回滚恢复]` 以区分新观察和恢复的观察

Step 4: 更新状态
  → `.yang-state.json` 更新：
    - `rubric_version` 回退至 v<old>
    - `stats.rubric_bumps` 不变（bump 次数不因回滚减少）
    - 追加 `last_rollback_at: <ISO timestamp>`
    - 追加 `rollback_history[]` 条目

Step 5: 标记校准数据
  → bump 后产生的新校准记录标注 `rubric_version_used: v<new>(rolled_back)`
  → 这些记录仍保留在校准池中，但后续 bump 时标注其基于已回滚版本
```

**回滚安全约束**：
- 回滚后 7 天内不建议再次 bump（冷却期，避免频繁切换）
- 回滚不删除任何校准数据（数据不可丢，只改 rubric）
- 同一版本最多回滚 2 次（第 2 次回滚后建议人工审查 rubric 设计）

**部分回滚**（高级）：
若 bump 包含多项修改，且能明确归因问题到某一修改项：
- 可仅回滚问题修改项，保留其余修改
- 部分回滚需重新执行全量重打和验证
- 部分回滚后版本号使用 `v<X>.<Y>.<Z>-patch1` 格式

### 跨模型审计检查清单

> Channel C 审计时，按以下清单逐项检查，确保 bump 结果经得起第三方模型审视。

**审计前准备**：
- [ ] 确认 Channel C 模型可用（qwen-max / gemini-pro / 自审模式）
- [ ] 准备审计输入包：旧版 rubric + 新版 rubric + 校准池样本 + 新旧评分对比表

**审计检查项**：

| # | 检查项 | 检查内容 | 通过标准 | 不通过处理 |
|---|--------|---------|---------|-----------|
| 1 | **维度合理性** | 新增/修改的维度是否有逻辑依据？是否与现有维度冗余？ | Channel C 模型判定维度定义清晰、无冗余 | 标记争议维度，要求补充依据或调整 |
| 2 | **权重分配合理性** | 权重调整方向是否与观察数据一致？是否存在"过度修正"？ | 权重调整方向与偏差方向一致，单次调整 ≤ 5% | 标记争议权重，要求解释或缩小调整幅度 |
| 3 | **公式逻辑正确性** | 新公式是否在边界条件下仍合理？是否存在数值溢出/除零风险？ | Channel C 模型对 5 个边界测试用例的评分均合理 | 标记公式缺陷，要求修正后重新验证 |
| 4 | **评分分布健康度** | 新 rubric 下评分分布是否合理？是否出现"所有内容都高分/低分"？ | 评分分布的偏度 < 1.5，峰度 < 5.0 | 标记分布异常，要求调整公式或权重 |
| 5 | **一致性偏差检测** | 新 rubric 是否系统性推高/拉低了所有样本的分数？ | 新旧 composite score 均值差 < 1.0 | 触发 `BUMP_ANCHOR_DRIFT`，要求审查 |
| 6 | **不一致样本解释** | 对不一致样本，新 rubric 的解释是否比旧 rubric 更合理？ | Channel C 模型判定新解释更合理 ≥ 50% | 标记解释力不足，要求补充分析 |
| 7 | **观察吸收完整性** | 被吸收的观察是否确实被新 rubric 覆盖？是否有"名义吸收、实际未覆盖"的情况？ | 每条被吸收观察在新 rubric 中有明确的对应维度/公式变化 | 标记未完全吸收的观察，恢复到待验证区 |
| 8 | **回滚可行性** | 回滚路径是否清晰？旧版 rubric 数据是否完整保留？ | 旧版 rubric 完整可恢复，回滚步骤可执行 | 标记回滚风险，要求补充旧版数据 |

**审计输出格式**：

```
🔍 Channel C 审计报告
  审计模型: <qwen-max / gemini-pro / 自审模式>
  审计时间: <ISO timestamp>

  检查结果:
    ✅ 通过: N 项
    ⚠️ 有条件通过: N 项（附条件说明）

  详细结果:
    [1] 维度合理性: ✅ 通过 / ⚠️ 有条件通过 / ❌ 不通过
        <Channel C 的具体评审意见>
    [2] 权重分配合理性: ...
    ...

  审计结论: <通过 / 有条件通过 / 不通过>
```

**审计结论处理**：
- **通过** → 正常进入 Step 7 决定
- **有条件通过** → 在 Step 7 前完成条件整改，整改后无需重新审计
- **不通过** → 退回 Step 4 重新制定公式，整改后需重新审计

### Step 1: 检查校准池

> **🛑 检查点 CP1**：`calibration_samples ≥ MIN_SAMPLES_FOR_BUMP`。若不满足 → 触发 `BUMP_INSUFFICIENT_SAMPLES`，拒绝继续。

从 `.yang-state.json` 读取 `calibration_samples`。

输出: `当前校准池: {N} 条（阈值: 10）`

### Step 1.5: 校准池健康度摘要

在校准池满足前置条件（`calibration_samples ≥ 10`）后，输出健康度摘要（非硬性拦截，仅信息展示）：

```
### 校准池健康度摘要

📊 健康度指标:
  流量覆盖: ≤1w({n}) 1w-10w({n}) >10w({n}) [✅/⚠️]
  时间新鲜度: 最老 {d} 天前，超过 90 天比例 {pct}% [✅/⚠️]
  平台分布: 抖音({n}) B站({n}) 小红书({n}) [✅/⚠️]
```

- 若流量覆盖某档次缺失 → ⚠️ 提示但继续执行 bump
- 若超过 30% 样本超过 90 天 → ⚠️ "大量样本过期，建议优先发布新内容做 retro"
- 若某平台样本为 0 → ⚠️ 提示但继续执行 bump

若 `calibration_samples < 10` → 不输出健康度摘要（样本过少，统计无意义）。

### Step 2: 读取 rubric_notes.md

读出当前版本号和所有 `status: active` 的维度、权重、公式。

### Step 3: 读取所有观察

> **🛑 检查点 CP2**：存在 ≥ 1 条待验证观察。若无观察 → 触发反例黑名单 #4（禁止无观察升级），拒绝继续。

从 `rubric_notes.md` 的 `## 观察（待验证）` 区域读取符合升级条件的观察。

### Step 4: 制定新公式

对每个候选升级维度：
- 定义新维度或修改已有维度的公式
- 设定新的权重分配
- 生成候选版本号（format: `v<X>.<Y>.<Z>`）

### Step 5: 全量重打（Bump = full re-score）

> **🛑 检查点 CP3**：所有校准池样本已重打完成，新旧排名列表完整。若跳过 → 触发反例黑名单 #1（禁止跳过全量重打）。

⚠ 这是强制性步骤，不可跳过。

对校准池中**每一个有实绩数据的样本**：
1. 用新评分规则重新打分
2. 生成新旧排序的两个排名列表
3. 对比：新排名 vs 实际表现排名

### Step 6: 验证条件

> **🛑 检查点 CP4**：验证结果必须明确"通过/不通过"，不允许模棱两可。若不通过 → 触发 `BUMP_VALIDATION_FAILED`。

| 样本数 | 要求 | 争议维度处理 | 备注 |
|--------|------|-------------|------|
| 5 ≤ N ≤ 10 | 新排名与实际表现在 ≥4/5 样本上一致 | 极差 > 2 标记争议（阈值见 [constants.md](../../shared-protocols/constants.md)） | 小样本，严格门槛 |
| 10 < N ≤ 30 | 新排名与实际表现在 ≥70% 样本上一致 | 极差 > 2 标记争议，≥3 条争议维度触发权重审查 | 中等样本 |
| N > 30 | 新排名与实际表现在 ≥60% 样本上一致 | 极差 > 2.5 标记争议 | 大样本，统计稳定性 |

### Step 7: 决定

**若验证通过**：
```markdown
? Bump 通过（v2.0.0 → v2.1.0）

验证结果:
- 一致: 4/5 (80%)
- 不一致: video-003（新评分高估了信息增量，实际观众对深度内容反应平淡）

新增维度:
- 信息密度 (权重 0.15): 原"信息增量"重命名 + 细化公式

调整维度:
- 钩子冲击力 0.30 → 0.25（过度强调钩子，稀释了完播预测精度）

移除观察:
- 2026-03-01 关于钩子权重的观察 → 已吸收

更新文件: rubric_notes.md, .yang-state.json
```

**若验证不通过**：
```
? Bump 被拒

原因: 新排序与实际表现在 3/5 (60%) 样本上不一致，未达到 4/5 阈值。

不一致样本:
- video-002: 新评分低估 20%
- video-004: 新评分高估 15%

建议: 检查待验证观察是否与不一致样本有关联；可能需要更细化的公式调整，而非当前粗粒度的权重挪移。

观察保留: 不删除任何观察。
```

### Step 8: 删除已吸收的观察

若 Bump 通过，删除 `rubric_notes.md` 中被吸收的观察（原则 #3：rubric 是工作台，不是博物馆）。

**降级行为（yang-bump）**：权重调整参考从A降级为B的爆款元素
- 当A降级时：结构精细化三要素不可作为权重调整的参考依据
- 维度权重调整 → 改为以B（八大爆款元素）作为主参考框架
- 钩子相关维度的精细度校验 → 加重C（开篇36计）的权重
- 新维度公式的有效性验证 → 仅使用B的判断标准，去掉A的结构要素
- 知识依据标注自动调整：`A-结构` → `A-占位(B代替)`，`B-爆款` 权重提升至主导

## 跨模型审计（`--strict` 模式）

若用户带着 `--strict` 标志触发 bump：

### Channel C 模型降级链

```
qwen-max → gemini-pro（若有 key）→ 自审模式（fallback）
```

**检测逻辑**：
1. 优先尝试 `mcp__llm-chat__chat` 调用 qwen-max
2. 若 qwen-max 不可用 → 检测 `GEMINI_API_KEY` 环境变量，尝试调用 gemini-pro
3. 若仍不可用 → 降级为自审模式

### 自审模式（CROSS_MODEL_AUDIT=fallback）

当 Channel C 所有外部模型均不可用时，进入自审模式：

- 在 rubric-memo.md 中标注 `[自审] CROSS_MODEL_AUDIT=fallback`
- 在 `.yang-state.json` 中标记 `last_bump_self_audited: true`
- 降低 bump 置信度标签（"高" → "中"）

**自审模式额外执行**：
1. **一致性偏差检测**：将 bump 前后的维度评分分布进行对比，检测是否存在系统性漂移（如"所有维度在新 rubic 下都上升了 0.5+"），若检测到 → 警告并标记 `consistency_bias_detected: true`
2. **锚点漂移检测**：对比 bump 前后的 composite score 均值，若差值 > 1.0 → 警告 `anchor_drift_detected: true`，提示 rubric 修改可能改变了评分基准而非仅微调权重

## 失败模式编码

| 编码 | 含义 | 触发条件 | 处置 |
|------|------|---------|------|
| `BUMP_INSUFFICIENT_SAMPLES` | 校准样本不足 | `calibration_samples < MIN_SAMPLES_FOR_BUMP` | 拒绝执行 bump，提示积累更多 retro |
| `BUMP_VALIDATION_FAILED` | 验证条件未通过 | 新排名与实际表现一致率低于对应样本数阈值 | 拒绝 bump，保留观察，生成建议报告 |
| `BUMP_SELF_AUDIT_ONLY` | 仅自审模式完成 bump | Channel C 外部模型均不可用，fallback 到自审 | 降级置信度标签（"高"→"中"），标记 `last_bump_self_audited: true` |
| `BUMP_ANCHOR_DRIFT` | 评分锚点漂移 | bump 前后 composite score 均值差 > 1.0 | 警告 `anchor_drift_detected: true`，提示 rubric 修改可能改变了评分基准 |
| `BUMP_CONSISTENCY_BIAS` | 一致性偏差 | bump 后所有维度评分系统性偏移 ≥ 0.5 | 警告 `consistency_bias_detected: true`，要求审查权重调整是否存在方向性偏差 |

## 反例黑名单

> 以下行为在 bump 中**严格禁止**，任何一条触发即标记为 `⚠️ BLACKLIST_VIOLATION`。

1. **禁止跳过全量重打**：不得以"样本太多"为由只对部分样本重打，必须对校准池中所有有实绩数据的样本执行 full re-score
2. **禁止选择性验证**：不得只展示一致样本而隐藏不一致样本，所有样本的新旧排名对比必须完整呈现
3. **禁止降低验证门槛**：不得因"这次改动很小"而跳过验证步骤或降低一致率阈值，验证条件是硬性门槛
4. **禁止无观察升级**：不得在没有待验证观察的情况下凭空新增维度或调整权重，每次 bump 必须有观察作为依据
5. **禁止删除未吸收观察**：bump 未通过时不得删除任何待验证观察，观察只能在被吸收后删除
6. **禁止忽略争议维度**：极差 > 2 的争议维度必须标记，不得在未处理争议的情况下通过 bump
7. **禁止单样本驱动权重**：不得基于单个样本的偏差调整维度权重，权重调整必须有 ≥ 3 个样本的支撑
8. **禁止跳过健康度检查**：不得跳过校准池健康度摘要，即使样本分布不均也必须展示并标注风险
