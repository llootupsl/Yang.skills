# yang-graphic · 图文内容生产

## ⚡ 紧凑核心规则

**搜索意图图文**：Channel E发现的内容空白（搜索结果无图文内容）→ 优先做图文而非视频，因为图文在搜索引擎中的排名优势更大。小红书/知乎图文尤其适合搜索意图选题。

> **定位**：抖音/快手是"视频闭环"，本 skill 补齐**图文闭环**——小红书、知乎、微信公众号。
> 图文与视频共用同一套知识库与人设，只是"落地形态"不同。
>
> **依赖**：`adapters/graphic-suite/`（渲染器）、`knowledge/`（配色/钩子/标题规则）、`.yang-state.json`（人设/rubric）
>
> **产出**：小红书 → 图卡 PNG（封面+内容卡）；知乎 → 粘贴友好语义 HTML；公众号 → 内联样式 HTML

---

## 何时触发

- "把这个选题做成小红书图文 / 图卡 / 笔记"
- "写一篇知乎回答 / 专栏文章"
- "排版成公众号推文"
- "给这段文案配封面 / 做首图"

> 与 `yang-seed`/`yang-score` 的关系：图文同样先经过"选题→评分"。本 skill 负责**评分通过后的图文落地**。若用户直接要图文，可内联做一次轻量选题与标题打磨，再渲染。

## 前置检查

读取 `.yang-state.json`：取人设（口吻、人群印记、超级符号/配色倾向）、垂直领域、rubric 主题标签。
- 若不存在 → 提示先 `yang-init`（但仍可用默认主题渲染，不阻塞）。
- 若内容引用了热点 → 适用**时效锁**（`shared-protocols/freshness-protocol.md`）：以运行此刻为锚，过期热点不进图文。

## 知识库驱动的图文规则（核心，不可跳过）

图文不是"把字摆好看"，而是把知识库的钩子/情绪/视听语言落到版面上。

### 小红书（视觉优先 · 速判性最强）
- **首图 = 人群印记 + 速判性**（安先生 §1.1 / 附录R 信息特性）：封面 1.5 秒内要让目标人群"认出这是给我的"。标题里放**人群词 + 利益点/数字 + 反差**。
  - 例：「月薪5k也能存下20万」＞「我的存钱心得」。
- **标题钩子**：套用 shekong 开篇 13 种文案钩子 + xuehui「四维度让标题更有吸引力」（数字/反差/悬念/与我相关）。
- **配色 = 情绪**（安先生 附录P 视听语言：色相/明度/饱和度、影调）：按选题情绪选主题——
  | 选题情绪 | 推荐主题 |
  |---|---|
  | 温暖/治愈/生活 | `cream` / `sunset` |
  | 干货/理性/职场 | `mono` |
  | 健康/成长/自然 | `fresh` |
  | 高级/夜感/情绪 | `dark` |
- **构图**（附录P 构图：视觉重量/张力/留白）：封面大标题占视觉重心，副标题让位；内容卡一卡一要点，**宁少勿挤**（呼吸感）。
- **切片性**（附录R）：每张内容卡用"小标题▍+ 要点"制造"还有下一条"的翻页欲。

### 知乎（深度优先 · 结构清晰）
- 观点型用 xuehui「观点型脚本」结构：钩子结论先行 → 论据（六种论据类型）→ 升华。
- 知识型用 shekong「教知识」三子结构（案例引入/痛点/推荐）+ 获得感三要素。
- 排版交给知乎自身样式，重点是**逻辑分层**（h2 分节、列表化论据、引用做强调）。

### 公众号（图文混排 · 样式需内联）
- 开头 100 字内完成钩子（安先生：选题决定上限）。
- 用 h2 带左竖条分节、引用块做金句、列表化要点——所有样式**内联**（公众号会剥离 `<style>`）。
- 文末可挂行动引导（关注/合集），但不喧宾夺主。

## 工作流

### Step 1：确定平台与情绪 → 选主题

> 🔍 **检查点 CP-1**：`--platform` 已解析或从语义推断，情绪主题已匹配

解析 `--platform`（xhs/zhihu/wechat）；无则按用户语义判断。再按选题情绪选 `--theme`（见上表）。

### Step 2：生成/打磨内容（知识库驱动）

> 🔍 **检查点 CP-2**：标题候选 ≥3 个且含人群印记+钩子要素，内容要点无空缺

- 小红书：产出封面标题（人群印记+钩子）、副标题、3–6 张内容卡要点、footer。
- 知乎/公众号：产出 Markdown 正文（结论先行、论据分层、金句引用）。
- 标题候选 ≥3 个，按 xuehui 四维度自评后选最优。

### Step 3：渲染

> 🔍 **检查点 CP-3**：渲染脚本存在且输出目录可写

**小红书图卡**（HTML→PNG，自动分页、多主题；无 Chromium 时降级输出 HTML）：
```bash
# 先写好 card.json：{title, subtitle, theme, size, badge, cards:[{heading,body}], footer}
python adapters/graphic-suite/render_card.py --in card.json --out graphic_out/xhs/
# 或快速直传
python adapters/graphic-suite/render_card.py --title "<封面标题>" --subtitle "<钩子>" \
  --body "第一步...\n第二步..." --theme cream --badge 干货 --footer "@账号 关注不迷路" --out graphic_out/xhs/
```
- 尺寸：`--size 3:4`(1080×1440，默认) 或 `1:1`。正文超长自动拆多卡。
- 输出：`01_cover.png` + `NN_card.png` + `manifest.json`（同时落 HTML 兜底）。

**知乎语义 HTML**（粘贴进知乎编辑器保留结构；表格自动转列表、LaTeX 保留）：
```bash
python adapters/graphic-suite/zhihu_format.py --in answer.md --out graphic_out/zhihu/answer.html
```

**公众号内联 HTML**（全选复制粘贴进公众号即保留排版）：
```bash
python adapters/graphic-suite/wechat_md.py --in article.md --theme warm --out graphic_out/wechat/article.html
```

### Step 4：交付与自检

> 🔍 **检查点 CP-4**：产物文件存在且可访问（PNG/HTML 非空）
>
> 🔍 **检查点 CP-5**：平台特定质检通过（小红书标题≤22字/知乎结论先行/公众号内联样式）

- 小红书：确认封面标题 ≤22 字、含人群印记、首图主题与情绪匹配；内容卡无溢出（已自动分页）。
- 知乎：确认结论先行、论据分层、无表格溢出。
- 公众号：确认样式为内联（粘贴后不丢格式）、开头 100 字内有钩子。
- 提示用户产物路径；图卡可直接发布，HTML 可复制粘贴。

## 失败与降级

| 情况 | 处理 |
|---|---|
| 无 Chromium（Playwright 未装） | render_card 自动输出每页 HTML + 提示 `playwright install chromium`；用户可浏览器另存为图 |
| 正文过长 | 自动分页为多张内容卡，无需手动切 |
| 公众号粘贴后掉格式 | 确认用的是 wechat_md.py 产物（内联样式），不要粘 Markdown 源码 |
| 中文字体显示异常 | 渲染机需有任一中文字体（PingFang/思源/雅黑）；脚本已用系统字体栈兜底 |

---

## 失败模式编码

| 编码 | 含义 | 触发条件 | 处置 |
|------|------|----------|------|
| `GR-E01` | 渲染脚本缺失 | `render_card.py`/`zhihu_format.py`/`wechat_md.py` 不存在 | 提示 `yang-init`，终止 |
| `GR-E02` | Chromium 未安装 | Playwright chromium 不可用 | 降级输出 HTML，提示安装 |
| `GR-E03` | 主题不匹配 | 选题情绪无法映射到已有主题 | 使用 `cream` 兜底，标注"默认主题" |
| `GR-E04` | 内容溢出 | 单卡文字超长导致排版溢出 | 自动分页，标注"已拆分" |
| `GR-E05` | 中文字体缺失 | 系统无中文字体 | 使用系统字体栈兜底，警告可能显示异常 |
| `GR-E06` | 时效锁拦截 | 引用的热点已过期 | 剔除过期热点内容，标注"已移除过期素材" |

## 反例黑名单

1. **禁止跳过知识库驱动**：图文配色/钩子/标题必须由知识库规则驱动，不得凭感觉随意配色
2. **禁止封面标题超 22 字**：小红书封面标题 ≤22 字是硬限制，超出必须精简
3. **禁止使用外部样式表**：公众号必须内联样式，`<style>` 标签会被平台剥离
4. **禁止忽略人群印记**：小红书首图必须含人群词+利益点，不得用泛泛标题
5. **禁止正文不分页**：小红书内容卡一卡一要点，超长必须自动拆分，不得挤在一卡
6. **禁止知乎用表格**：知乎编辑器表格兼容性差，必须转为列表
7. **禁止跳过时效锁**：引用热点时必须校验时效，过期热点不得进入图文
8. **禁止渲染失败静默**：渲染失败必须告知用户并降级输出 HTML，不得返回空结果

## 量化标准：图文钩子命中率

图文内容的有效性由**钩子命中率**衡量：

- **钩子命中率** = 包含知识库钩子要素（人群印记/反差/数字/悬念）的标题数 / 标题总数
- **合格线**：命中率 ≥ 80%（3 个标题中至少 2 个含钩子要素）
- **优秀线**：命中率 = 100%
- 小红书首图速判性：封面标题须在 1.5 秒内可读（字数 ≤22 + 无生僻词）
- 知乎/公众号开头钩子：前 100 字内必须完成钩子（结论先行/悬念/反差）
- 命中率 < 80% 时，必须重新打磨标题后再渲染

## 图文钩子设计规范

图文内容的钩子与视频钩子逻辑不同——图文没有"前3秒"，替代的是"首屏速判"。封面标题是图文最核心的钩子载体。

### 封面标题四维度评分

每个封面标题候选须按以下 4 个维度评分（每维度 1-5 分），总分 ≥ 14 分方可使用：

| 维度 | 定义 | 5分标准 | 1分标准 | 权重 |
|------|------|---------|---------|------|
| **人群印记** | 目标人群能否在 1.5 秒内"认出这是给我的" | 含精准人群词 + 场景词（如"月薪5k的打工人"） | 无人群指向，任何人看都无感 | 30% |
| **速判性** | 读者能否在 1.5 秒内理解标题核心信息 | 信息结构清晰，一眼抓到重点，无歧义 | 信息模糊，需要思考才能理解 | 25% |
| **情绪触发** | 标题能否引发情绪反应（好奇/共鸣/紧迫/反差） | 强情绪词 + 具体场景锚点，读者有身体反应 | 平铺直叙，无情绪波动 | 25% |
| **信息增量** | 标题是否承诺了读者不知道的新信息 | 含反常识/新数据/新视角，读者"原来如此" | 读者已知信息，无新知承诺 | 20% |

### 评分等级

| 总分 | 等级 | 处理 |
|------|------|------|
| 18-20 | 🟢 优秀 | 直接使用 |
| 14-17 | 🟡 合格 | 可用，建议微调提升弱维度 |
| 10-13 | 🟠 待优化 | 必须修改至少 2 个维度后再评分 |
| < 10 | 🔴 不合格 | 重新设计标题 |

### 标题设计自检清单

每个标题候选须通过以下快速自检（任一否决则重写）：

1. ✅/❌ 删掉所有形容词后，核心信息是否仍然成立？（否→信息空洞）
2. ✅/❌ 换一个目标人群词，标题是否失效？（否→人群印记不够精准）
3. ✅/❌ 读者看完标题后是否有"然后呢？"的冲动？（否→缺乏信息缺口）
4. ✅/❌ 标题是否 ≤ 22 字（小红书）/ ≤ 30 字（知乎/公众号）？（否→需精简）

## 多平台适配差异清单

同一内容在不同平台发布时，格式限制和最佳实践差异显著。以下为三平台核心差异对照：

| 差异项 | 小红书 | 知乎 | 公众号 |
|--------|--------|------|--------|
| **内容形态** | 图卡序列（封面+内容卡） | 长文回答/专栏文章 | 长文推文 |
| **封面标题字数** | ≤ 22 字（硬限制） | 无硬限制，但前 30 字决定点击 | 无硬限制，但推送标题 ≤ 64 字 |
| **首屏钩子载体** | 封面图 + 标题（1.5 秒速判） | 回答前 3 行（折叠前） | 标题 + 摘要（推送通知中） |
| **排版方式** | HTML→PNG 渲染，视觉完全可控 | 粘贴语义 HTML，平台控制样式 | 内联样式 HTML，复制粘贴保留排版 |
| **表格支持** | 不适用（图卡中避免表格） | 兼容性差，必须转列表 | 兼容性中等，简单表格可用 |
| **图片限制** | 封面 3:4 或 1:1，内容卡 3:4 | 可内联图片，无严格尺寸 | 可内联图片，宽度自适应 |
| **代码/LaTeX** | 不适用（图卡中用截图） | LaTeX 支持，代码块支持 | 不支持 LaTeX，代码需截图 |
| **链接规则** | 正文中链接不可点击 | 链接可点击 | 原文链接可点击，其他受限 |
| **互动引导** | 评论区置顶 / 合集标签 | 评论区 / 想法 | 文末关注引导 / 阅读原文链接 |
| **最佳发布时间** | 12:00-14:00 / 20:00-22:00 | 工作日 9:00-11:00 / 20:00-22:00 | 7:00-9:00 / 20:00-22:00 |
| **内容长度偏好** | 3-6 张图卡，每卡 1 要点 | 1500-3000 字，结构化长文 | 1500-2500 字，段落短+金句多 |
| **SEO/搜索权重** | 标题关键词 + 标签 | 标题 + 首段关键词 + 话题标签 | 标题 + 摘要关键词 |
| **样式风险** | 渲染失败→降级 HTML | 粘贴丢格式→用 zhihu_format.py | `<style>` 被剥离→必须内联 |

### 跨平台适配流程

1. **内容层统一**：同一选题的核心论点/要点/金句在三个平台保持一致
2. **结构层适配**：小红书→图卡切片；知乎→h2 分节+列表化；公众号→短段落+金句引用
3. **钩子层适配**：小红书→封面标题钩子；知乎→前 3 行结论先行；公众号→推送标题+首段钩子
4. **样式层适配**：各平台用对应渲染器输出，不混用

## 图文产出质量自检清单

图文内容渲染完成后，发布前必须逐项检查以下 10 项条件。任一条件不满足须修复后再发布：

| # | 检查项 | 通过条件 | 不通过时的处理 |
|---|--------|---------|--------------|
| 1 | **封面标题含人群印记** | 标题中有明确的目标人群词（如"打工人""宝妈""大学生"） | 重写标题，加入人群词 |
| 2 | **封面标题 ≤ 22 字**（小红书） | 字数统计 ≤ 22（含标点） | 精简标题 |
| 3 | **钩子命中率 ≥ 80%** | 标题候选中 ≥ 80% 包含钩子要素（人群印记/反差/数字/悬念） | 重新打磨标题 |
| 4 | **首图/首屏速判性** | 1.5 秒内可读核心信息，无生僻词，无信息过载 | 简化首图文字，突出核心 |
| 5 | **内容卡一卡一要点** | 每张内容卡只有 1 个核心要点，无堆砌 | 拆分为多卡 |
| 6 | **配色与情绪匹配** | 主题色与选题情绪一致（温暖→cream/sunset，干货→mono 等） | 切换主题 |
| 7 | **内联样式完整**（公众号） | 所有样式为内联，无 `<style>` 标签 | 用 wechat_md.py 重新渲染 |
| 8 | **结论先行**（知乎） | 回答前 3 行包含核心结论/观点 | 调整结构，结论前置 |
| 9 | **时效锁校验** | 引用的热点/数据未过期（以运行时刻为锚） | 剔除过期内容 |
| 10 | **渲染产物完整** | PNG 非空 / HTML 可打开 / 无截断 | 重新渲染 |

### 自检输出格式

```
✅ 图文产出质量自检 · [平台] · [选题]

  1. 人群印记: ✅ "打工人" 
  2. 标题字数: ✅ 18字
  3. 钩子命中率: ✅ 3/3 (100%)
  4. 首屏速判: ✅ 核心信息1.5s可读
  5. 一卡一要点: ✅ 5卡5要点
  6. 配色匹配: ✅ cream(温暖)匹配治愈选题
  7. 内联样式: ✅ (公众号)
  8. 结论先行: ✅ (知乎)
  9. 时效锁: ✅ 无热点引用
  10. 渲染完整: ✅ PNG×6 + HTML×1

结果: 10/10 通过，可发布
```
