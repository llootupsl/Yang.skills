# yang-seed · Cold-start 选题启动器

## ⚡ 紧凑核心规则

**种子词提取**：从rubric_notes.md的评分维度名称+用户垂直领域标签+persona.md的关键词中提取3-5个具体种子词（如"职场沟通"→["职场沟通技巧","职场冲突处理","向上管理"]）。禁止用泛词（如"AI""科技""生活"）作为唯一种子词。

**去重规则**：标题关键词重叠>80%或核心论点相同→合并（多源验证升级优先级C→B→A）或保留信息密度更高者。同角度不同受众→均保留。五通道全部降级→报错SEED_ALL_CHANNELS_DEGRADED不输出空推荐。

**分级标准**：🅰A=Rubric高分+对标验证+有时效性（策略变化驱动自动A级）| 🅱B=任一通道强信号 | 🅲C=信号弱备选。热点型72h衰减 | 竞品型30天 | Rubric型90天 | 评论型60天 | 搜索意图型180天。

> **前置条件**：项目已 init
>
> **产生**：candidates.md 更新（新增候选选题）
>
> **依赖**：yang-trends（热点通道）；yang-benchmark 高赞评论挖掘（Channel D 金句来源）

## 工作流

### 五通道冷启动

```
┌──────────────────────────────────────────────────┐
│               Cold-Start Seed Generator            │
├──────────────────────────────────────────────────┤
│                                                    │
│  Channel A: Rubric-Guided    ← rubric_notes.md     │
│  Channel B: Benchmark-Lift   ← benchmark.md        │
│  Channel C: Trend-Surf       ← adapters/trend-*    │
│  Channel D: Comment-Gold     ← 高赞评论金句         │
│  Channel E: Search-Intent    ← adapters/search-intent/  │
│   (A:Rubric逆推 / B:竞品库 / C:热点 / D:高赞评论 / E:搜索意图)   │
│                                                    │
│         ▼  ▼  ▼  ▼  ▼                              │
│    candidates.md（分级候选池）                      │
│                                                    │
└──────────────────────────────────────────────────┘
```

### Channel A: Rubric 导向选题

从你的评分规则反推高分选题：

> **检查点 CP-A1**：rubric_notes.md 存在且非空 → 通过；否则触发 `SEED_NO_RUBRIC`，Channel A 降级为 B-三有框架。

1. 读出 `rubric_notes.md` 中的评分维度
2. 对每个维度逆向推理：「什么样的选题能在这一维拿高分？」
3. 生成 3-5 个 Rubric 驱动的选题候选项

> **检查点 CP-A2**：生成选题覆盖 rubric 中至少 3 个评分维度 → 通过；否则补充遗漏维度的逆推选题。

### Channel B: 对标拉升选题（竞品数据库驱动）

从竞品数据库中的历史分析和策略变化中派生选题：

> **检查点 CP-B1**：竞品数据库有活跃竞品 或 benchmark.md 非空 → 通过；否则触发 `SEED_NO_COMPETITORS`，Channel B 降级跳过。

> **Channel B 数据流向**：`yang-learn-from` 同时写入 `benchmark.md` + 竞品数据库（project_data.db）。`yang-seed` Channel B 优先读取竞品数据库，若数据库为空或无活跃竞品 → fallback 到 `benchmark.md` 手动笔记。

#### Step 1: 查询竞品数据库
```python
from adapters.data_pipeline import db
competitors = db.get_all_competitors(is_active=True)
```
获取所有活跃竞品。若 `len(competitors) == 0`：
→ 降级到旧版 `benchmark.md` 手动笔记（向后兼容）
→ 输出提示：
```
⚠️ 尚未发现对标账号。
建议先运行 yang-competitor-search "你的赛道关键词" 来自动发现竞品。
在此之前，Channel B 将使用 benchmark.md 中的手动笔记（若有）。
```

#### Step 2: 查询竞品数据与策略变化
对每个竞品：
- `db.get_competitor_snapshots(competitor_id, limit=1)` → 最近数据
- `db.get_competitor_strategy_changes(competitor_id)` → 最近策略变化
- 搜索 `benchmarks/` 目录下的对标报告文件

#### Step 3: 检查数据新鲜度（时效锁）
依据 `shared-protocols/freshness-protocol.md` 对竞品数据做时效判定，锚点为运行此刻、绝不写死日期：
- 竞品快照 / 对标报告按发布时间打标 `fresh`(≤90天) / `aging`(90–365天) / `stale`(>365天) / `unknown`。
- 若某竞品最新数据已 `aging`：选题可用，但须标注"基于偏旧数据"；若 `stale` 或超过 30 天无新对标报告：
  → 提示用户：`竞品「{name}」最新数据已偏旧/超 30 天未分析，建议运行 yang-benchmark 获取最新数据`
  → 可自动触发 pipeline（需用户确认）
- 代码层判定：`from adapters._common import freshness`，用 `freshness.freshness_label(publish_date)` / `freshness.sort_by_recency(...)`。
- **原则**：旧时间的爆款规律可能已失效，stale 数据默认不作为"当下选题信号"，仅作趋势对照。

> **检查点 CP-B2**：所有竞品数据已过时效锁校验 → 通过；否则触发 `SEED_STALE_DATA`，标注偏旧数据并提示刷新。

#### Step 4: 策略变化驱动的优先选题
若某竞品最近检测到策略变化（如 hook_type_shift）：
→ 该变化相关的选题自动标记为 🅰 高优先
→ 选题描述格式：`趋势捕捉：竞品「X」从{旧策略}转向{新策略}，建议尽快跟进或差异化反制`

#### Step 5: 四源综合生成选题
基于以下四个数据源综合推导选题：
a. **竞品最近视频选题方向** × 你的差异化角度 → 对标派生
b. **赛道格局中的蓝海信号**（若 landscape_snapshots 表有数据）→ 空缺赛道切入
c. **竞品策略变化趋势** → 趋势捕捉 / 反制策略
d. **跨竞品共性模式** × 你的执行可行性 → 已验证模式复用

#### Step 6: 生成选题
生成 **5-8 个**对标派生选题（竞品数据库驱动）。

#### Step 7: 选题标注
每个选题包含 4 个标注字段：
| 字段 | 说明 | 示例 |
|------|------|------|
| 灵感来源 | 竞品名 + 具体视频/数据点 | "竞品「老王说AI」○三分钟讲清楚大模型" |
| 差异化角度 | 你和他的不同之处 | "用更通俗的比喻代替技术术语，面向新手" |
| 预计难度 | 低/中/高 | "中" |
| 时效性 | 立即/本周/本月 | "立即" |

### Channel C: 热点冲浪选题

从实时热点中捕捉选题机会：

> **检查点 CP-C1**：adapters/trend-* 存在且可调用 → 通过；否则 Channel C 降级跳过。

1. 调用 `/yang-trends` 获取当前热点
2. 筛选与你的垂直领域相关的热点
3. 对每个热点："你的切入角度" 应该是什么？
4. 生成 3-5 个热点派生的选题候选项

> **检查点 CP-C2**：每个热点选题已说明与自身垂直领域的关联角度 → 通过；否则丢弃无关联的"硬蹭"选题。

### Channel D: 高赞评论金句选题

> **核心逻辑**：一条爆款视频下的高赞评论，是已经被几千几万人用点赞投过票的"普世共鸣"。把这些金句提炼成标题/选题，等于直接复用被验证过的情绪与表达——这正是 **A-选题** 的现成素材，也可直接做 **黄-开篇** 的文案钩子。

**数据来源**：对标视频/热点视频的评论区（由 yang-benchmark 管线中的高赞评论挖掘步骤产出）。

> **检查点 CP-D1**：存在可用评论数据（comments.json 非空）且至少 1 条近期爆款视频 → 通过；否则 Channel D 降级跳过。

**流程**：
1. 选定 1–N 条**近期**爆款视频（必须先过时效锁：`stale` 视频的评论默认不作为当下选题来源，见 `freshness-protocol.md`）。
2. 运行评论挖掘（详见 yang-benchmark「高赞评论 → 选题/标题」一节）：
   ```bash
   python adapters/benchmark-analysis/mine_comments.py <comments.json> --top 30 --out comment_gold.json
   ```
   产出按点赞排序、剔除水军/广告/无信息量后的金句，并给出 `title_candidates` / `topic_candidates` / `emotion_signals`。
3. 把高赞金句 × 你的垂直角度 → 生成 3–5 个选题候选项；金句本身可直接做候选标题或开篇钩子。
4. 入池前对每条素材打时效标，`stale` 不默认入池。

> **检查点 CP-D2**：评论筛选已完成（水军/广告/无信息量评论已剔除）→ 通过；否则重新执行筛选流程。

**标注**：来源标 `Channel D（高赞评论金句 · 视频「X」· 赞 N）`，并注明该视频时效档。

### Channel E: 搜索意图选题

> **核心逻辑**：热榜告诉你"什么已经在火"，搜索意图告诉你"什么将要火/什么有人搜但没人做好"。搜索意图是**低竞争、长窗口**的选题信号——比热榜更适合中小账号切入。

**数据来源**：`adapters/search-intent/search_intent.py`（零API Key，公开端点）。

> **检查点 CP-E1**：adapters/search-intent/ 存在且可调用 → 通过；否则 Channel E 降级跳过。

**六种搜索意图信号**：

| 信号类型 | 来源 | 选题价值 | 时效性 |
|---------|------|---------|--------|
| 搜索建议 | 百度/Google/必应自动补全 | 发现用户真实搜索词 | 中（持续需求） |
| 相关搜索 | 百度/Google搜索页底部 | 发现关联需求 | 中 |
| 问题型需求 | 知乎问题/百度知道 | 发现"有人问但没人答好"的空白 | 高（精准需求） |
| 长尾关键词 | 种子词多级扩展 | 发现低竞争高需求词 | 高（蓝海信号） |
| 趋势查询 | Google Trends上升查询 | 发现"正在升温"的话题 | 高（早期信号） |
| 内容空白检测 | 搜索结果质量分析 | 发现"有人搜但内容差"的机会 | 最高（直接可切入） |

**流程**：
1. 从 `rubric_notes.md` 提取用户垂直领域的核心关键词（3-5个种子词）
2. 调用搜索意图适配器：
   ```bash
   python adapters/search-intent/search_intent.py --keyword "种子词" --sources baidu_suggest,baidu_related,google_suggest,zhihu_question,bing_suggest --limit 20 --out candidates/search_intent.json
   ```
3. 对返回的搜索意图信号做相关性筛选（同 Channel C 的相关性评分标准）
4. 对内容空白检测的结果（content_gap 类型）自动标记为 🅰 高优先
5. 对问题型需求（question 类型）标注"需求验证：X人关注/Y个回答"
6. 生成长尾关键词选题 3-5 个

> **检查点 CP-E2**：每个搜索意图选题已说明信号来源和需求验证数据 → 通过；否则丢弃无验证数据的选题。

**标注**：来源标 `Channel E（搜索意图 · {信号类型} · 种子词「X」）`，并注明搜索量估算/关注数。

**Channel E 与其他通道的协同**：
- Channel E + Channel C 重叠 → 搜索意图验证了热点持续性，升级为 🅰
- Channel E 发现的内容空白 + Channel B 竞品验证 → 确认可切入，升级为 🅰
- Channel E 独有的长尾词 → 默认 🅱，除非内容空白评分极高

#### 评论筛选标准

**什么算"高赞"评论**：
- **绝对阈值**：评论点赞数 ≥ 视频总点赞数的 0.5%，且 ≥ 100 赞（取两者较高值）。
- **相对阈值**：评论点赞数排名进入该视频评论区 Top 30。
- 两条阈值满足其一即可判定为"高赞"。

**水军评论剔除规则**：
- **账号特征**：评论者账号为纯数字昵称、注册时间 < 30 天、历史评论全为相似文案 → 标记为疑似水军。
- **内容特征**：评论内容为纯表情/纯"666"类无信息量回复、含明显推广链接或二维码、与视频内容完全无关的通用夸赞 → 剔除。
- **行为特征**：同一账号在同一视频下评论 ≥ 3 条且内容高度雷同 → 剔除该账号所有评论。
- **批量特征**：多条评论发布时间集中在 1 分钟内且措辞高度相似 → 整批标记为疑似水军，人工复核或直接剔除。

**评论时效性判定规则**：
- 评论发布时间距运行此刻 ≤ 30 天 → `fresh`，优先使用。
- 评论发布时间距运行此刻 30–90 天 → `aging`，可用但标注"评论偏旧"。
- 评论发布时间距运行此刻 > 90 天 → `stale`，不作为当下选题信号来源。
- **例外**：若评论所在视频仍处于持续增长期（近 7 天播放量增长 > 5%），则该视频下的评论时效可提升一档（stale → aging，aging → fresh）。

### 五通道优先级与组合策略

五通道并非平等权重，根据不同场景有明确的优先级和组合策略：

**场景优先级矩阵**：

| 场景 | 优先通道 | 次优先通道 | 原因 |
|------|---------|-----------|------|
| 冷启动（无历史数据） | Channel A（Rubric导向） | Channel C（热点冲浪） | 无竞品数据时，Rubric逆推是最可靠的选题来源 |
| 有对标账号数据 | Channel B（对标拉升） | Channel A（Rubric导向） | 竞品验证过的选题成功率最高 |
| 热点窗口期（< 48h） | Channel C（热点冲浪） | Channel D（高赞评论金句） | 时效性优先，热点不等人 |
| 账号成熟期（> 50条内容） | Channel D（高赞评论金句） | Channel B（对标拉升） | 高赞评论直接反映受众需求 |
| 人设驱动型账号 | Channel A（Rubric导向） | Channel D（高赞评论金句） | 确保选题与人设评分维度对齐 |
| 搜索意图驱动 | Channel E（搜索意图） | Channel A（Rubric导向） | 搜索意图发现低竞争高需求选题，Rubric确保选题质量 |
| 蓝海切入 | Channel E（搜索意图） | Channel B（对标拉升） | 搜索意图发现内容空白，竞品验证确认可切入 |

**多通道选题重叠时的去重与合并规则**：

当多个通道产出相似选题时，按以下规则处理：

1. **重叠检测**：若两个选题的核心角度相同（即使标题措辞不同），视为重叠选题
2. **合并策略**：
   - 同角度多来源 → 合并为一条，标注所有来源通道（如 `来源: Channel A + Channel B`），多源验证的选题自动升级优先级（C→B，B→A）
   - 同角度不同切入点 → 保留两条，但标注为"姊妹选题"，建议用户二选一或拆分为系列内容
3. **冲突策略**：
   - Channel B（竞品验证）与 Channel C（热点）选题冲突时 → 优先 Channel B（验证过的选题更可靠）
   - Channel A（Rubric导向）与 Channel D（评论金句）选题冲突时 → 优先 Channel D（受众需求更直接）

### 自动优先级判断

当用户未指定场景时，系统根据当前状态自动判断优先通道：

1. 读取 `.yang-state.json` 的 `total_predictions`：
   - 0（冷启动）→ 优先 Channel A + Channel E
   - 1-5（初期）→ 优先 Channel B + Channel E
   - 6+（成熟期）→ 优先 Channel D + Channel E

2. 读取当前时间：
   - 工作日 9-12点 → Channel C 权重+20%（早高峰热点窗口）
   - 周末 → Channel E 权重+20%（长尾选题更适合周末深度内容）

3. 读取 buffer 颜色：
   - 🔴 → 只推 Channel A + Channel E（最稳+最长尾）
   - 🟢 → 全通道开放

### 选题去重规则

多通道产出的候选选题入池前，必须经过去重筛选：

**去重判定标准**：

| 判定维度 | 规则 | 示例 |
|---------|------|------|
| **标题相似度** | 核心关键词重叠 > 80% 视为重复 | "AI工具推荐" vs "推荐几个AI工具" → 重复 |
| **角度相似度** | 核心论点/切入角度相同视为重复，即使标题不同 | "为什么AI不会取代你" vs "AI取代不了人类的3个原因" → 重复 |
| **同角度不同表达** | 保留信息密度更高、更具体的那个 | "AI工具推荐" vs "5个免费AI工具帮你省3小时" → 保留后者 |
| **同角度不同受众** | 若明确面向不同受众群，保留两条 | "AI工具·新手入门" vs "AI工具·进阶玩家" → 均保留 |

**去重流程**：
1. 所有通道选题汇总后，先按标题相似度初筛（关键词提取 + 重叠率计算）
2. 初筛通过的选题，再按角度相似度精筛（核心论点比对）
3. 精筛后保留的选题，标注去重结果（保留/合并/丢弃 + 原因）
4. Channel E 的长尾词与 Channel C 热点重叠 → 保留 Channel E 版本（有搜索意图验证）
5. Channel E 的问题型选题与 Channel D 评论金句重叠 → 合并，标注双来源

**去重输出格式**：
```
去重结果：原始 X 条 → 去重后 Y 条
- 保留：Z 条（独立选题）
- 合并：M 条（多源验证，来源升级）
- 丢弃：N 条（与更高质量选题重复）
```

### 选题新鲜度衰减

`candidates.md` 中的选题具有时效性，随时间推移价值衰减：

**衰减规则**：

| 选题类型 | 有效期 | 衰减行为 | 过期处理 |
|---------|--------|---------|---------|
| **热点驱动型**（Channel C） | 72 小时 | 24h 后降为 B 级，48h 后降为 C 级 | 72h 后标记为 `⏰ 过期`，移入归档区 |
| **竞品策略型**（Channel B） | 30 天 | 15 天后降为 B 级 | 30 天后标记为 `⏰ 过期`，除非竞品策略仍在持续 |
| **Rubric导向型**（Channel A） | 90 天 | 60 天后降为 B 级 | 90 天后重新评估，若 rubric 规则未变可延期 |
| **评论金句型**（Channel D） | 60 天 | 30 天后降为 B 级 | 60 天后标记为 `⏰ 过期`，除非原视频仍在增长期 |
| **搜索意图型**（Channel E） | 180 天 | 90 天后降为 B 级 | 180 天后重新评估 |

**衰减标注方式**：
- 在 `candidates.md` 中每个选题后追加 `[新鲜度: fresh/aging/stale]` 标签
- `fresh`：在有效期内，优先级不变
- `aging`：已过半衰期，优先级降一级
- `stale`：已过期，移入归档区或删除

**自动衰减触发**：
- 每次 yang-seed 运行时，自动扫描 `candidates.md` 中已有选题的新鲜度
- 对比选题的 `生成时间` 与当前时间，按上表规则更新标签
- 输出衰减报告：`本次扫描：X 条 fresh，Y 条 aging，Z 条 stale（已归档）`

> **例外**：若某选题在 `aging` 或 `stale` 状态下被用户明确选中并开始写稿，则该选题重新标记为 `active`，不受衰减规则限制。

## 失败模式编码

| 编码 | 含义 | 触发条件 | 恢复动作 |
|------|------|----------|----------|
| `SEED_NO_RUBRIC` | rubric 缺失 | `rubric_notes.md` 不存在或为空 | 提示用户初始化评分规则；Channel A 降级为 B-三有框架 |
| `SEED_ALL_CHANNELS_DEGRADED` | 五通道全部降级 | Channel A/B/C/D/E 均不可用 | 报错并提示初始化项目；不输出空候选池 |
| `SEED_STALE_DATA` | 竞品数据过期 | 竞品最新快照标记为 `stale`（>365天） | 标注"基于偏旧数据"；提示运行 yang-benchmark 刷新；stale 数据不作为当下选题信号 |
| `SEED_NO_COMPETITORS` | 无对标账号 | 竞品数据库无活跃竞品且 `benchmark.md` 为空 | 提示运行 yang-competitor-search；Channel B 降级跳过 |
| `SEED_SEARCH_INTENT_UNAVAILABLE` | 搜索意图适配器不可用 | `adapters/search-intent/` 不存在或 `search_intent.py` 不可执行 | Channel E 降级跳过；提示用户安装搜索意图适配器 |
| `SEED_NO_SEED_KEYWORDS` | 无法从rubric提取种子关键词 | `rubric_notes.md` 中无明确的垂直领域关键词 | Channel E 降级跳过；提示用户完善rubric中的垂直领域关键词 |

**编码使用规范**：
- 在输出日志和 candidates.md 中，每个降级/错误事件必须附带对应编码，便于事后追溯。
- 多个编码可同时触发（如 `SEED_NO_RUBRIC` + `SEED_NO_COMPETITORS`），按触发顺序列出。

## 反例黑名单

以下行为模式在选题生成过程中**严格禁止**，出现即判定为无效输出：

1. **凭空捏造选题**：无任何数据来源支撑（无 rubric 逆推、无竞品对标、无热点依据、无评论金句），纯靠"脑补"生成的选题 → 直接丢弃。
2. **忽略时效锁**：将 `stale` 数据作为当下选题信号，未标注数据时效 → 必须标注时效档，stale 不默认入池。
3. **同质化堆叠**：同一通道生成 3 个以上高度相似的选题（仅换措辞，核心角度相同）→ 去重后仅保留最优 1 条。
4. **跨赛道硬蹭**：热点与自身垂直领域无关联，强行"蹭热点"生成选题 → 必须说明切入角度的合理性，否则丢弃。
5. **水军评论入池**：将明显的水军/广告/刷量评论作为金句来源 → 必须经过评论筛选流程剔除。
6. **Rubric 维度遗漏**：Channel A 选题未覆盖 rubric 中至少 3 个评分维度 → 补充遗漏维度的逆推选题。
7. **竞品数据未校验**：Channel B 直接使用竞品数据但未执行时效锁判定 → 必须先过 freshness 校验再生成选题。
8. **候选池为空仍输出推荐**：五通道均降级后仍输出"推荐选题" → 必须报错 `SEED_ALL_CHANNELS_DEGRADED`，不输出空推荐。
9. **金句脱离原语境**：高赞评论金句脱离原视频语境单独使用，导致歧义或断章取义 → 必须标注来源视频及上下文。
10. **忽略降级标注**：某通道降级后，输出推荐语中未体现降级信息 → 必须在推荐语中标注"Channel X 降级"及原因。
11. **搜索意图未验证**：Channel E 选题无搜索量/关注数等验证数据 → 必须有量化验证。
12. **种子词过于宽泛**：如"AI""科技"等泛词 → 必须从rubric提取具体垂直词。
