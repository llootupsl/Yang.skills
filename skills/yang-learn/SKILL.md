## 工作流

### Phase 0: 意图确认

> 🔍 **CHECKPOINT 0**：分析来源方式（自动拉取/手动上传）已确认

> 你要分析哪个账号？需要自动拉取还是手动上传？

- **自动拉取**：提供账号主页链接或名称 → 系统自动下载视频并分析
- **手动上传**：用户自行上传视频脚本 → 系统仅做模式分析（跳过 Step 2-3 的自动拉取）

确认意图后，记录分析来源方式到本次 session 的 metadata 中。

### Step 1: 获取对标账号信息

支持两种输入方式：
- **URL**：输入对标账号主页链接 → 提取账号名称、ID
- **名称**：输入账号名称 → 搜索获取 ID

### Step 2: 拉取对标账号视频列表

提取最近 N 条视频（默认 20 条），保存元数据：标题、发布时间、播放量、点赞/评论/分享/收藏。

### Step 3: 自动转录对标视频

> 🔍 **CHECKPOINT 1**：视频列表已拉取，转录管线就绪

对每条视频执行转录管线：下载音频 → 转录 → 保存转录文本

```bash
# 使用 adapter 进行视频转录
bash adapters/benchmark-auto/run.sh --url <video-url> --output samples/<account>/<video-id>/
```

转录结果存于：`samples/<account>/<video-id>/transcript.md`

### Step 4: 提取脚本模式

> 🔍 **CHECKPOINT 2**：转录完成，进入模式提取阶段

从对标账号的高播放视频中提取共性模式：

1. **钩子模式**：前 3 秒的开场方式（"你知道吗"/"做自媒体X年的血泪经验"/反常识陈述/制造悬念/情绪爆发）
2. **节奏模式**：信息密度分布、段落长度、转折频率
3. **情绪曲线**：从起承转合分析对标账号的情绪弧线
4. **完播设计**：末尾的闭环方式（金句收尾/开放问题/行动呼吁）

输出到 `script_patterns.template.md`。

### Step 5: 更新 benchmark.md

> 🔍 **CHECKPOINT 3**：模式提取完成，benchmark.md 写入前确认

将对标账号信息写入 benchmark.md：

```markdown
## 对标账号

### <账号名>
- 平台: <platform>
- 垂直领域: <vertical>
- 粉丝数: <followers>
- 平均播放: <avg-views>
- 分析样本数: <sample-count>
- 上次更新: <date>

### 对标笔记

#### 钩子模式
1. ...

#### 结构模式
1. ...

#### 主题方向
1. ...

#### 可借鉴维度的 rubric 调整建议
1. ...
```

## 错误处理

| 场景 | 行为 |
|------|------|
| 项目未 init（rubric_notes.md 或 benchmark.md 不存在） | 提示"项目未初始化，请先运行 '初始化'" |
| 对标账号链接无效或无法访问 | 报告"无法访问对标账号"，提示检查链接或手动提供数据 |
| `adapters/benchmark-auto/run.sh` 不存在 | 警告"转录工具缺失"，提示先安装 adapter 依赖 |
| 对标账号无公开视频或视频列表为空 | 提示"该账号暂无可用视频数据"，建议更换对标账号 |

## 失败模式编码

| 编码 | 名称 | 描述 |
|------|------|------|
| `YL-E01` | 项目未初始化 | rubric_notes.md 或 benchmark.md 不存在，无法写入对标学习结果 |
| `YL-E02` | 转录管线断裂 | adapter 缺失或 whisper 未安装，视频无法转录为文本 |
| `YL-E03` | 账号不可达 | 对标账号链接无效、私密或地域限制，无法拉取视频列表 |
| `YL-E04` | 样本过少 | 可用视频 < 3 条，提取的模式不具备统计意义 |
| `YL-E05` | 模式泛化失败 | 所有视频高度同质化，无法区分出差异化模式 |
| `YL-E06` | 转录质量低下 | whisper 转录错误率过高，pattern 提取基于错误文本 |

## 反例黑名单

1. **禁止在项目未 init 时执行对标学习**——无 rubric_notes.md / benchmark.md 会导致结果无处落盘
2. **禁止跳过转录直接从标题猜模式**——标题级分析无法产出钩子/节奏/情绪曲线等深层 pattern
3. **禁止将单条视频的个性特征当作账号模式**——模式需 ≥2 条样本交叉验证
4. **禁止自动下载视频到用户设备**——与 yang-learn-from 一致，避免 TOS + 反爬风险
5. **禁止在转录失败时静默跳过**——必须报告失败条目及原因，让用户决定是否重试
6. **禁止将对标模式直接写入用户 rubric 权重**——对标模式是参考信号，需经 yang-bump 正式校准
7. **禁止覆盖已有 benchmark 数据**——追加而非替换，保留历史对标记录
8. **禁止在 adapter 缺失时假装自动拉取**——必须如实告知工具状态，引导手动上传

**搜索意图学习**：学习对标账号时，同时检查该账号在搜索意图关键词下的排名——排名高的账号是"搜索意图标杆"，值得重点学习其SEO/关键词策略。

## 特有量化标准：模式覆盖率

对标学习产出的模式集合须计算**模式覆盖率**，衡量提取结果对样本的解释程度：

| 指标 | 公式 | 门槛 |
|------|------|------|
| 钩子覆盖率 | 被某钩子模式覆盖的样本数 / 总样本数 | ≥ 60% |
| 结构覆盖率 | 被某结构模式覆盖的样本数 / 总样本数 | ≥ 50% |
| 综合覆盖率 | 被任一模式覆盖的样本数 / 总样本数 | ≥ 80% |

覆盖率低于门槛时，须在输出中标注 `⚠ 模式覆盖率不足（钩子 X% / 结构 Y% / 综合 Z%），部分样本未被已有模式解释，可能存在未识别模式`。

## 学习结果验证

提取的 Pattern 必须经过验证才能作为可靠参考，验证分为三个层级：

### 第一层：内部一致性验证

| 验证项 | 方法 | 通过标准 | 不通过时 |
|--------|------|---------|---------|
| 模式覆盖率 | 被某模式覆盖的样本数 / 总样本数 | 钩子 ≥ 60%，结构 ≥ 50%，综合 ≥ 80% | 标注覆盖率不足，可能存在未识别模式 |
| 模式互斥性 | 任一样本不应被同一类型下多个模式同时主导 | 互斥冲突率 < 15% | 合并重叠模式或细化模式边界 |
| 模式稳定性 | 去掉任意 1 条样本后重新提取，模式是否变化 | 核心模式不变 | 标注"模式不稳定"，建议增加样本量 |
| 转录质量抽检 | 随机抽检 3 条转录文本，人工核对关键句 | 关键句准确率 ≥ 80% | 标注"转录质量不足"，建议重跑转录 |

### 第二层：交叉验证

| 验证方法 | 描述 | 执行条件 |
|---------|------|---------|
| 跨账号验证 | 将提取的模式应用到同赛道其他账号，观察是否同样适用 | 有 ≥ 2 个同赛道对标账号数据 |
| 跨时间验证 | 对同一账号的不同时期内容分别提取模式，观察一致性 | 账号内容跨度 > 3 个月 |
| 跨平台验证 | 同一账号在不同平台的模式是否一致 | 账号在 ≥ 2 个平台有内容 |

### 第三层：实效验证

| 验证方法 | 描述 | 执行时机 |
|---------|------|---------|
| 应用测试 | 将提取的钩子/结构模式应用到自己的脚本中，观察打分变化 | 下一次 yang-score 执行时 |
| A/B 对照 | 使用 vs 不使用学习到的模式，对比预测分差异 | 积累 ≥ 3 条对照数据后 |
| 复盘验证 | 应用模式后的实际播放数据是否与预测一致 | yang-retro 执行时 |

### 验证结果标注

每个提取的模式在 `script_patterns.template.md` 中标注验证状态：

```markdown
#### 钩子模式 1: 反常识开篇
- 覆盖样本: 12/20 (60%)
- 验证状态: ✅ 内部一致 | ⚠️ 跨账号未验证 | ❌ 实效未验证
- 置信度: 中（需跨账号验证提升）
```

## 学习与 bump 的联动

学习结果不应直接修改 rubric 权重，而是通过 yang-bump 正式校准流程触发升级：

### 联动机制

```
yang-learn 提取模式 → 写入 benchmark.md（标注"待 bump 验证"）
                                    ↓
                          校准池样本 ≥ 10 时
                                    ↓
                    yang-bump 读取 benchmark.md 中的模式建议
                                    ↓
                    bump 评估：该模式是否与校准数据一致？
                                    ↓
              ┌──── 一致 ────┐          ┌─── 不一致 ───┐
              ↓              ↓          ↓              ↓
        rubric 权重调整   新增观察项   放弃该模式    降级为参考信号
```

### 模式到 rubric 的映射规则

| 学习模式类型 | 影响 rubric 的维度 | 映射方式 |
|------------|------------------|---------|
| 钩子模式 | HP（钩子力） | 调整钩子类型的权重分布 |
| 节奏模式 | SR（结构力）/ Rhythm | 调整节奏评分的基准线 |
| 情绪曲线 | ER（情绪力） | 调整情绪刺点的位置权重 |
| 完播设计 | SR / SAT | 调整结尾设计的评分标准 |
| 主题方向 | AB（传播力） | 调整选题热度的权重 |

### bump 触发条件

学习结果触发 bump 的条件（满足任一即可）：

1. **新模式发现**：学习到与当前 rubric 不一致的模式（如 rubric 重视悬念型钩子，但学习发现对标账号用冲突型钩子效果更好）
2. **模式覆盖率显著变化**：新模式覆盖率 > 当前 rubric 对应维度的覆盖率
3. **连续 3 次学习结果指向同一调整方向**：多次学习结果一致建议调整某维度权重

### 联动输出格式

在 `benchmark.md` 的"可借鉴维度的 rubric 调整建议"中追加：

```markdown
#### 可借鉴维度的 rubric 调整建议
1. [钩子力] 对标账号高频使用冲突型钩子（8/20 条），当前 rubric 以悬念型为主 → 建议 bump 时评估钩子类型权重
2. [情绪力] 对标账号情绪曲线呈"V 型反转"（15/20 条），当前 rubric 未区分情绪曲线类型 → 建议 bump 时增加曲线类型维度

📌 以上建议需经 yang-bump 校准验证后方可生效，不可直接修改 rubric 权重
```

## 学习失败诊断

学习效果不好时，按以下诊断框架逐步排查：

### 常见失败模式

| 失败现象 | 可能原因 | 排查步骤 | 修复方案 |
|---------|---------|---------|---------|
| 模式覆盖率 < 50% | 样本量不足或样本差异过大 | 1. 检查样本数是否 ≥ 5<br>2. 检查样本内容是否跨多个子领域 | 增加样本量；缩小分析范围到单一子领域 |
| 所有模式高度同质化 | 对标账号内容缺乏变化 | 1. 检查对标账号是否为矩阵号/模板化生产<br>2. 检查是否选错了对标账号 | 更换对标账号，选择内容更多元的账号 |
| 提取的模式与直觉不符 | 转录质量低下导致误判 | 1. 抽检转录文本准确率<br>2. 对比原视频确认关键句 | 重跑转录（使用更高精度模型）；手动修正关键句 |
| 钩子模式无法提取 | 视频前 3 秒转录缺失 | 1. 检查转录是否从第 0 秒开始<br>2. 检查是否有静音/纯音乐开头 | 手动补充前 3 秒描述；使用视觉分析辅助 |
| 情绪曲线平坦无波动 | 转录文本缺乏情绪标记 | 1. 检查转录是否丢失语气词/感叹号<br>2. 检查对标账号是否为知识类（天然低情绪） | 结合视觉帧分析补充情绪信号；调整情绪曲线基准 |
| 结构模式混乱 | 样本跨多种脚本类型 | 1. 按脚本类型（观点/过程/知识/故事）分组<br>2. 分别提取模式 | 先分类再提取，避免混合模式 |

### 诊断流程

```
学习效果不佳
    ↓
Step 1: 检查样本质量
  → 样本数 < 5？ → 增加样本
  → 转录质量低？ → 重跑转录
    ↓
Step 2: 检查对标账号选择
  → 账号内容是否过于模板化？ → 更换对标
  → 账号是否跨领域？ → 聚焦单一领域
    ↓
Step 3: 检查模式提取逻辑
  → 模式覆盖率低？ → 细化模式分类
  → 模式同质化？ → 增加差异化样本
    ↓
Step 4: 检查验证条件
  → 验证不通过？ → 回退到 Step 1-3
  → 验证通过但实效差？ → 模式可能不适合当前阶段
    ↓
Step 5: 输出诊断报告
  → 记录失败原因 + 建议下一步
```

### 诊断报告格式

```
🔍 学习失败诊断报告

失败现象: 模式覆盖率不足（钩子 40% / 结构 35% / 综合 55%）

诊断结果:
  根因: 样本量不足（仅 4 条有效样本，需 ≥ 5 条）
  次因: 样本跨 2 个子领域（职场成长 + 情感观点），模式被稀释

修复建议:
  1. 增加采样视频至 ≥ 10 条
  2. 聚焦单一子领域（建议先分析"职场成长"方向）
  3. 重新执行 yang-learn

是否立即按建议重新执行？(y/n)
```
