# yang-retro · 数据回收与复盘

## ⚡ 紧凑核心规则

**复盘3步流程**：①获取实际数据→预测vs实际对比表 → ②偏差归因（按优先级：rubric问题→外部因素→执行偏差） → ③提取观察写入rubric_notes.md + 追加`##复盘`段到预测文件。

**偏差归因决策树一句话**：偏差>15%→先查rubric（维度缺失/权重失衡/公式缺陷）→再查外部（发布时机/算法变动/竞争分流/注意力转移）→最后查执行（内容偏离/包装偏离/运营干预）→归因未知则标记"待观察"。

**观察写入规则**：每条观察含现象+假设+验证条件+所需样本数+关联维度+优先级；偏差等级决定最少样本（🟡3/🔴2/🔴🔴2）；观察升级为正式维度需≥最少样本+2个独立视频+假设未被证伪+有维度定义和公式建议。

**搜索意图复盘**：复盘时检查Channel E选题的搜索意图信号是否验证（如：选题基于"AI工具推荐"搜索建议→发布后检查该关键词搜索排名变化）。

> **前置条件**：对应预测文件存在
>
> **产生**：预测文件中追加 `## 复盘` 段（不可修改 `## 预测` 段）
>
> **依赖**：adapters/perf-data/（复盘数据获取）、templates/retro.template.md

## 工作流

### 复盘分析量化标准

> 以下标准用于判断偏差等级和触发条件，确保复盘分析有据可依。

**偏差等级定义**：

| 等级 | 偏差范围 | 标记 | 归因要求 |
|------|---------|------|---------|
| 微偏差 | ≤ 15% | 🟢 | 无强制归因，可选记录 |
| 中偏差 | 15% < 偏差 ≤ 30% | 🟡 | 至少一类归因（模型缺失/外部因素/执行偏差） |
| 大偏差 | 30% < 偏差 ≤ 50% | 🔴 | 必须三类归因全覆盖，缺一不可 |
| 极端偏差 | > 50% | 🔴🔴 | 必须三类归因 + 触发新观察提取（Step 5 强制执行） |

**触发新观察的条件**（满足任一即触发）：
1. 任意指标偏差 > 30%（大偏差及以上）
2. 两个及以上指标同方向偏差 > 20%（系统性偏移信号）
3. 预测 bucket 与实际 bucket 差距 ≥ 2 档（如预测 A 实际 C）
4. 连续 2 次复盘同一维度出现同方向偏差（重复偏差模式）

**预测准确度评分标准**（Step 6 的"本轮得分"）：

| 准确度得分 | 条件 |
|-----------|------|
| 9-10 | 所有指标微偏差，无中偏差及以上 |
| 7-8 | 存在中偏差但无大偏差，且归因完整 |
| 5-6 | 存在1项大偏差，归因完整 |
| 3-4 | 存在2项大偏差或1项极端偏差 |
| 1-2 | 存在2项及以上极端偏差，或归因不完整 |

### 复盘深度分级

> 根据复盘触发时间与目的，将复盘分为三个深度等级，执行内容和严格程度逐级递增。

| 等级 | 触发时机 | 核心目的 | 执行内容 | 归因要求 | 观察提取 |
|------|---------|---------|---------|---------|---------|
| **T+3d 快速复盘** | 发布后 3-7 天 | 初步数据验证，捕捉明显偏差 | Step 1-4（必做）+ Step 6（简化版） | 仅大偏差（>30%）需归因，中偏差可选记录 | 仅极端偏差（>50%）触发观察提取 |
| **T+7d 标准复盘** | 发布后 7-14 天 | 完整数据回收，系统性归因 | Step 1-7（完整流程） | 中偏差及以上必须归因，三类归因全覆盖 | 满足触发条件即提取观察 |
| **T+30d 深度复盘** | 发布后 30 天+ | 长尾数据验证，校准模型长期准确性 | Step 1-7 + 额外长尾分析（见下方） | 所有偏差均需归因，含长尾效应分析 | 所有观察均需提取，含时间维度衰减分析 |

**T+30d 深度复盘额外执行项**：
1. **长尾效应分析**：对比 T+7d 与 T+30d 的数据变化率，判断内容是否进入长尾传播期（变化率 > 20% → 长尾有效）
2. **算法推荐衰减评估**：分析 T+7d 后的播放增长曲线，判断是否仍处于推荐池（日播放 > 总播放 5% → 仍在推荐）
3. **跨周期对比**：若同主题有多条内容，对比不同发布时间点的长尾表现差异
4. **rubric 长效校准**：将 T+30d 数据纳入校准池时，标注 `data_maturity: full`（T+3d/T+7d 标注为 `partial`）

**复盘升级规则**：
- T+3d 快速复盘发现大偏差（>30%）→ 建议在 T+7d 再做标准复盘
- T+7d 标准复盘发现数据仍在快速增长（日增幅 > 15%）→ 建议在 T+30d 做深度复盘
- 同一条内容最多做 3 次复盘（T+3d / T+7d / T+30d），每次复盘追加到同一 `## 复盘` 段下

### 偏差归因决策树

> 当预测偏差较大时，按以下优先级顺序排查原因，确保归因系统化、不遗漏。

```
偏差 > 15%？
├── YES → Step 1: 检查 rubric 问题
│   ├── rubric 维度是否覆盖了该内容的核心特征？
│   │   ├── NO → 归因：模型缺失（维度不足）→ 提取观察，待 bump 升级
│   │   └── YES → 继续
│   ├── 权重分配是否合理？（某维度权重过高/过低导致评分偏移）
│   │   ├── NO → 归因：模型缺失（权重失衡）→ 提取观察，待 bump 调权
│   │   └── YES → 继续
│   └── 公式计算是否存在边界问题？（如极端值导致评分失真）
│       ├── YES → 归因：模型缺失（公式缺陷）→ 提取观察，待 bump 修公式
│       └── NO → 进入 Step 2
│
├── Step 2: 检查外部因素
│   ├── 发布时间是否偏离最佳时段？（非目标用户活跃时段发布）
│   │   ├── YES → 归因：外部因素（发布时机）→ 记录但不改 rubric
│   │   └── NO → 继续
│   ├── 平台算法是否有变动？（近期平台规则/推荐逻辑调整）
│   │   ├── YES → 归因：外部因素（算法变动）→ 标注待观察，积累样本
│   │   └── NO → 继续
│   ├── 是否有竞品/同质内容同期发布？（流量被分流）
│   │   ├── YES → 归因：外部因素（竞争分流）→ 记录但不改 rubric
│   │   └── NO → 继续
│   └── 是否有突发事件影响用户注意力？（社会热点/节假日等）
│       ├── YES → 归因：外部因素（注意力转移）→ 记录但不改 rubric
│       └── NO → 进入 Step 3
│
└── Step 3: 检查执行偏差
    ├── 实际视频与脚本/策划是否一致？
    │   ├── NO → 归因：执行偏差（内容偏离）→ 标注具体偏离点
    │   └── YES → 继续
    ├── 标题/封面是否按计划发布？
    │   ├── NO → 归因：执行偏差（包装偏离）→ 标注具体偏离点
    │   └── YES → 继续
    └── 发布后是否有运营干预？（如投流/置顶/删评等）
        ├── YES → 归因：执行偏差（运营干预）→ 标注干预类型和程度
        └── NO → 归因：未知因素 → 标记为"待进一步观察"，积累样本
```

**归因优先级原则**：
1. **rubric 问题优先排查**：若 rubric 有缺陷，修改 rubric 可系统性提升后续预测准确度，收益最大
2. **外部因素次之**：外部因素不可控，但记录后可帮助建立"外部因素修正系数"
3. **执行偏差最后**：执行偏差是偶发的，不影响模型本身，但需标注以区分"模型不准"和"执行走样"

### 观察提取模板

> 标准化观察的格式，确保每条观察可追溯、可验证、可量化。

从偏差分析中提取观察时，必须使用以下标准模板写入 `rubric_notes.md` 的 `## 观察（待验证）` 区域：

```markdown
### 观察：YYYY-MM-DD from <video-id>
- **现象**: <客观描述观察到的数据偏差，含具体数值>
  - 偏差指标: <指标名>
  - 偏差方向: <高估/低估>
  - 偏差幅度: <X%>
  - 偏差等级: <🟢微偏差 / 🟡中偏差 / 🔴大偏差 / 🔴🔴极端偏差>
- **假设**: <对偏差原因的可证伪假设，必须明确"如果假设成立，则应观察到…">
  - 假设类型: <rubric缺失 / 权重失衡 / 公式缺陷 / 外部因素 / 执行偏差>
  - 可证伪条件: <什么情况下这个假设会被推翻>
- **验证条件**: <如何验证该假设，含具体操作步骤>
  - 验证方法: <A/B对比 / 回溯历史数据 / 新样本测试 / 跨平台验证>
  - 所需数据: <需要什么额外数据>
- **所需样本数**: <至少需要多少个独立样本才能确认该观察>
  - 最少样本: <N>（低于此数不升级为正式维度）
  - 推荐样本: <M>（达到此数可高置信度升级）
  - 当前已积累: <K/N>（已观察到的支持样本数）
- **关联维度**: <该观察与 rubric 中哪个现有维度相关，或建议新增维度名>
- **优先级**: <高/中/低>（基于偏差等级和假设的改进潜力综合判断）
```

**样本数确定规则**：

| 偏差等级 | 最少样本 | 推荐样本 | 理由 |
|---------|---------|---------|------|
| 🟡 中偏差 | 3 | 5 | 需排除偶然性 |
| 🔴 大偏差 | 2 | 4 | 信号较强，但需确认非孤立事件 |
| 🔴🔴 极端偏差 | 2 | 3 | 信号极强，但仍需至少一次独立验证 |

**观察升级为正式维度的条件**（全部满足）：
1. 已积累 ≥ 最少样本数的支持样本
2. 至少 2 个独立视频出现同类偏差
3. 假设未被证伪条件推翻
4. 有明确的维度定义和评分公式建议

### Step 1: 定位预测文件 + 确定预测分版本

> **🛑 检查点 CP1**：预测文件存在且包含有效预测段。若不满足 → 触发 `RETRO_NO_PREDICTION`，拒绝继续。

根据用户参数找到对应预测文件。

读取 `.yang-state.json` 中的 `shoots[]`，定位本次复盘的 shoot 记录：

```python
shoot = next((s for s in state.get("shoots", []) if s.get("prediction_file") == prediction_path), {})
v2_written = shoot.get("v2_prediction_written", False)
```

- 若 `v2_prediction_written` 为 `true` → 读取预测文件中的 `## 预测 v2` 段的分数作为预测基准
- 若 `v2_prediction_written` 为 `false`（或缺失）→ 读取预测文件中的 `## 预测 v1` 段的分数作为预测基准
- 若 shoot 记录不存在（ad_hoc 拍摄）→ 默认使用 v1 段，标注 "预测版次未知，以 v1 为准"

### Step 2: 获取实际表现数据

> **🛑 检查点 CP2**：可获取指标 ≥ 3 项。若不满足 → 触发 `RETRO_DATA_INCOMPLETE`，降级复盘。

| 分享数 | 平台后台 / app 截图 |
| 收藏数 | 平台后台 / app 截图 |
| 完播率 | 平台后台（如有） |
| 涨粉 | 平台后台（如有） |

### Step 4: 分析偏差原因

> **🛑 检查点 CP3**：偏差分析必须包含三类归因（模型缺失/外部因素/执行偏差）。若仅列数值无归因 → 触发 `RETRO_BIAS_UNCHECKED`，退回本步。

对每个超出置信区间的指标分析原因：

1. **"是我们预测模型没学到的东西"** → rubric 里缺了什么？
2. **"是外部因素"** → 发布时间、算法变化、竞品同期发布？
3. **"是执行偏差"** → 实际视频和脚本差异？

#### 搜索意图验证（Channel E 选题专属）

若复盘的选题来自 Channel E（搜索意图），额外执行：
1. 查看该选题的种子关键词在发布后的搜索排名变化
2. 检查搜索建议是否仍包含该关键词
3. 若搜索意图信号已消失（如关键词不再出现在搜索建议中）→ 标注"搜索意图窗口已过"
4. 若搜索意图信号仍在 → 标注"搜索意图持续有效"，该选题方向可继续深挖

### Step 5.5: 人设效能对比

从 `.yang-state.json` 读取 `persona_history` 数组：

若 `persona_history` 中有 ≥ 2 个版本记录：
1. 按人设版本分组统计各版本的校准样本数据
2. 计算每个版本下的平均播放量、平均互动率（点赞+评论+分享/播放）
3. 生成对比报告

若 `persona_history` 中 < 2 个版本或不存在 → 跳过此步骤。

```
👤 人设效能对比
  v1.0（理性分析型）：平均播放 2.3w，互动率 4.1%
  v2.0（口语对话型）：平均播放 3.1w，互动率 5.8%
  → v2.0 表现更优（+34% 播放，+41% 互动）
```

- 版本名称优先从 `persona_history` 记录的 `version_label` 字段读取
- 若 `version_label` 缺失 → 使用 `v{N}` 默认名（N 为版本序号）
- 若样本数过少（某版本下 < 3 个样本）→ 标注 "样本不足，参考有限"
- 此对比非硬性结论，仅作为人设迭代方向的参考信息

## 失败模式编码

| 编码 | 含义 | 触发条件 | 处置 |
|------|------|---------|------|
| `RETRO_NO_PREDICTION` | 预测文件中无 `## 预测` 段 | 读取预测文件后未找到任何预测段 | 拒绝复盘，提示先运行预测 |
| `RETRO_EARLY_DATA` | 数据回收过早（< T+3d） | 发布不足 72 小时即请求复盘 | 警告并标注"数据可能不稳定"，允许强行复盘但降级置信度 |
| `RETRO_IMMUTABLE_VIOLATION` | 试图修改 `## 预测` 段 | 检测到对预测段的写入操作 | 立即中止，回滚变更，提示"预测段不可变" |
| `RETRO_DATA_INCOMPLETE` | 实际数据缺失过多 | 可对比指标 < 3 项（N/A 占比 > 50%） | 降级复盘，标注"数据不完整，偏差分析参考有限" |
| `RETRO_BIAS_UNCHECKED` | 偏差分析未做归因 | Step 4 中仅列偏差数值未做原因分类 | 退回 Step 4，要求补充分类归因（模型缺失/外部因素/执行偏差） |

## 反例黑名单

> 以下行为在复盘中**严格禁止**，任何一条触发即标记为 `⚠️ BLACKLIST_VIOLATION`。

1. **禁止修改预测段**：复盘数据只能追加到 `## 复盘` 段，`## 预测` 段为 immutable，任何修改都是违规
2. **禁止选择性对比**：不得只展示偏差小的指标而隐藏偏差大的指标，所有可获取指标必须全部列入对比表
3. **禁止事后合理化**：不得将大偏差解释为"本来就不好预测"而不做归因分析，偏差 > 30% 必须有明确归因
4. **禁止虚构实际数据**：不得为缺失指标编造数值或使用估算值替代，缺失一律标记 N/A
5. **禁止跳过偏差归因**：不得从对比表直接跳到"关键发现"，必须经过 Step 4 的三类归因分析
6. **禁止单样本升级规则**：不得基于单次复盘的观察直接升级 rubric 维度，观察必须标注"待验证"并积累样本
7. **禁止忽略置信区间**：对比时必须标注预测置信区间，不得仅比较点估计值
8. **禁止复盘结论含糊**：复盘总结必须包含明确的"本轮得分"，不得以"还行""差不多"等模糊表述替代量化评分
