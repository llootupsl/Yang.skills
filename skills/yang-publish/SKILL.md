# yang-publish · 发布元数据登记

## ⚡ 紧凑核心规则

**发布前10项自检**：①预测文件存在 ②评分完整(7维非空) ③composite≥6.0(否则警告) ④预测桶已生成 ⑤发布-预测时差≥4h(否则标记边缘/违规) ⑥元数据完整(时间/平台/链接) ⑦视频目录存在 ⑧非重复登记 ⑨buffer状态确认 ⑩无超期待复盘。全部通过方可登记。

**发布后触发链**：登记完成→立即设T+3复盘提醒+检查bump阈值+计算buffer颜色→T+3d Schedule触发复盘提醒→T+7d未复盘升级提醒强度。连续3次composite<6.0触发yang-doctor | 连续3次方向性偏差触发yang-bump评估。

**搜索意图标签**：发布时自动附加Channel E的种子关键词作为标签/话题，确保内容能被搜索意图覆盖。如选题来自"AI工具推荐"搜索建议→发布时带#AI工具推荐 话题。

> **前置条件**：对应预测文件存在
>
> **产生**：预测文件中追加 `## 发布信息` 段
>
> **依赖**：对应 predictions/ 下的预测文件

## 工作流

### Step 1: 定位预测文件

> 🔍 **CHECKPOINT 0**：预测文件已定位，发布登记目标明确

根据用户参数找到对应预测文件。支持以下匹配方式：
- 精确路径：`predictions/YYYY-MM-DD_<id>_<short>.md`
- 模糊匹配：用户提供 ID 或标题关键词

### Step 2: 收集发布信息

> 🔍 **CHECKPOINT 1**：发布信息（时间/平台/链接）已收集完整

| 字段 | 要求 |
|------|------|
| 发布时间 | ISO 8601 格式，精确到分钟 |
| 发布平台 | 抖音/小红书/B站/视频号/... |
| 视频链接 | 完整的可访问 URL |
| 发布时账号状态 | 粉丝数、近 7 天平均播放（可选） |

### Step 3: 写入发布信息

> 🔍 **CHECKPOINT 2**：发布信息已写入预测文件，数据完整性已验证

在预测文件中追加（注意，是追加，不是修改 `## 预测` 段）：

```markdown
---

## 发布信息

- **发布时间**: YYYY-MM-DDTHH:MM+TZ
- **发布平台**: <platform>
- **视频链接**: <url>
- **发布时账号状态**: 粉丝 <N>，近 7 天平均播放 <N>
- **登记时间**: <ISO timestamp>
```

### Step 4: 设置复盘提醒

在 `.yang-state.json` 中记录待复盘项，提醒用户 T+3 天后回来复盘。

### Step 5: 更新状态

> 🔍 **CHECKPOINT 3**：state.shoots 队列已更新，buffer 计数已刷新

更新 `.yang-state.json`：
- `stats.total_published += 1`
- `stats.pending_retros` 保持（预测已计入）
- 按 `prediction_file` 匹配 `state.shoots` 中的对应条目，发布后从数组中移除，确保 `buffer_available` 始终正确

## 错误处理

| 场景 | 行为 |
|------|------|
| 找不到对应预测文件 | 提示"这个视频还没做过预测，先'启动预测'" |
| 预测文件已有发布信息 | 提示"这个预测已经登记过发布了"，显示已有信息 |
| 无法访问视频链接 | 警告但不阻止登记（可以后补） |

## 失败模式编码

| 编码 | 名称 | 描述 |
|------|------|------|
| `YB-E01` | 预测文件缺失 | 找不到对应预测文件，无法关联发布信息 |
| `YP-E02` | 重复登记 | 预测文件已有发布信息段，避免二次写入 |
| `YP-E03` | 前置条件不满足 | last_shoot_file 为 null，未走 yang-shoot 流程 |
| `YP-E04` | 发布时间格式异常 | 非 ISO 8601 格式，无法解析为标准时间戳 |
| `YP-E05` | buffer 计数不一致 | state.shoots 移除后 buffer_available 与实际不符 |
| `YP-E06` | 并发冲突 | in_progress_session 被其他流程占用 |

## 反例黑名单

1. **禁止在无预测文件时登记发布**——没有预测就没有复盘基线，必须先跑 yang-predict
2. **禁止重复写入发布信息段**——同一预测文件只能有一个 `## 发布信息`，重复登记需先确认
3. **禁止修改预测段内容**——发布信息是追加，不得回改 `## 预测` 段的任何内容
4. **禁止跳过复盘提醒设置**——T+3 复盘提醒是闭环关键，不可省略
5. **禁止在 buffer 计数异常时静默继续**——shoots 队列移除后必须验证 buffer_available 正确
6. **禁止在并发冲突时强制写入**——必须等待或询问用户清除锁
7. **禁止接受空链接作为发布信息**——视频链接为必填，缺失则提示用户后补
8. **禁止单次发布登记操作跨多个预测文件**——一条发布对应一个预测，批量需逐条执行

## 特有量化标准：发布-预测时差合规率

发布登记时须计算**发布-预测时差**（publish_time - prediction_created_at），衡量盲预测原则的执行质量：

| 时差区间 | 标记 | 含义 |
|----------|------|------|
| ≥24h | `合规` | 预测与发布间隔充足，盲预测原则得到保障 |
| 4-24h | `边缘` | 间隔偏短，可能存在预测受拍摄过程影响的风险 |
| <4h | `违规` | 间隔过短，盲预测原则可能被违反 |

**合规率** = 合规次数 / 总发布次数。合规率 < 80% 时，yang-status 须提示"发布-预测时差合规率偏低，建议在拍摄前完成预测"。

时差标记写入预测文件 `## 发布信息` 段的 `prediction_publish_gap` 字段。

## 发布前自检清单

> 发布登记前必须逐项确认以下 10 项条件，全部通过方可执行发布登记。任一项不通过须提示用户并暂停流程。

| # | 自检项 | 通过条件 | 不通过处理 |
|---|--------|---------|-----------|
| 1 | 预测文件存在 | `predictions/<id>.md` 存在且可读 | 拒绝发布，提示先运行 yang-predict |
| 2 | 预测评分完整 | 预测文件含 `## 预测` 段且 7 维度评分非空 | 提示"预测评分不完整，请先补全" |
| 3 | composite ≥ 发布阈值 | composite ≥ 6.0（或用户自定义阈值） | 警告"composite 偏低（{N}），确认仍要发布？" |
| 4 | 预测桶已生成 | `predicted_bucket` 字段非空 | 提示"预测桶缺失，建议重新运行 yang-predict" |
| 5 | 发布-预测时差合规 | `publish_time - prediction_created_at ≥ 4h` | 标记为"边缘"或"违规"，提示用户确认 |
| 6 | 元数据完整 | 发布时间/平台/链接三项非空 | 拒绝发布，提示补全缺失项 |
| 7 | 视频文件存在 | `videos/<id>/` 目录存在且含 `script.md` | 警告"视频目录缺失，是否为 ad_hoc 发布？" |
| 8 | 非重复登记 | 预测文件中无 `## 发布信息` 段 | 拒绝重复登记，展示已有信息 |
| 9 | buffer 状态确认 | `buffer_available > 0`（shoots 队列中有对应条目） | 警告"buffer 中无此视频，是否为异常发布？" |
| 10 | 复盘提醒未过期 | 无超过 T+7 天未复盘的 pending_retros | 警告"有 N 条待复盘项已超期，建议先复盘" |

**自检输出格式**：
```
📋 发布前自检（10/10 通过）
  ✅ 预测文件 | ✅ 评分完整 | ✅ composite 8.47 | ✅ 预测桶 30-100w
  ✅ 时差合规 | ✅ 元数据完整 | ✅ 视频目录 | ✅ 非重复
  ✅ buffer 确认 | ✅ 无超期待复盘
```

若有不通过项：
```
📋 发布前自检（7/10 通过，3 项需处理）
  ✅ 预测文件 | ✅ 评分完整 | ⚠️ composite 5.2（低于阈值 6.0）| ✅ 预测桶
  ⚠️ 时差边缘（2.5h）| ✅ 元数据 | ✅ 视频目录 | ✅ 非重复
  ✅ buffer | ⚠️ 2 条待复盘超期
  → 请确认是否继续发布？
```

## 发布后自动触发规则

> 发布登记完成后，系统自动检查以下触发条件并执行对应的后续 skill 调用链。无需用户手动触发。

| 触发条件 | 自动动作 | 说明 |
|---------|---------|------|
| 发布登记完成 | 设置 T+3 复盘提醒 | 写入 `pending_retros`，提醒用户 3 天后复盘 |
| 发布登记完成 | 检查 `calibration_samples` 是否达到 bump 阈值 | 若 `calibration_samples ≥ next_bump_threshold` → 提示"校准样本已达 bump 阈值，建议运行 yang-bump" |
| 发布登记完成 + buffer 颜色变 🔴 | 触发 yang-recommend 稳分推荐 | 自动提示"buffer 已空，推荐下一条稳分选题" |
| 发布登记完成 + buffer 颜色变 🔵 | 输出积压警告 | 提示"buffer 积压，建议暂停拍摄" |
| T+3 天到达 | 触发 yang-retro 复盘提醒 | 通过 Schedule 工具设置定时提醒 |
| T+7 天未复盘 | 升级提醒强度 | 从"建议复盘"升级为"⚠️ 复盘超期，数据可能失真" |
| 连续 3 次发布 composite < 6.0 | 触发 yang-doctor 诊断 | 提示"近期发布质量偏低，建议系统体检" |
| `consecutive_directional_errors ≥ 3` | 触发 yang-bump 评估 | 提示"连续方向性偏差，rubric 可能需要校准" |

**自动触发链执行顺序**：
```
发布登记完成
  → 立即：设置 T+3 复盘提醒（写入 pending_retros）
  → 立即：检查 bump 阈值 → 条件满足则提示
  → 立即：计算 buffer 颜色 → 颜色变化则输出对应建议
  → 延迟 T+3d：Schedule 触发复盘提醒
  → 延迟 T+7d：若未复盘，升级提醒
```

### 跨平台发布登记

当同一视频发布到多个平台时：
- 每个平台独立登记一条 `## 发布信息` 段（用 `### 平台: <name>` 子标题区分）
- `prediction_publish_gap` 按首次发布时间计算
- buffer 计数仅在首次发布时 -1，跨平台发布不重复扣减
- 各平台实绩数据分别采集，yang-retro 按平台分别计算偏差
