# 中文ASR引擎对比调研

> **调研问题**：当前进行对标账号视频转录，是否有更优的中文ASR方案？
> **结论**：方案A为首选替代方案，性价比最高；方案B为精度之最；方案C适合多人对话场景。

## 二、方案详细分析

### 2.1 方案A —— 首选推荐

**核心优势**：
- **三重能力合一**：ASR + 情感识别（喜怒哀乐等7种情绪）+ 音频事件检测（掌声、笑声、BGM变化等），一个模型同时输出多维度标注
- **极致轻量**：Small版仅270MB，10秒音频推理70ms，适合批量处理对标账号大量视频
- **中文精度卓越**：AISHELL-1 达98.2%
- **扩展性强**：50+语言支持，粤语精度95.7%

**集成收益分析**：

| 收益维度 | 量化预估 |
|---------|---------|
| 转录精度提升 | 对标视频转写错字率降低 ~60%（CER从5%降至2%以内） |
| 新增能力 | 自动输出情感标签 → 直接增强 `yang-emotion-curve`；自动输出音频事件 → 丰富对标拆解维度 |
| 效率提升 | 推理速度快7倍，批量处理效率极大提升 |
| 存储成本 | 模型体积大幅缩小 |

**集成难度**：低
- 封装为 `adapters/benchmark-auto/asr-adapter.py`
- 保持与现有 adapter 相同的 I/O 接口

---

### 2.2 方案B —— 多人对话首选

**核心优势**：
- **端到端全链路**：VAD（语音活动检测）→ ASR → 标点恢复 → 说话人分离，一条龙服务
- **流式识别**：支持实时流式处理，适合直播场景
- **方言/口音支持**：7种方言、26种口音

**最佳使用场景**：对标账号含多人对谈/圆桌讨论/辩论等多人场景

**集成难度**：中
- 需要配置全链路 pipeline
- 输出格式需要格式转换层

---

### 2.3 方案C —— 精度之最

**核心优势**：
- **中文识别精度 #1**：AISHELL-1 CER仅0.57%，当前公开benchmark最优
- 适合对转录精度要求极高的场景

**适用场景**：对标视频中信息密度极高（如法律科普、财经分析），错一字可能误判内容的关键场景

**集成难度**：中高
- 社区生态较小，文档和工具链待完善
- 建议作为方案A的高精度后备引擎

---

### 2.4 方案D —— 方言场景

**核心优势**：
- 粤语支持和轻声识别业界领先
- 1.5B参数，适合需要更高理解能力的场景

**最佳使用场景**：对标广东话/粤语内容创作者

**集成难度**：中
- 模型较大，推理资源需求较高
- 适合作为特定方言的专用引擎

## 三、推荐方案与技术路线

### 推荐优先级

| 优先级 | 方案 | 使用场景 | 理由 |
|--------|------|---------|------|
| **P0** | 方案A | 通用中文对标转录，90%场景 | 精度高 + 速度极快 + 额外情感/事件标注能力 |
| **P1** | 方案B | 多人对话对标分析 | 说话人分离是关键功能，通用场景不一定需要 |
| **P2** | 方案C | 极限精度要求场景（法律/财经） | 精度最佳但生态不成熟，作为后备 |
| **P3** | 方案D | 粤语内容创作者对标 | 场景窄但不可替代 |

### 技术路线

```
对标视频
    │
    ├── 单人/博主口播 ──→ 方案A ──→ 转写文本 + 情感标签 + 音频事件
    │
    ├── 多人对话 ──→ 方案B ──→ 转写文本 + 说话人分离
    │
    ├── 粤语内容 ──→ 方案D ──→ 粤语转写 + 轻声标注
    │
    └── 降级路径：以上任一失败 → 通用方案
```

### 集成架构

```
adapters/benchmark-auto/
├── asr_engine.py        # 引擎抽象接口（统一I/O）
├── asr_adapter_a.py     # Phase 1 新增
├── asr_adapter_b.py     # Phase 2 新增
└── engine_config.yaml   # 引擎配置与切换规则
```
