# 热点趋势监控方案调研

> **调研问题**：当前 `yang-trends` 使用静态数据源（手动配置的 trend-sources adapter），如何升级为实时、自动化的多平台热点监控？
> **结论**：多平台热点监控是一站式解决方案，已实现标准协议，可直接作为 Agent Tool 集成。

---

## 一、当前痛点分析

| 痛点 | 说明 | 影响 |
|------|------|------|
| **静态数据** | 热点数据依赖手动配置，无法实时更新 | 错过时效性热点，选题慢半拍 |
| **平台覆盖少** | 当前仅覆盖少量平台 | 多平台联动选题能力缺失 |
| **缺AI摘要** | 纯原始数据，缺少关键信息提炼 | Agent需要额外做信息提炼 |
| **推送缺失** | 无法主动推送热点提醒 | 被动等待用户查询 |

## 三、集成方案设计

### 3.1 MCP Tool 注册

TrendRadar 已实现 MCP 协议，注册为 Agent Tool 后，Yang.skills 各子skill可直接调用：

```json
{
  "mcpServers": {
    "trendradar": {
      "command": "npx",
      "args": ["-y", "trendradar-mcp"],
      "env": {
        "TRENDRADAR_API_KEY": "${TRENDRADAR_API_KEY}"
      }
    }
  }
}
```

### 3.2 Tool 能力映射

| TrendRadar Tool | 映射到 Yang.skills 工作流 | 触发时机 |
|----------------|-----------------|---------|
| `search_trends` | `yang-trends` 热点查询 | 每日选题流程入口 |
| `get_trend_detail` | `yang-trends` 单热点深挖 | 确定选题后深入分析 |
| `compare_trends` | `yang-trends` 跨平台对比 | 多平台差异化选题决策 |
| `subscribe_topic` | `yang-trends` 长期监控 | 固定赛道关键词持续追踪 |

### 3.3 工作流集成

```
每日选题触发
      │
      ▼
TrendRadar MCP ──→ 多平台热点数据 (11+平台)
      │
      ├──→ yang-trends: 热点筛选 + 关键词过滤
      │
      ├──→ AI摘要: 热点一句话提炼 + 适用性评分
      │
      └──→ 推送飞书: 每日热点日报
              │
              ▼
      yang-seed: 基于热点的选题策划
```

## 四、集成难度与风险

| 维度 | 评估 |
|------|------|
| **集成难度** | 低 —— MCP协议已实现，仅需配置注册 + 适配器封装 |
| **维护成本** | 低 —— 社区活跃，持续更新 |
| **依赖风险** | 低 —— 如TrendRadar不可用，降级回现有静态数据源 |
| **API限流** | 需关注 —— 多平台采集可能触发各平台反爬机制 |
