# 发布时间优化算法调研

> **调研问题**：当前 `yang-publish-optimizer` 使用简单的贝叶斯回归，是否有更优的发布时间优化算法？
> **结论**：Multi-Armed Bandit 强化学习法为短中期首选，解决"数据少时怎么决策"的核心问题；时间序列预测和因果推断为中长期高级分析工具。

---

## 一、三种算法对比

| 维度 | Multi-Armed Bandit | 时间序列预测 | 因果推断 |
|------|:---:|:---:|:---:|
| **算法类型** | 强化学习（Multi-Armed Bandit） | 时间序列预测 | 因果推断 |
| **核心问题** | "在哪个时间段发布效果最好？" | "哪一天/哪个时段是流量高峰？" | "改发布时间后，效果真的变好了吗？" |
| **输入数据** | 每次发布的播放量/互动量 | 历史播放量 + 节假日/周周期 | 发布策略变更前后的时间序列 |
| **最小样本** | 8次即可开始收敛 | 建议50+数据点 | 需要策略变更前后的对比数据 |
| **冷启动能力** | 优秀（8样本即可） | 中等（需要历史数据建模） | 差（需要变更前后的对照数据） |
| **可解释性** | 高（Beta分布可视化） | 高（趋势+周期分解） | 高（反事实预测） |
| **集成难度** | 低（~50行Python） | 中 | 高 |
| **维护成本** | 低（无外部依赖） | 中 | 中 |

## 二、方案详细分析

### 2.1 Multi-Armed Bandit —— 首选推荐（Phase 2）

**原理**：将一天24小时划分为N个时间窗（如每2小时一个窗口 = 12个"臂"）。每次发布后，用 Beta 分布更新该窗口的"奖励概率"（播放量/互动量）。Bandit算法按后验概率采样选择最优窗口，自动平衡探索（Exploration）与利用（Exploitation）。

**核心优势**：

| 优势 | 说明 |
|------|------|
| **极快冷启动** | 仅需8次发布即可收敛到最优时间窗附近 |
| **自动E&E平衡** | 无需手动设置探索比例，算法自动在探索/利用间平衡 |
| **持续自适应** | 如果用户行为变化（如寒暑假），自动跟踪调整 |
| **零外部依赖** | 纯Python实现，约50行代码 |

**适用场景**：
- 新账号/新赛道的发布时间探索
- 需要快速收敛的冷启动场景
- 当前简单贝叶斯回归的直接升级替代

**实现要点**：
```python
# 伪代码：Bandit算法 for time slot optimization
import numpy as np

class BanditPublishOptimizer:
    def __init__(self, n_slots=12):  # 24h / 2h = 12 slots
        self.n_slots = n_slots
        self.alpha = np.ones(n_slots)  # Beta prior: uninformative
        self.beta = np.ones(n_slots)

    def select_slot(self):
        samples = np.random.beta(self.alpha, self.beta)
        return np.argmax(samples)

    def update(self, slot, success):
        # success = (plays > median) for binary reward
        self.alpha[slot] += success
        self.beta[slot] += (1 - success)
```

### 2.2 时间序列预测 —— 中长期趋势预测（Phase 3）

**原理**：自动检测周周期、年周期、节假日效应。将播放量趋势分解为：趋势线 + 周期 + 节假日效应。

**核心优势**：
- **周期建模**：自动识别"每周一流量高、周日低"等规律
- **节假日效应**：内置中国节假日（春节、国庆等）流量波动建模

**适用场景**：
- 账号运行6个月以上，有足够历史数据
- 结合趋势做中长期内容发布节奏规划

**局限**：
- 需要较多历史数据（50+）
- 不能处理冷启动场景

---

### 2.3 因果推断 —— 策略效果因果评估（Phase 3）

**原理**：基于贝叶斯结构时间序列，构建反事实预测。比较"策略变更后"的实际播放量与"如果不改策略"的反事实预测播放量，计算因果效应（+95%置信区间）。

**核心优势**：
- **因果推断**：不止问"相关"，而问"因果" —— "改了发布时间到底是巧合还是真的有效？"

**适用场景**：
- 做了重大策略变更后，量化评估效果
- 例如：从"晚上8点"改为"早上7点"发布后，第30天评估总体因果效应

**局限**：
- 需要"有前后对照"的数据设计

## 三、推荐方案与技术路线

### 推荐优先级

| 优先级 | 方案 | 使用场景 | 理由 |
|--------|------|---------|------|
| **P0** | Multi-Armed Bandit | 日常发布时间决策，替代现有简单贝叶斯 | 8样本冷启动 + 自动E&E + 零依赖 |
| **P1** | 时间序列预测 | 长期趋势分析，年度内容日历规划 | 周期建模能力不可替代 |
| **P2** | 因果推断 | 重大策略变更的因果评估 | 场景窄但科学价值高 |

