# 故障排查指南

以下是 8 个常见系统级故障的排查流程，yang-doctor 诊断时按此流程执行。

## 故障 1：预测文件缺失或损坏

| 步骤 | 检查项 | 预期结果 | 异常处置 |
|------|--------|----------|----------|
| 1 | `ls predictions/*.md` 列出所有预测文件 | 文件数与 scripts/ 下的已打分脚本数匹配 | 缺失 → 检查是否遗漏 yang-predict |
| 2 | 每个预测文件包含 `## 预测` 段 | 段落存在且非空 | 缺失 → 该文件可能被误编辑，从 git 恢复 |
| 3 | 预测段未被修改（immutable 检查） | 预测段 hash 与写入时一致 | 被修改 → 恢复原版，记录违规事件 |
| 4 | 预测文件名与脚本文件名 id 匹配 | 一一对应 | 不匹配 → 重命名或补写 |

## 故障 2：rubric 版本不一致

| 步骤 | 检查项 | 预期结果 | 异常处置 |
|------|--------|----------|----------|
| 1 | 读取 `rubric_notes.md` 头部版本号 | 版本号存在 | 缺失 → 补写当前版本号 |
| 2 | 读取 `.yang-state.json` 的 `rubric_version` | 与文件版本一致 | 不一致 → 以 rubric_notes.md 为准，更新 state |
| 3 | 检查校准池样本是否用当前 rubric 打分 | 全部样本已用当前版本打分 | 有旧版本样本 → 重打分 |
| 4 | 检查 `rubric-memo.md` 中的 bump 记录 | 记录与版本号对应 | 不对应 → 补写 bump 记录 |

## 故障 3：buffer 溢出

| 步骤 | 检查项 | 预期结果 | 异常处置 |
|------|--------|----------|----------|
| 1 | 读取 `.yang-state.json` 的 `shoot_buffer` | buffer ≤ BUFFER_MAX（默认5） | 超出 → 警告"buffer 溢出" |
| 2 | 检查 buffer 中每条是否有对应预测文件 | 全部有预测 | 无预测 → 补写预测或移除 buffer 项 |
| 3 | 检查 buffer 中每条是否有对应视频目录 | 已拍摄的应有视频目录 | 无目录 → 确认是否已拍摄 |
| 4 | 建议优先发布 buffer 中最早的内容 | 先进先出 | 用户决定发布顺序 |

## 故障 4：校准池数据异常

| 步骤 | 检查项 | 预期结果 | 异常处置 |
|------|--------|----------|----------|
| 1 | 检查校准池样本数 | ≥ MIN_SAMPLES_FOR_BUMP | 不足 → 继续积累 |
| 2 | 检查每个样本的预测值和实际值 | 均为有效数值 | 有空值 → 提示补充数据 |
| 3 | 检查预测偏差分布 | 无极端异常值（偏差 >200%） | 有异常 → 标记为离群样本，分析原因 |
| 4 | 检查样本时间分布 | 近3个月有持续数据 | 无新数据 → 提示继续创作和复盘 |

## 故障 5：知识库引用断裂

| 步骤 | 检查项 | 预期结果 | 异常处置 |
|------|--------|----------|----------|
| 1 | 检查 `knowledge/` 目录下三个知识库文件是否存在 | 全部存在 | 缺失 → 重新安装 skill 包 |
| 2 | 检查子skill中的 `[来源：X-模块]` 引用 | 引用的锚点在 Knowledge-Index.md 中存在 | 不存在 → 更新锚点表或修正引用 |
| 3 | 检查 Knowledge-Index.md 版本与 state 一致 | 版本号一致 | 不一致 → 更新 state 或重新初始化 |
| 4 | 检查降级替代方案是否可用 | 降级方案引用的锚点存在 | 不存在 → 更新降级方案 |

## 故障 6：钩子未生效

| 步骤 | 检查项 | 预期结果 | 异常处置 |
|------|--------|----------|----------|
| 1 | 检查 `.claude/hooks/` 目录下钩子文件 | 全部存在 | 缺失 → 从 skill 包复制 |
| 2 | 检查 `hooks.json` 注册格式 | 格式正确 | 格式错误 → 参考模板修正 |
| 3 | 检查钩子脚本权限 | 可执行 | 无权限 → `chmod +x` |
| 4 | 测试 prediction-immutability 钩子 | 修改预测段被拦截 | 未拦截 → 检查 hook 路径和匹配规则 |

## 故障 7：状态文件损坏

| 步骤 | 检查项 | 预期结果 | 异常处置 |
|------|--------|----------|----------|
| 1 | 读取 `.yang-state.json` | JSON 解析成功 | 解析失败 → 从 git 恢复最近版本 |
| 2 | 检查 schema 版本 | 等于 LATEST_SCHEMA | 版本过旧 → 运行 `/yang-migrate` |
| 3 | 检查必须字段 | `mode`、`rubric_version`、`shoot_buffer` 等存在 | 字段缺失 → 运行 `/yang-migrate` 修复 |
| 4 | 验证字段值合法性 | mode 为 cold-start/calibration 之一 | 非法值 → 重置为 cold-start |

## 故障 8：竞品数据库异常

| 步骤 | 检查项 | 预期结果 | 异常处置 |
|------|--------|----------|----------|
| 1 | 检查 `project_data.db` 是否存在 | 文件存在 | 不存在 → 运行 yang-competitor-search 初始化 |
| 2 | 检查数据库表结构 | `competitor_snapshots` 和 `competitor_strategy_changes` 表存在 | 表缺失 → 运行 `adapters/data_pipeline/schema.sql` 重建 |
| 3 | 检查数据新鲜度 | 最近一条数据 ≤ 7 天 | 数据过期 → 运行竞品数据采集更新 |
| 4 | 检查数据完整性 | 关键字段非空 | 有空值 → 重新采集缺失字段 |
