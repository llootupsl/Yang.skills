# 升级验证协议（原则 #2）

## 核心规则

1. rubric 升级时，校准池所有有实绩数据的样本必须用新公式重打分。
2. 新排序与实际表现排序若在 ≥4/5（N≤10）或 ≥80%（N>10）样本上不一致，升级被拒。
3. Bump 操作不可跳步或降级验证标准。

## 执行流程

### 1. 前置检查
- calibration_samples >= MIN_SAMPLES_FOR_BUMP（默认 5）
- 有 ≥1 条待验证观察

### 2. 全量重打分
对每个有实绩数据的样本：
- 用旧公式打分 → 旧排名
- 用新公式打分 → 新排名
- 实际表现排名

### 3. 一致性验证

| 样本数 | 通过条件 |
|--------|---------|
| 5 ≤ N ≤ 10 | 新排名 vs 实际排名，≥4/5 一致 |
| N > 10 | 新排名 vs 实际排名，≥80% 一致 |

### 4. 结果
- 通过 → 升级版本号，删除已吸收观察，更新 `.yang-state.json`
- 被拒 → 保留观察，输出不一致样本分析，建议细化调整

## 跨模型审计（--strict）
- 两个不同模型或独立对话各自做全量重打分
- 两个模型的排序一致性 ≥ 4/5 才通过
- 不一致时标记「跨模型分歧」

## 验证条件细化标准（按样本数分层）

不同校准池规模下，验证的严格程度和步骤有差异。以下为各层级的完整要求。

### 层级 1：最小可验证（5 ≤ N ≤ 7）

| 步骤 | 要求 | 说明 |
|------|------|------|
| 全量重打分 | 所有 N 个样本 | 无豁免 |
| 一致性验证 | ≥4/5 样本新排名与实际排名一致 | 允许 1 个偏差样本 |
| 跨模型审计 | **强制**（--strict 自动开启） | 小样本下单模型验证不够稳健 |
| 偏差样本分析 | 逐个分析不一致样本 | 必须说明偏差原因（维度权重 / 样本特殊性 / 数据噪声） |
| 冷启动保护 | 新公式不得删除 > 30% 的现有维度 | 防止小样本过拟合导致维度坍缩 |

### 层级 2：标准验证（8 ≤ N ≤ 15）

| 步骤 | 要求 | 说明 |
|------|------|------|
| 全量重打分 | 所有 N 个样本 | 无豁免 |
| 一致性验证 | ≥80% 样本新排名与实际排名一致 | 允许 ≤20% 偏差 |
| 跨模型审计 | 推荐（--strict 可选） | 样本量足够时单模型验证基本可靠 |
| 偏差样本分析 | 偏差样本 > 2 个时需逐个分析 | 偏差样本 ≤ 2 个可汇总说明 |
| 维度增删 | 新增维度需至少 3 个样本支撑；删除维度需说明原因 | 中等样本量允许适度维度调整 |

### 层级 3：规模化验证（N > 15）

| 步骤 | 要求 | 说明 |
|------|------|------|
| 全量重打分 | 所有 N 个样本（可分批并行） | 大样本量下可分批执行，但最终必须全量 |
| 一致性验证 | ≥80% 样本新排名与实际排名一致 | 同层级 2 |
| 跨模型审计 | 可选 | 大样本量下统计显著性已足够 |
| 偏差样本分析 | 按偏差类型分组分析（系统性偏差 vs 随机偏差） | 区分偏差模式 |
| 维度增删 | 新增维度需至少 5 个样本支撑；删除维度需 ≥3 个反例 | 高标准要求 |
| 分层验证 | 按 composite 分层（高/中/低）各层分别验证一致性 | 防止新公式只在某个分段有效 |

### 特殊情况处理

| 情况 | 处理 |
|------|------|
| 校准池中部分样本缺实绩数据 | 仅对有实绩数据的样本做一致性验证；缺数据样本不参与排名比对 |
| 新增维度但无历史锚点 | 新维度初始权重 = 0，标注为"观察中"，下次 bump 时根据积累数据赋权 |
| 样本分布严重偏斜（如 80% 为高表现） | 在一致性验证之外增加"低表现子集"单独验证，确保新公式不只对高表现有效 |

## Bump 失败的常见原因和修复建议

| # | 失败原因 | 典型表现 | 修复建议 |
|---|----------|----------|----------|
| 1 | **维度权重调整过激** | 新公式对 2+ 样本排名翻转，且翻转方向不一致 | 降低调整幅度：每次 bump 每个维度权重变化 ≤ ±30%。分多次小幅调整替代一次大幅调整 |
| 2 | **新增维度缺乏支撑** | 新维度只在 1-2 个样本上有区分力，其他样本无差异 | 暂不赋权，标注为"观察中"，等更多样本积累后再赋权 |
| 3 | **删除维度过早** | 删除某维度后，之前靠该维度正确排序的样本排名翻转 | 恢复该维度，降低权重而非删除。只有 ≥3 个反例支撑时才可删除 |
| 4 | **样本分布偏斜** | 校准池中高表现样本过多，新公式对低表现样本排序失准 | 补充低表现样本到校准池；或对低表现子集单独验证 |
| 5 | **跨模型分歧** | 两个模型的排序一致性 < 4/5 | 标记分歧维度，分析哪个模型在分歧维度上更合理；如无法判断，维持旧公式 |
| 6 | **过拟合近期数据** | 新公式对最近 3 条复盘完美排序，但对更早样本排名混乱 | 加入时间衰减权重，不让近期数据主导；或增加"时间稳定性"检查 |
| 7 | **观察吸收不完整** | bump 时删除了观察，但该观察的信号实际上未被新公式覆盖 | 逐条检查待删除观察：每条观察必须在新公式中有对应维度或权重体现，否则保留 |
| 8 | **样本数不足就触发** | N < MIN_SAMPLES_FOR_BUMP 但被强制触发 | 拒绝 bump，等待更多样本。MIN_SAMPLES_FOR_BUMP 是硬门槛 |

### 修复后重新提交的流程

1. 根据失败原因调整新公式
2. 重新执行全量重打分
3. 重新执行一致性验证
4. 如有跨模型审计要求，重新执行
5. 通过后正常走 bump 流程

> ⚠️ 同一轮 bump 最多允许 **3 次修复重试**。3 次仍失败 → 建议维持旧公式，积累更多样本后再尝试。

## 版本号升级规则

rubric 版本号遵循 **SemVer 语义化版本**：`MAJOR.MINOR.PATCH`

### 什么时候升什么版本

| 变更类型 | 版本升级 | 示例 | 条件 |
|----------|----------|------|------|
| **新增评分维度** | MINOR | 1.2.0 → 1.3.0 | 新维度初始权重 > 0，通过一致性验证 |
| **删除评分维度** | MINOR | 1.3.0 → 1.4.0 | ≥3 个反例支撑，通过一致性验证 |
| **维度权重调整** | PATCH | 1.4.0 → 1.4.1 | 权重变化 ≤ ±30%，通过一致性验证 |
| **维度权重大幅调整** | MINOR | 1.4.1 → 1.5.0 | 权重变化 > ±30%，通过一致性验证 |
| **评分公式结构变更** | MAJOR | 1.5.0 → 2.0.0 | 加法→乘法、引入非线性项等结构性变更 |
| **composite 计算方式变更** | MAJOR | 2.0.0 → 3.0.0 | 改变综合评分的聚合逻辑 |
| **观察吸收（删除已验证观察）** | PATCH | 1.4.1 → 1.4.2 | 观察信号已被维度覆盖，无结构变更 |
| **纯格式/排版调整** | 不升版本 | — | 不影响评分逻辑 |

### 版本升级执行规范

1. **版本号写入 `.yang-state.json`**：`rubric_version` 字段
2. **版本号写入 `rubric_notes.md` 头部**：`version: X.Y.Z`
3. **版本变更记录写入 `rubric-memo.md`**：包含变更内容、通过率、不一致样本分析
4. **MAJOR 升级必须跨模型审计**：结构性变更影响面大，单模型验证不够
5. **PATCH 升级可跳过跨模型审计**：但必须通过一致性验证
6. **版本号只升不降**：如 bump 失败，维持旧版本号，不回退

### 版本兼容性

| 升级类型 | 旧预测文件兼容性 | 说明 |
|----------|------------------|------|
| PATCH | ✅ 完全兼容 | 旧预测的 composite 仍有参考价值 |
| MINOR | ⚠️ 部分兼容 | 新维度在旧预测中缺失，复盘时需标注"维度缺失" |
| MAJOR | ❌ 不兼容 | 旧预测的 composite 不可直接对比，需重打分后才能比较 |
