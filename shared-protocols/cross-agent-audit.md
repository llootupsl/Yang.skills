# 跨 Agent 审计协议

## 目的

在多Agent协作引擎环境中，确保每个 Agent 的输出被至少另一个 Agent 交叉验证，防止单一 Agent 偏差累积。

## 审计规则

### 1. 审计对
| 审计方 | 被审计方 | 审计内容 |
|--------|---------|---------|
| Content Agent | Topic Agent | 选题质量 vs rubric 评分一致性 |
| Data Agent | Content Agent | 实际表现 vs 脚本质量预测 |
| Strategy Agent | Data Agent | 数据解释是否有替代假设 |

### 2. 审计频率
- 每次产线周期（选题 → 发布 → 复盘）触发一次
- Solo 模式下审计暂停

### 3. 审计产出
```json
{
  "cycle": "YYYY-MM-DD",
  "auditor": "Content Agent",
  "auditee": "Topic Agent",
  "findings": [
    {
      "category": "偏差",
      "description": "...",
      "severity": "low|medium|high",
      "suggested_action": "..."
    }
  ]
}
```

### 4. 升级条件
- severity: high × 3 次 → 需人工审核该 Agent 配置
- 同一类型偏差连续 3 个周期 → 触发 bump 建议

## 跨模型审计具体执行步骤

### 执行步骤（10 步完整流程）

```
Step 1: 触发审计
  │  触发条件：产线周期完成 / 手动触发 / 定时触发
  │  产出：审计任务单（含周期编号、审计对、时间范围）
  │
Step 2: 采集被审计方输出
  │  从 .yang-state.json 和对应文件中提取被审计方在本次周期的全部输出
  │  包括：选题文件、评分文件、预测文件、复盘文件
  │
Step 3: 采集审计方上下文
  │  从审计方对应的数据源中提取独立判断所需的原始数据
  │  包括：实际播放数据、用户反馈数据、平台公开数据
  │
Step 4: 审计方独立评估
  │  审计方基于原始数据独立做出判断，不参考被审计方的结论
  │  产出：审计方的独立评分/判断结果
  │
Step 5: 对比分析
  │  将审计方独立判断与被审计方输出逐项对比
  │  对比维度：方向一致性、数值偏差幅度、遗漏项、过度推断项
  │
Step 6: 偏差分类
  │  将发现的偏差按以下类别分类：
  │  - 方向性偏差（结论方向相反）
  │  - 幅度性偏差（方向一致但幅度差异大）
  │  - 遗漏性偏差（被审计方遗漏关键信号）
  │  - 过度推断偏差（被审计方超出数据支撑的结论）
  │
Step 7: 严重度评定
  │  对每项偏差按三级标准评定严重度（见下方三级判定标准）
  │
Step 8: 生成审计报告
  │  按标准 JSON 格式输出审计结果
  │  包括：findings 列表、综合判定等级、建议动作
  │
Step 9: 审计结果通知
  │  将审计报告写入 .yang-cache/audit-reports/<cycle_id>.json
  │  如综合判定为"不通过" → 向用户发送告警
  │  如综合判定为"有条件通过" → 在 yang-status 中标注
  │
Step 10: 后续动作执行
  │  根据审计结果触发后续动作：
  │  - 通过 → 无动作
  │  - 有条件通过 → 标注偏差，下次周期重点复查
  │  - 不通过 → 触发降级策略（见下方降级策略）
```

### 执行约束

| 约束项 | 规则 |
|-------|------|
| 审计独立性 | 审计方不得读取被审计方的中间推理过程，只读最终输出 |
| 审计时效 | 审计必须在周期结束后 24 小时内完成 |
| 审计幂等性 | 同一周期同一审计对只执行一次审计，不重复执行 |
| 审计可追溯 | 审计报告必须持久化，不可删除，供 yang-doctor 检查 |

## 审计结果三级判定标准

### 判定等级定义

| 等级 | 标识 | 判定条件 | 后续动作 |
|------|------|---------|---------|
| **通过** | `PASS` | 所有偏差均为 low 严重度；且方向性偏差数为 0 | 无需额外动作 |
| **有条件通过** | `CONDITIONAL_PASS` | 存在 medium 严重度偏差；或方向性偏差 ≤1 且幅度 <30% | 标注偏差项，下次周期重点复查；被审计方输出保留但标注"审计有保留" |
| **不通过** | `FAIL` | 存在 high 严重度偏差；或方向性偏差 ≥2；或幅度性偏差 >50% | 触发降级策略；被审计方输出降权或作废 |

### 严重度评定细则

| 严重度 | 方向性偏差 | 幅度性偏差 | 遗漏性偏差 | 过度推断偏差 |
|-------|----------|----------|----------|------------|
| **low** | — | 幅度差异 10-20% | 遗漏非关键信号 | 推断有轻微超出但方向正确 |
| **medium** | 方向偏差 1 项 | 幅度差异 20-50% | 遗漏中等重要信号 | 推断明显超出数据支撑 |
| **high** | 方向偏差 ≥2 项 | 幅度差异 >50% | 遗漏关键信号（如平台重大变化） | 推断与数据矛盾 |

### 综合判定算法

```
综合判定 = 
  IF 任何偏差 severity == "high" → FAIL
  IF 方向性偏差计数 >= 2 → FAIL
  IF 幅度性偏差 > 50% → FAIL
  IF 任何偏差 severity == "medium" → CONDITIONAL_PASS
  IF 方向性偏差 == 1 AND 幅度 < 30% → CONDITIONAL_PASS
  ELSE → PASS
```

### 判定结果记录格式

```json
{
  "cycle": "YYYY-MM-DD",
  "auditor": "Content Agent",
  "auditee": "Topic Agent",
  "verdict": "PASS | CONDITIONAL_PASS | FAIL",
  "findings": [
    {
      "id": "F-001",
      "category": "方向性偏差",
      "description": "被审计方判断选题A为高潜力，独立评估为低潜力",
      "severity": "medium",
      "evidence": {
        "auditee_output": "选题A composite=8.2, bucket=S",
        "auditor_independent": "选题A 实际播放低于基线30%",
        "deviation": "方向相反"
      },
      "suggested_action": "下次周期重点复查选题评估逻辑"
    }
  ],
  "summary": {
    "total_findings": 3,
    "by_severity": {"low": 2, "medium": 1, "high": 0},
    "by_category": {"方向性偏差": 1, "幅度性偏差": 2},
    "directional_errors": 1,
    "max_amplitude_deviation": "25%"
  }
}
```

## 审计失败降级策略

### 降级触发条件

| 触发条件 | 降级等级 | 触发动作 |
|---------|---------|---------|
| 单次审计判定为 FAIL | **一级降级** | 被审计方输出降权，不作为唯一决策依据 |
| 连续 2 次审计判定为 FAIL | **二级降级** | 被审计方输出作废，需人工审核后才能使用 |
| 连续 3 次审计判定为 FAIL（同一类型偏差） | **三级降级** | 触发 Agent 配置人工审核 + bump 建议 |
| 审计方自身不可用 | **审计暂停** | 切换到 Solo 模式降级运行 |

### 降级策略详情

#### 一级降级：输出降权

```
触发：单次 FAIL
  │
  ├─ 被审计方输出保留，但追加标签 _audit_degraded=true
  ├─ 该输出在后续 skill 中的权重降为 0.5
  ├─ yang-status 标注"上次审计未通过，输出已降权"
  └─ 下次周期自动恢复（如审计通过）
```

#### 二级降级：输出作废

```
触发：连续 2 次 FAIL
  │
  ├─ 被审计方输出标记 _audit_invalidated=true
  ├─ 该输出不参与任何后续计算和决策
  ├─ 需人工审核被审计方的配置和逻辑
  ├─ 人工审核通过后，清除 _audit_invalidated 标签
  └─ yang-status 持续提示"审计连续失败，需人工审核"
```

#### 三级降级：Agent 重配置

```
触发：连续 3 次 FAIL（同一类型偏差）
  │
  ├─ 触发 bump 建议（偏差可能源于 rubric 本身的问题）
  ├─ 冻结被审计方的自动运行权限
  ├─ 需人工审核 Agent 配置 + rubric 配置
  ├─ 人工审核通过后，重置审计计数器
  └─ yang-status 标注"Agent 已冻结，需人工审核后解封"
```

#### 审计暂停降级

```
触发：审计方不可用（如跨模型服务中断）
  │
  ├─ 审计暂停，不执行审计步骤
  ├─ 产线切换到 Solo 模式降级运行
  ├─ 被审计方输出正常使用，但标注 _audit_skipped=true
  ├─ yang-status 提示"审计服务不可用，运行于无审计模式"
  └─ 审计恢复后，对暂停期间积累的输出执行补审计
```

### 降级恢复路径

```
一级降级 → 下次审计通过 → 自动恢复
二级降级 → 人工审核通过 → 清除标签 → 恢复
三级降级 → 人工审核 + bump → 重置计数器 → 恢复
审计暂停 → 审计服务恢复 → 补审计 → 恢复
```

### 降级期间的用户通知

| 降级等级 | 通知方式 | 通知内容 |
|---------|---------|---------|
| 一级降级 | yang-status 标注 | "⚠️ 审计降级：[Agent] 输出已降权，原因：[偏差描述]" |
| 二级降级 | yang-status + 显式提示 | "🔴 审计失败：[Agent] 输出已作废，需人工审核" |
| 三级降级 | yang-status + 阻断提示 | "🚫 Agent 冻结：[Agent] 已停止自动运行，需人工审核后解封" |
| 审计暂停 | yang-status 标注 | "ℹ️ 审计暂停：运行于无审计模式，输出未经验证" |
